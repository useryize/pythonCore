## 📖 二、知识讲解

### 2.1 算术运算符

**一句话定义**：对数值（或字符串的重复）进行运算的符号。

| 运算符 | 含义 | 示例 | 结果 | 备注 |
| --- | --- | --- | --- | --- |
| `+` | 加 | `17 + 5` | `22` | 字符串则是拼接 |
| `-` | 减 | `17 - 5` | `12` | |
| `*` | 乘 | `17 * 5` | `85` | 字符串则是重复 |
| `/` | 真除法 | `17 / 5` | `3.4` | **永远返回 float** |
| `//` | 地板除法 | `17 // 5` | `3` | 向负无穷取整 |
| `%` | 取余 | `17 % 5` | `2` | 结果符号跟随除数 |
| `**` | 幂 | `17 ** 5` | `1419857` | **右结合** |

**三个必须记住的特殊行为**：

```python
# 1) / 永远返回 float，不存在「整除」
print(10 / 2)          # 5.0  ← 不是 5
print(type(10 / 2))    # <class 'float'>

# 2) // 是「向下取整」，不是「去掉小数部分」
print(17 // 5)         # 3
print(-17 // 5)        # -4  ← ⚠️ 不是 -3！是向负无穷方向取整
# 恒等式保证：a == b * (a // b) + a % b，对负数也成立
print(-17 % 5)         # 3   ← 余数非负，保证上面的恒等式

# 3) ** 是右结合的（从右往左算）
print(2 ** 3 ** 2)     # 512  = 2 ** (3 ** 2)，不是 (2 ** 3) ** 2 = 64
```

**⚠️ 一元负号与幂的优先级**：

```python
# 幂的优先级高于一元负号，所以 -a ** 2 等价于 -(a ** 2)
a = 3
print(-a ** 2)         # -9
print((-a) ** 2)       # 9    ← 有括号才是「负数的平方」
```

**除零的完整规则**：

```python
# ⚠️ 重要澄清：Python 对 int 和 float 一视同仁，都抛 ZeroDivisionError
# 这点和 JavaScript 不同（JS 里 1.0/0 得到 Infinity）
try:
    1 / 0
except ZeroDivisionError as exc:
    print(exc)         # division by zero

try:
    1.0 / 0
except ZeroDivisionError as exc:
    print(exc)         # float division by zero（错误信息略有不同）
```

> 📌 **记忆要点**：JavaScript 的 `1.0/0` 得到 `Infinity`、`0.0/0` 得到 `NaN`，**Python 没有这个行为**。如果你有 JS 经验，这里一定要纠正过来。

需要「无穷大」和「NaN」时必须显式构造：

```python
import math
print(math.inf)             # inf     正无穷
print(-math.inf)            # -inf    负无穷
print(math.nan)             # nan
print(math.nan == math.nan) # False   ⚠️ NaN 不等于任何东西，包括它自己
```

**位运算入门**（把整数看成二进制）：

```python
a, b = 12, 10               # 1100 和 1010
print(a & b)                # 8   1100 & 1010 = 1000   按位与
print(a | b)                # 14  1100 | 1010 = 1110   按位或
print(a ^ b)                # 6   1100 ^ 1010 = 0110   异或
print(a << 2)               # 48  左移两位 = 乘 4
print(a >> 2)               # 3   右移两位 = 除 4（向下取整）
print(~a)                   # -13 按位取反 = -(a+1)，这是恒等式

# 实用技巧：判断偶数比 & 1 快
print(n % 2 == 0)           # 常规写法
print(n & 1 == 0)           # 位运算写法，面试常问
```

### 2.2 比较运算符

**一句话定义**：比较两个值，返回 `True` 或 `False`。

| 运算符 | 含义 | 示例 | 结果 |
| --- | --- | --- | --- |
| `==` | 等于 | `10 == 10` | `True` |
| `!=` | 不等于 | `10 != 3` | `True` |
| `>` | 大于 | `10 > 3` | `True` |
| `>=` | 大于等于 | `10 >= 10` | `True` |
| `<` | 小于 | `10 < 3` | `False` |
| `<=` | 小于等于 | `10 <= 3` | `False` |

**⚠️ `=` 与 `==` 是完全不同的东西**：

```python
x = 5        # 赋值：把 5 存进 x（= 是赋值符号）
x == 5       # 比较：问「x 的值是不是 5」（== 是相等运算符）

if x == 5:   # ✅ 正确：if 后面必须是表达式
    print("是 5")

# if x = 5:  # ❌ SyntaxError: invalid syntax. 赋值不是表达式
```

**⚠️ 不加空格的坑**：PEP 8 要求 `=`、`==` 两边留空格。写成 `x==5` 语法上没错（只有 `==` 允许），但可读性差，且 `x=-5` 和 `x-=5` 的区别很微妙。

**比较的类型规则**：

```python
# ✅ 同类型之间可以比较
print(1 < 2)               # True
print("apple" < "banana")  # True，按 Unicode 码位逐字符比
print((1, 2) < (1, 3))     # True，元组逐元素比
print([1, 2] < [1, 3])     # True，列表同理

# ❌ 不同类型之间会抛 TypeError（Python 没有隐式转换）
try:
    1 < "2"
except TypeError as exc:
    print(exc)             # '<' not supported between instances of 'int' and 'str'

# ⚠️ 这和 JavaScript 不同：JS 里 1 < "2" 会得到 True（"2" 被转成数字 2）
# Python 拒绝隐式转换，这是它的「显式优于隐式」设计理念的体现
```

**⚠️ 列表的 `==` 是「浅比较」**：

```python
print([1, 2] == [1, 2])         # True  值相等
print([1, 2] is [1, 2])         # False 身份不同
print([[1]] == [[1]])           # True  逐层比较值
print([[1]] is [[1]])           # False
```

### 2.3 链式比较（Python 特色）

**一句话定义**：`a < b < c` 是一个完整表达式，语义等价于 `a < b and b < c`，且中间表达式**只求值一次**。

```python
score = 75
# 最自然的写法
print(0 <= score <= 100)         # True

# 它等价于下面这个（但中间表达式只求值一次）
print(0 <= score and score <= 100)   # True
```

**为什么中间只求值一次很重要**：

```python
# ⚠️ 手写展开会让昂贵函数被调用两次
calls = []
def get_value():
    calls.append(1)
    return 5

print(1 < get_value() < 10)      # True
print(f"链式写法调用了 {len(calls)} 次")   # 2 次（一次取中间值）

calls.clear()
v = get_value()
print(1 < v < 10)
print(f"先接变量调用了 {len(calls)} 次")     # 1 次 ✅ 更高效
```

**链式比较的边界行为**：

```python
# 中间任何一个条件不满足，整个表达式就是 False
print(1 < 2 < 3)     # True
print(1 < 3 < 2)     # False   ← 第二个条件失败
print(3 > 2 > 1)     # True    支持任意方向的链
print(1 < 2 > 0)     # True    混合方向也是合法的

# 甚至可以这样写（虽然不常见）
print("a" < "b" < "c")  # True

# 与 in 组合：判断字符是否在 'aeiou' 里
vowel = "e"
print(vowel in "aeiou")     # True，这是单次判断，不需要链式
```

**⚠️ 链式比较 ≠ 链式赋值**：

```python
# ✅ 链式比较：一个表达式
if 0 < x < 10:
    print(x)

# ✅ 链式赋值：多次赋值
a = b = c = 0        # 三个名字都指向 0

# ⚠️ 它们语法上都用「链式」，但完全是两回事
# if a = b = c:      # ❌ SyntaxError，赋值不能出现在 if 后面
```

### 2.4 逻辑运算符与短路求值

**一句话定义**：`and` / `or` / `not` 用来组合布尔值，但**返回值不一定是布尔值**。

**关键认知：`and` 和 `or` 返回的是「参与运算的那个对象」**：

```python
# and：左边为假 → 返回左边；左边为真 → 返回右边
print(True and "x")       # 'x'    返回右边
print(False and "x")      # False  返回左边
print(0 and "x")          # 0      返回左边本身，不是 False！
print("" and "x")         # ''     空字符串本身

# or：左边为真 → 返回左边；左边为假 → 返回右边
print("a" or "b")         # 'a'    返回左边
print("" or "默认")       # '默认'  返回右边
print(0 or 10)            # 10     0 是 falsy
print(None or 0 or "最后")  # '最后'  一串 or 找第一个「有值」的

# not：永远返回严格的布尔值
print(not "x")            # False
print(not "")             # True

# 推导：or 链是「取默认值」惯用法
name = input("姓名：").strip() or "匿名"
```

**短路求值（short-circuit）**：

```python
# and 短路：左边为假，右边根本不执行
def risky():
    print("  ⚠️ 危险操作被执行了！")
    return False

print(False and risky())   # 不打印任何东西

# or 短路：左边为真，右边根本不执行
print(True or risky())     # 同样不打印
```

**短路是保护机制，不只是性能优化**：

```python
config = {"user": {"name": "张三"}}

# ✅ 正确：先判断嵌套结构是否存在，再取值
if "user" in config and "name" in config["user"]:
    print(config["user"]["name"])      # 安全

# ❌ 错误：先取值（会 KeyError），再判断
if config["missing"] and config["missing"]["name"]:   # 立即崩溃
    ...
```

⚠️ **短路让「顺序」成为正确性问题，而不只是风格问题**。

**优先级：`not` > `and` > `or`**：

```python
# not 的优先级高于比较运算符
a = 5
print(not a == None)      # ⚠️ 解析为 (not a) == None → False is None → False

# ⚠️ 判断 None 必须写 is not
print(a is not None)      # True ✅
```

### 2.5 赋值运算符

**一句话定义**：把「运算」和「赋值」合并成一个符号，让代码更简洁。

| 运算符 | 等价于 | 初始 10 执行后 |
| --- | --- | --- |
| `+=` | `x = x + v` | 15 |
| `-=` | `x = x - v` | 7 |
| `*=` | `x = x * v` | 30 |
| `/=` | `x = x / v` | 3.333 |
| `//=` | `x = x // v` | 3 |
| `%=` | `x = x % v` | 1 |
| `**=` | `x = x ** v` | 100 |
| `:=` | 海象运算符，见下 | — |

**⚠️ `+=` 在不同类型上行为完全不同**：

```python
# int 的 += 是「算新值再赋值」
n = 10
n += 5
print(n)                 # 15

# str 的 += 是「拼接后赋给新对象」
s = "ab"
s += "cd"
print(s)                 # 'abcd'，但原字符串没被改（不可变）

# list 的 += 是「原地追加」，和 extend 一样
lst = [1, 2]
lst += [3, 4]
print(lst)               # [1, 2, 3, 4]   ⚠️ 注意：list += tuple 会报错！

# ⚠️ list += tuple 会 TypeError，要用 extend 或 +
# lst += (3, 4)          # TypeError: 'can only concatenate list (not "tuple") to list'
lst.extend((3, 4))       # ✅ extend 接受任意可迭代对象
```

**三种赋值形态**：

```python
# 1) 链式赋值：从左到右依次赋值
a = b = c = 0
print(a, b, c)           # 0 0 0

# 2) 解包赋值：左右个数必须一致
x, y = 1, 2
print(x, y)              # 1 2

# 3) 变量交换：不需要临时变量，Python 的招牌写法
x, y = y, x
print(x, y)              # 2 1

# 三元轮换
p, q, r = 1, 2, 3
p, q, r = r, p, q
print(p, q, r)           # 3 1 2

# 4) 星号解包：让「剩下的全给」最后一个变量
first, *rest = [1, 2, 3, 4, 5]
print(first, rest)       # 1 [2, 3, 4, 5]

first, *middle, last = [1, 2, 3, 4, 5]
print(first, middle, last)   # 1 [2, 3, 4] 5

# ⚠️ 元组不需要括号
t = 1, 2
print(t)                 # (1, 2)
```

**⚠️ 左右个数不匹配会报错**：

```python
try:
    x, y = 1, 2, 3
except ValueError as exc:
    print(exc)           # too many values to unpack (expected 2)

# 星号解包可以解决「个数不定」的问题
a, *others = [1, 2, 3, 4, 5]    # ✅ others 接收所有剩余的
```

**海象运算符 `:=`（3.8+）**：在表达式中赋值，避免重复计算。

```python
# 典型场景：while 循环里避免调用两次昂贵的函数
line_count = 0
# while (line := fp.readline()) != "":   ✅ 只调用一次 readline
#     line_count += 1

# 更常见的用法：if 条件里计算，条件后使用
data = [1, 2, 3, 4, 5]
if (n := len(data)) > 3:
    print(f"共 {n} 个元素")    # n 在这里可用
```

### 2.6 成员运算符：`in` 与 `not in`

**一句话定义**：判断某个元素/子串是否存在于容器中。

```python
fruits = ["苹果", "香蕉", "橙子"]
print("香蕉" in fruits)          # True
print("草莓" not in fruits)      # True

# 不同容器的 in 语义
print(2 in [1, 2, 3])           # True    列表：元素值
print("lo wo" in "hello world")  # True   字符串：子串
print("name" in {"name": 1})     # True   字典：键
```

**⚠️ 字典的 `in` 判断的是「键」，不是「值」**（超高频误解）：

```python
user = {"name": "张三", "age": 20}
print("name" in user)               # True  键存在
print("张三" in user)               # False ⚠️ 值不算！

# 查值必须用 values()
print("张三" in user.values())      # True

# 查「键值对是否存在」用 items()
print(("name", "张三") in user.items())   # True
```

**⚠️ 字符串的 `in` 是「子串」，不是「字符」**：

```python
print("ello" in "hello")       # True  子串
print("heo" in "hello")        # False 不是连续子串
print("l" in "hello")          # True  单个字符当然是子串

# 判断「是否包含任意一个字符」
print(any(c in "hello" for c in "xyz"))   # False
print("h" in "hello" or "e" in "hello")   # True
```

**性能提醒**：`in` 对 list 是 O(n)，对 set/dict 是 O(1)。

```python
# ⚠️ 高频查询场景下，list 转成 set 是必做优化
big_list = list(range(10000))
big_set = set(big_list)
# 在 list 里找 9999 → 遍历 10000 次
# 在 set 里找 9999 → 约 1 次哈希计算
```

### 2.7 身份运算符：`is` 与 `is not`

**一句话定义**：`is` 判断「是不是同一个对象」（比较内存地址），`==` 判断「值是否相等」（调用 `__eq__`）。

**这是本课最重要的概念，必须彻底搞清楚。**

| | `is` | `==` |
| --- | --- | --- |
| 比较什么 | 对象身份（`id()`） | 值是否相等 |
| 谁决定 | `id()` / 内存地址 | 对象的 `__eq__` 方法 |
| 对字符串/数字 | 结果不可预测 | 结果确定 |
| 用途 | 只应与 `None`/`True`/`False` 比较 | 值比较的默认选择 |

**为什么会「不可预测」：小整数缓存和字符串驻留**

```python
# 小整数缓存：Python 把 -5 到 256 的整数对象预先创建好并复用
a = 256
b = 256
print(a is b)               # True   ← 恰好同对象（在缓存范围内）

c = 1000
d = 1000
print(c == d)               # True   值相等
print(c is d)               # False  ⚠️ 超出缓存范围，是两个不同对象！

# 同一行赋值一定同对象
e = f = 1000
print(e is f)               # True   必然，两个标签指向同一个对象
```

字符串也有同样的现象：

```python
s1 = "hello"
s2 = "hello"
print(s1 is s2)             # True   字面量会被驻留复用

s3 = "".join(["hel", "lo"])  # 运行时构造的字符串
print(s3 == s1)             # True   值相等
print(s3 is s1)             # False  不驻留
```

> 📌 **绝对不要依赖 `is` 比较数字或字符串**。CPython 的实现细节（缓存范围、驻留策略）在其他实现（PyPy、MicroPython）中可能不同，依赖它就是写不可移植的代码。

**`is` 的正确用法（只有两种）**：

```python
# 用法 1：与 None 比较（None 是唯一合法单例）
value = None
if value is None:
    print("是空值")

# ✅ 写法对比
# value is None      ← 推荐：语义明确、速度快、不能被子类重载
# value == None      ← 能工作，但 == 可被 __eq__ 重载，语义不严格
# value is not None  ← 推荐
# not value          ← ❌ 不对！0、""、[] 都是 falsy，会被误判

# 用法 2：与 True / False 比较（可选，直接写 if value: 更好）
print((1 == 1) is True)    # True
```

**⚠️ 优先级陷阱：`is not` 是一个整体运算符，不是 `is` 的否定**：

```python
a = None
print(not a is a)          # ⚠️ 解析为 (not a) is a → True is None → False
print(a is not a)          # ✅ 语义正确：None is not None → False
```

这两者看起来只差顺序，含义却完全不同。记住：**`is not` 是一个不可拆的运算符**。

**为什么 Python 要设计 `is` 和 `==` 两个运算符**：因为「同一个对象」和「值相等」是两个独立的问题。有些对象值相等但不是同一个（两个内容相同的列表），有些情况下你需要区分（比如检查缓存命中、检查是否复用了对象）。有了两个运算符，语义才完整。

### 2.8 运算符优先级

**从高到低的完整顺序**：

```text
┌─────────────────────────────────────────────────────────────┐
│ 优先级  运算符                    分类                        │
├─────────────────────────────────────────────────────────────┤
│  1     ()  []  {}                括号、下标、字面量          │
│  2     **                         幂（右结合）                │
│  3     +x  -x  ~x                一元正负、按位取反            │
│  4     *  /  //  %               乘除取模                     │
│  5     +  -                       加减                        │
│  6     <<  >>                     移位                        │
│  7     &                          按位与                      │
│  8     ^                          按位异或                    │
│  9     |                          按位或                      │
│ 10     in not in is is not == != < <= > >=   比较/成员/身份  │
│ 11     not                        逻辑非                      │
│ 12     and                        逻辑与                      │
│ 13     or                         逻辑或                      │
│ 14     = += -= *= /= //= %= **= >>= <<= &= ^= |=  赋值      │
│ 15     lambda                     匿名函数（L13）             │
│ 16     x if c else y              条件表达式                  │
└─────────────────────────────────────────────────────────────┘
```

> ⚠️ **关于条件表达式的优先级**：三元表达式 `A if C else B` 的实际优先级比 `or` 略低，所以**当它作为 `or`/`and` 的子表达式时，必须整体加括号**。这是实战中最高频的优先级坑。

**三个经典误判**：

```python
# 案例 1：加法 vs 比较
print(1 + 2 > 3)          # False  先算 1+2=3，再算 3>3
print(1 + (2 > 3))        # 1      括号改变含义，2>3 是 False，1+False=1

# 案例 2：not / and / or 的组合
print(not True and False or True)      # True
# not True = False → False and False = False → False or True = True
print((not (True and False)) or True)  # True（碰巧相同）

# 案例 3（最实战）：三元与 or
label = ""
x = 1
# ❌ 错误：被解析成 label or ('A' if x else 'B')
result_wrong = label or ("已命名" if x else "未命名")
print(result_wrong)        # ''  ← 空的 label 为 falsy，所以恰好返回右边

# ✅ 正确：三元整体加括号
result_right = label if label else ("已命名" if x else "未命名")
print(result_right)        # '已命名'  ← 明确表达「label 为空时才用默认值」
```

**实践建议**：混用不同优先级时**一律加括号**。可读性 > 简洁性，括号花不了几秒。

### 2.9 表达式与语句

**一句话定义**：表达式能**计算出值**，语句做**一件事**（不一定有值）。

```python
# print("x") 是函数调用语句，虽然调用本身是表达式
```

### 2.10 三大高频坑

#### 坑 1：浮点数用 `==` 比较

```python
print(0.1 + 0.2 == 0.3)              # False  ❌
print(0.1 * 3 == 0.3)                # True   ⚠️ 这个居然对了！纯属运气
print(2.675 == 2.675)                # True   同一个对象，必然相等

# ✅ 正确做法：容差比较
import math
print(math.isclose(0.1 + 0.2, 0.3))   # True
print(abs((0.1 + 0.2) - 0.3) < 1e-9)  # True

# 更好的做法：从源头避免
from decimal import Decimal
print(Decimal("0.1") + Decimal("0.2") == Decimal("0.3"))   # True
```

⚠️ **不要用「四舍五入后再比较」**：看起来能绕过问题，但「保留几位」本身是拍脑袋决定的，遇到更大误差时依然会错。容差比较才是正解。

#### 坑 2：链式赋值的误解

```python
# ❌ 误解 1：以为 a = b = c 是「从右往左的数学赋值」
a = b = c = 5
print(a, b, c)       # 5 5 5  ✅ 事实上没问题
print(a is b is c)   # True    三个标签指向同一个对象

# ❌ 误解 2：以为 a = b, c 是合法的
try:
    a = b, c = 1, 2
except SyntaxError as exc:
    print(exc)       # cannot assign to b, c

# ❌ 误解 3：链式赋值和链式比较搞混
# if a = b = c:  # ❌ SyntaxError

# ✅ 正确理解：a = b = c 是「把 c 的值赋给 b，再把 b 的值赋给 a」
# 由于「c 的值」在赋值时就已经确定了，所以顺序不影响结果
```

#### 坑 3：优先级误判

```python
# ⚠️ not 的位置
a = 5
print(not a == None)       # False   解析为 (not a) == None

# ⚠️ 乘法优先于加法
print("a" + "b" * 2)        # 'abb'   先算 "bb" 再拼
print(("a" + "b") * 2)     # 'abab'

# ⚠️ is not 是一个整体
value = None
print(not value is value)  # False   错误写法
print(value is not value)  # False   正确写法（但本例中两者恰好同结果）

# ⚠️ 赋值优先级最低
x = 1
y = 2
print(x == 1 | y == 2)     # ⚠️ | 的优先级高于 ==，实际是 x == (1|y) == 2
# 这是位运算的坑，不用管它，但要知道位运算优先级高于比较
```

## ⚠️ 四、常见错误清单

| 错误现象 | 原因 | 正确写法 |
| --- | --- | --- |
| `SyntaxError: invalid syntax` 指向 `if x = 5` | `=` 是赋值语句，不是表达式 | `if x == 5:` |
| `0.1 + 0.2 == 0.3` 为 `False` | float 二进制表示误差 | `math.isclose()` 或 `abs(a-b) < 1e-9` |
| `if not x is None:` 永远不成立 | `not` 优先级高于 `is`，解析为 `(not x) is None` | `if x is not None:` |
| `if x == None:` 被 linter 警告 | `==` 可被 `__eq__` 重载，语义不严格 | `if x is None:` |
| `'a' + 'b' * 2` 得到 `'abb'` | 乘法优先级高于加法 | `('a' + 'b') * 2` 得到 `'abab'` |
| `2 ** 3 ** 2` 不等于 `(2 ** 3) ** 2` | `**` 是右结合 | `(2 ** 3) ** 2` 需显式加括号 |
| `-3 ** 2` 等于 `-9` | 一元负号优先级低于幂 | `(-3) ** 2` 得 9 |
| `1 < "2"` 抛 `TypeError` | Python 不做隐式类型转换（与 JS 不同） | `1 < float("2")` 或先转换 |
| `list += (1, 2)` 抛 `TypeError` | `list.__iadd__` 只接受 list | `list.extend((1, 2))` |
| `"张三" in {"name": "张三"}` 为 `False` | 字典的 `in` 判断键 | `"张三" in d.values()` |
| `x = y = z = a, b` 抛 `SyntaxError` | 链式赋值右侧不能是带逗号的元组字面量 | `x, y, z = a, b` |
| `while ...: x += 1` 被质疑效率 | `+=` 对可变对象是原地修改，效率高 | 无需修改，正确写法本就是 `+=` |
| 误以为 `1000 is 1000` 恒为 `True` | 小整数缓存只覆盖 -5~256 | 一律用 `==` 比较值 |
| `1.0 / 0` 没有得到 `inf` | Python 对 float 除零也抛异常（与 JS 不同） | 需要无穷值用 `math.inf` |
| `math.nan == math.nan` 为 `False` | NaN 与任何值比较都为 False | 用 `math.isnan()` 判断 |

## 📝 六、本课小结

- **七类运算符**：算术、比较、逻辑、赋值、成员、身份、位运算。其中成员和身份最容易被误解，逻辑运算符的返回值最反直觉。
- **`/` 永远返回 float，`//` 是向下取整**（不是去掉小数部分），`%` 的余数符号跟随除数。Python 的除零对 int 和 float 都会抛异常，**与 JavaScript 不同**。
- **`**` 是右结合**：`2 ** 3 ** 2 == 512`，不是 64。一元负号优先级低于幂，`-3 ** 2 == -9`。
- **链式比较 `0 <= x <= 100` 等价于 `and`，但中间表达式只求值一次**。它和链式赋值是两回事，后者在 `if` 后面会报 SyntaxError。
- **`and`/`or` 返回的是对象而不是布尔值**，这是「提供默认值」惯用法的原理。短路求值不只是优化，更是**保护机制**——把校验条件写在左边。
- **`is` 比较身份，`==` 比较值**。小整数缓存（-5~256）和字符串驻留会让 `is` 的结果「看起来时真时假」，**绝对不要用 `is` 比较数字或字符串**。
- **`is` 只有两种正确用法**：与 `None` 和 `True`/`False` 比较。`is not` 是一个不可拆的整体运算符。
- **优先级要主动加括号**。混用 `and`/`or` 时括号是正确性保障；三元表达式作为子表达式时必须整体加括号。
- **`+=` 在不同类型上行为不同**：int 是算新值，str 是拼接新对象，list 是原地追加（等价于 `extend`，但只接受 list）。

> **一句话总结**：运算符的坑几乎都来自「你以为的优先级和实际的不一样」以及「`is` 和 `==` 搞混」，记住优先级表 + 主动加括号 + `is` 只和 `None` 比，这三条能消掉 95% 的问题。

### 挑战题（选做）

**第 7 题（30 分）· 表达式求值顺序追踪器**

- **背景**：表达式里的副作用（函数调用、赋值）按什么顺序执行？搞错了会导致难以调试的 bug。
- **要求**：实现一个「求值追踪器」，演示并记录每一步：
  1. **算术表达式**：写一个函数 `t(n)`，在被调用时打印 `"t(n) 被调用"`，然后返回 `n`。用 `t(1) + t(2) * t(3)` 观察调用顺序，解释为什么是这个顺序。
  2. **比较短路**：`t(0) and t(1) or t(2)`，观察哪些被调用了。
  3. **链式比较求值次数**：`t(0) < t(5) < t(3)`，统计 `t` 被调用了几次。
  4. **条件表达式**：`(t(1) if t(0) else t(2))`，观察先求值哪个。
  5. **函数实参求值**：定义 `def f(a, b): return a - b`，然后 `f(t(3), t(10))`，确认是左到右。
  6. **嵌套调用**：`t(t(1))`，观察是「内层先还是外层先」。
- **输出**：每小题的打印序列 + 「求值顺序规则」总结。
- **交付物**：
  1. `eval_trace.py` 完整代码；
  2. 一张表总结六条规则（每条都要有你的实测输出作为证据）；
  3. 说明「左到右」这个规则在什么情况下会被打破（提示：链式比较、逻辑短路、三元表达式）。

**关键点 1：用同一个带副作用的函数去「染色」求值过程**，这是把抽象的求值顺序变成可观测量最有效的技巧：

```python
def t(n):
    """被追踪的函数：每次调用都打印名字，并返回自身的值。

    用打印而不是变量记录，是因为打印能直接呈现「先后顺序」，
    而累加到列表里的顺序容易看漏。
    """
    print(f"    t({n}) 被调用")
    return n
```

**关键点 2：注意第 3 题的「调用次数」是本题的隐藏考点**。链式比较 `t(0) < t(5) < t(3)` 中，`t(5)` 出现**两次**在语法上，但只求值**一次**：

```python
print("链式比较：0 < 5 < 3")
result = t(0) < t(5) < t(3)
# 输出：
#     t(0) 被调用      ← 左边界
#     t(5) 被调用      ← 中间值，只调用一次
#                       ← 3 没被调用！因为 0 < 5 已经 False，短路了
```

**关键点 3：把六条规则整理成一张表，每条都要挂上实测证据**：

```python
RULES = [
    ("算术运算从左到右",     "t(1) + t(2) * t(3)",       "先 t(1)，再 t(3)，再 t(2)"),
    ("乘法优先于加法",       "t(1) + t(2) * t(3)",       "先算乘法那一组"),
    ("比较从左到右且会短路", "t(0) < t(5) < t(3)",       "t(3) 不被调用"),
    ("逻辑运算会短路",       "t(0) and t(1) or t(2)",    "t(1)、t(2) 都不被调用"),
    ("条件表达式只算一个分支", "t(1) if t(0) else t(2)", "t(0) 先算，t(2) 不算"),
    ("函数实参从左到右",      "f(t(3), t(10))",           "先 t(3)，再 t(10)"),
    ("嵌套调用内层先",        "t(t(1))",                  "先 t(1)，再外层 t(1)"),
```

**完整代码**：

```python
"""eval_trace.py —— 挑战题：表达式求值顺序追踪器。

运行：python examples/quiz_L02_eval_trace.py
只依赖标准库，可直接运行。
"""

import math


# ============================================================
# 追踪用的带副作用函数
# ============================================================
def t(n: int) -> int:
    """被追踪的函数：每次调用都打印，并返回自身的值。

    用打印而不是累加到列表，是因为打印能直接呈现「先后顺序」。
    """
    print(f"    t({n}) 被调用")
    return n


def f(a: int, b: int) -> int:
    """用于验证「函数实参从左到右求值」的辅助函数。"""
    print(f"    f(a={a}, b={b}) 被调用")
    return a - b


# ============================================================
# 第 1 题：算术表达式的求值顺序
# ============================================================
def trace_arithmetic() -> None:
    """演示乘法优先于加法，且同级运算从左到右。"""
    print("【1】算术表达式求值顺序")
    print("  表达式: t(1) + t(2) * t(3)")
    # 预期：先算乘法那一组（t(3)），再算 t(2)*t(3)，最后算 t(1) + ...
    result = t(1) + t(2) * t(3)
    print(f"  结果 = {result}   (1 + 2*3 = 7)")
    print("  规则：乘法优先 → t(3) 先算；同级从左到右 → t(1) 在加号左边先算\n")

    print("  表达式: t(10) - t(3) - t(2)   （减法左结合）")
    result = t(10) - t(3) - t(2)
    print(f"  结果 = {result}   ((10-3)-2 = 5，不是 10-(3-2))")
    print("  规则：- 是左结合的，等价于 (a - b) - c\n")

    print("  表达式: t(2) ** t(3) ** t(2)   （幂是右结合）")
    result = t(2) ** t(3) ** t(2)
    print(f"  结果 = {result}   (2 ** (3 ** 2) = 512)")
    print("  规则：** 是右结合的，从右往左算\n")


# ============================================================
# 第 2 题：比较与短路的求值顺序
# ============================================================
def trace_short_circuit() -> None:
    """演示逻辑短路与链式比较的求值次数。"""
    print("【2】短路与链式比较")

    print("  表达式: t(0) and t(1) or t(2)")
    # 预期：t(0) 返回 0（falsy）→ and 短路，不调 t(1) → 0 or t(2) → 调 t(2)
    result = t(0) and t(1) or t(2)
    print(f"  结果 = {result}   ← t(1) 完全没有被调用（and 短路）\n")

    print("  表达式: t(1) or t(2)")
    # 预期：t(1) 返回 1（truthy）→ or 短路，不调 t(2)
    result = t(1) or t(2)
    print(f"  结果 = {result}   ← t(2) 完全没有被调用（or 短路）\n")

    print("  表达式: t(0) < t(5) < t(3)   （链式比较 + 短路）")
    # 关键：t(5) 语法上出现两次，但只求值一次
    result = t(0) < t(5) < t(3)
    print(f"  结果 = {result}")
    print("  规则：等价于 (0 < 5) and (5 < 3)；第一个为 False 就短路，t(3) 不被调用")
    print("  ⭐ 关键点：t(5) 只被调用 1 次，不是 2 次（这正是链式比较的价值）\n")


# ============================================================
# 第 3 题：条件表达式的求值顺序
# ============================================================
def trace_ternary() -> None:
    """演示三元表达式「只计算被选中的那个分支」。"""
    print("【3】条件表达式")

    print("  表达式: t(1) if t(0) else t(2)")
    # 预期：先算条件 t(0) → falsy → 走 else 分支 → t(2) 被调用，t(1) 不被调用
    result = t(1) if t(0) else t(2)
    print(f"  结果 = {result}   ← t(1) 没有被调用（未被选中的分支不求值）\n")

    print("  表达式: t(9) if t(1) else t(2)")
    # 预期：t(1) → truthy → 走 if 分支 → t(9) 被调用，t(2) 不被调用
    result = t(9) if t(1) else t(2)
    print(f"  结果 = {result}   ← t(2) 没有被调用\n")


# ============================================================
# 第 4 题：函数调用与嵌套调用
# ============================================================
def trace_function_calls() -> None:
    """演示实参从左到右求值，嵌套调用内层先。"""
    print("【4】函数调用")

    print("  表达式: f(t(3), t(10))")
    # 预期：实参从左到右求值
    result = f(t(3), t(10))
    print(f"  结果 = {result}")
    print("  规则：函数实参从左到右求值\n")

    print("  表达式: t(t(1))   （嵌套调用）")
    # 预期：内层 t(1) 先完成，外层 t(1) 后执行
    result = t(t(1))
    print(f"  结果 = {result}")
    print("  规则：先求实参（内层），再执行函数（外层）\n")

    print("  表达式: t(1) + f(t(2), t(3)) * t(4)")
    # 综合观察：乘法组优先
    result = t(1) + f(t(2), t(3)) * t(4)
    print(f"  结果 = {result}")
    print("  规则：先算右侧的乘法子表达式 f(...) * t(4)，再与 t(1) 相加")


# ============================================================
# 第 5 题：六条规则总结表
# ============================================================
def print_rule_table() -> None:
    """打印求值顺序规则总结表。"""
    print("=" * 78)
    print("表达式求值顺序 · 规则总结")
    print("=" * 78)
    print(f"{'规则':<26}{'验证表达式':<26}{'观察到的现象'}")
    print("-" * 78)
    rows = [
        ("算术同级从左到右", "t(10)-t(3)-t(2)", "(10-3)-2 = 5，非 10-(3-2)"),
        ("乘法优先于加法", "t(1)+t(2)*t(3)", "t(3) 先于 t(1)"),
        ("幂是右结合", "t(2)**t(3)**t(2)", "2**(3**2) = 512"),
        ("比较从左到右", "t(1) < t(2)", "t(1) 先被调用"),
        ("链式比较短路", "t(0) < t(5) < t(3)", "t(3) 不调用，t(5) 只调 1 次"),
        ("逻辑 and 短路", "t(0) and t(1)", "t(1) 不调用"),
        ("逻辑 or 短路", "t(1) or t(2)", "t(2) 不调用"),
        ("三元只算选中分支", "t(1) if t(0) else t(2)", "t(1) 不调用"),
        ("函数实参从左到右", "f(t(3), t(10))", "t(3) 先于 t(10)"),
        ("嵌套调用内层先", "t(t(1))", "内层先返回，再调外层"),
    ]
    for name, expr, finding in rows:
        print(f"{name:<26}{expr:<26}{finding}")
    print("=" * 78)
    print("\n⚠️ 「从左到右」会被打破的三种情况：")
    print("  1) 链式比较：中间表达式被复用，短路后右侧不求值")
    print("  2) 逻辑短路：and/or 的右侧可能完全不被求值")
    print("  3) 三元表达式：未选中的分支完全不求值")
    print("\n💡 工程含义：")
    print("  求值顺序决定了「哪些代码会真的执行」，这直接影响副作用的安全性。")
    print("  如果你在表达式里混入了有副作用的调用（文件写入、数据库更新、")
    print("  变量自增），求值顺序就变成了必须搞清楚的正确性问题。")


def main() -> None:
    """程序入口：按顺序执行全部追踪演示。"""
    print("🎯 表达式求值顺序追踪器 —— 挑战题参考答案\n")
    trace_arithmetic()
    print("-" * 78)
    trace_short_circuit()
    print("-" * 78)
    trace_ternary()
    print("-" * 78)
    trace_function_calls()
    print("-" * 78)
    print_rule_table()
    print("\n✅ 全部追踪演示执行完毕")


if __name__ == "__main__":
    main()
```
