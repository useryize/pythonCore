## 📖 二、知识讲解

### 2.1 if / elif / else 的完整语义

**一句话定义**：`if` 判断一个条件，条件为**真值**（Truthy）时执行对应代码块；`elif` / `else` 提供备选分支，**整条链只会执行一个分支**。

**为什么需要它**：前面几课的变量和运算只能表达「算出一个结果」。有了分支，程序才能根据数据决定「走哪条路」——这是从「脚本」到「程序」的分水岭。

**最基础的写法**：

```python
score = 85

if score >= 60:
    grade = "及格"
else:
    grade = "不及格"

print(grade)      # 及格
```

注意两个语法细节：

1. 行尾的**冒号 `:`** 不能漏。
2. 代码块靠**缩进**表示归属，标准是 4 个空格。缩进不一致会报 `IndentationError`，这是新手最高频的语法错误。

**⭐ 核心语义：整条链只执行一个分支，且条件按顺序求值**

这一点必须用代码验证，不能靠猜：

```python
executed = []

def probe(tag: str) -> bool:
    """记录自己被调用过，并返回一个预设的判断结果。"""
    executed.append(tag)          # 有副作用：记录被调用
    return tag == "第二个"         # 只有第二个返回 True

if probe("第一个"):
    print("    执行了第一个分支")
elif probe("第二个"):
    print("    执行了第二个分支")
elif probe("第三个"):
    print("    执行了第三个分支")
else:
    print("    执行了 else")

print(executed)      # ['第一个', '第二个']
# 第三个和 else 根本没被判断 —— 因为第二个成立后，链条就结束了
```

这条语义有一个重要推论：**分支的顺序是有意义的**。当你把「严格条件」写在前面、「宽松条件」写在后面时，先命中严格条件；反过来则会先命中宽松条件，导致结果错误。

```python
# ❌ 顺序错误：宽松条件在前，严格条件永远命中不了
score = 95
if score >= 60:
    print("及格")
elif score >= 90:
    print("优秀")        # 永远走不到这里

# ✅ 顺序正确：从严格到宽松
if score >= 90:
    print("优秀")        # 命中
elif score >= 60:
    print("及格")
```

**`elif` 的 else if 特性**：Python 没有单独的 `else if` 关键字，`elif` 是 `else: if ...` 的语法糖。这带来了「链条」语义——条件之间是 `elif` 连接，不是各自独立的 `if`。

```python
# ❌ 三个独立的 if：全部都会被判断，条件之间没有互斥关系
if score >= 90:
    level = "优秀"
if score >= 60:
    level = "及格"      # 会覆盖上一个赋值

# ✅ 用 elif 建立互斥：命中一个就停
if score >= 90:
    level = "优秀"
elif score >= 60:
    level = "及格"
else:
    level = "不及格"
```

**⚠️ 坑：漏写 `else` 导致变量未定义**

```python
if False:
    grade = "A"
# print(grade)   # NameError: name 'grade' is not defined

# ✅ 风险在于：某个分支没覆盖到时，后面用到这个变量就崩
if score >= 90:
    grade = "A"
elif score >= 60:
    grade = "B"
else:
    grade = "C"          # 有 else 兜底，任何输入都有值
```

**工程建议**：给变量赋值的 `if` 链，末尾**总是写 `else`**，哪怕 `else` 只是 `pass`。这让「所有路径都有赋值」成为一眼可见的性质。

**条件可以是任意表达式**：

```python
data = [3, 1, 4]

if data and max(data) > 3:      # data 非空 且 最大值大于 3
    print(f"列表非空且最大值为 {max(data)}")

# ⚠️ 顺序很重要：空列表不能先调 max()
if max(data) > 3 and data:      # ❌ 空列表会在这里抛 ValueError
    print("永远不会执行到")
```

这是**短路求值**最常见的应用场景（见 2.3）：把「可能失败的昂贵操作」放在条件右侧。

### 2.2 条件表达式的组合与优先级

**一句话定义**：`and` 连接多个条件表示「全部为真」，`or` 表示「任一为真」，`not` 取反。

**为什么需要它**：真实业务规则往往超过一个条件（成年 **且** 有票 **或** VIP），用多个 `if` 嵌套会让代码迅速失控。

```python
age, has_ticket, is_vip = 20, False, True

if age >= 18 and has_ticket:
    print("成年且有票")
if has_ticket or is_vip:
    print("有票或 VIP")
if not has_ticket:
    print("没票")
```

**⭐ 优先级顺序（从高到低）**：

```text
not  >  比较运算符  >  and  >  or
```

`and` 的优先级**高于** `or`，这意味着 `a or b and c` 会被解析成 `a or (b and c)`。这是新手最容易出错的地方。

```python
is_vip = False
balance = 5
has_permission = False

# 没有括号
result_a = is_vip or balance >= 10 and has_permission
# 实际解析为：is_vip or (balance >= 10 and has_permission)
#           = False or (False and False) = False

# 有括号（你想表达的大概率是这个）
result_b = (is_vip or balance >= 10) and has_permission
#           = (False or False) and False = False

print(result_a, result_b)     # False False
```

虽然这个例子里两者结果相同，但**当变量取值不同时就会分叉**。结论很明确：

> **混用 `and` 和 `or` 时，括号不是「可选的美化」，而是「必须的正确性保障」。**

**`not` 的位置也有陷阱**：

```python
value = 5

# ⚠️ not 的优先级高于比较运算符
# not value == None  实际解析为  (not value) == None
print((not value) == None)      # False

# ✅ 想表达「不是 None」应该用 is not
print(value is not None)        # True
```

规则：`not` 作用于紧跟其后的**整个表达式**，所以想让它作用于一个比较，必须加括号：

```python
not (a == b)         # ✅ 明确的「a 不等于 b」
not a == b           # ⚠️ 等价于 (not a) == b，几乎肯定不是你想要的
```

**链式比较**是 Python 的一个语法糖，能让范围判断更自然：

```python
age = 25
print(18 <= age <= 60)      # True，相当于 18 <= age and age <= 60

# 链式比较对任何返回可比较对象的表达式都成立
print(0 < len([]) < 5)      # False（len([]) 是 0，第一个条件就不成立）
```

⚠️ 链式比较**每个操作数只求值一次**，这和「展开成 `and`」不同（后者会求值两次）。这个区别在实测中可能用到：

```python
count = 5
# 链式比较：count 只求值一次
print(0 < count < 10)
# 展开成 and：count 被求值两次（性能极小差异，但语义上要留意）
```

**把 `and` / `or` 用于非布尔值（提前 return 模式）**：

```python
def get_user(user_id: int):
    """连续的 if-return 卫语句，等价于布尔表达式返回。"""
    if not user_id:
        return None                      # 卫语句
    if user_id < 0:
        return None
    return {"id": user_id}

# 等价但可读性差一些的写法：
def get_user_v2(user_id: int):
    """用 and 链条表达「多个前置条件」。"""
    user = None if user_id <= 0 else {"id": user_id}
    return user
```

卫语句写法（见 2.6）在可读性上明显更好，不要为了「少写几行」牺牲清晰度。

### 2.3 短路求值：保护机制而非单纯优化

**一句话定义**：Python 的 `and` 和 `or` 遇到第一个能确定整体结果的操作数时，**立即返回该操作数，不再计算右侧**。

**为什么需要它**：短路不只是「省时间」，更重要的是**让可能崩溃或有副作用的操作变成安全的**。

```python
calls: list[str] = []

def risky_a() -> bool:
    """模拟一个可能失败的操作，比如读文件、查数据库、调 API。"""
    calls.append("a")
    return True

def risky_b() -> bool:
    """模拟一个一定失败的操作。"""
    calls.append("b")
    raise RuntimeError("b 失败了")

# and：左侧为 True 才会算右侧
result = risky_a() and risky_b()       # ⚠️ 右侧被调用，抛异常
print(calls)                           # ['a', 'b']

# 但如果左侧是 False，右侧根本不会被执行
calls.clear()
def check_config() -> bool:
    calls.append("check")
    return False                        # 模拟「配置缺失」

result = check_config() and risky_b()  # ✅ 右侧完全没被调用
print(calls)                           # ['check']
print(result)                          # False
```

**实际价值：用短路保护「需要额外成本才能得到结果」的操作**

```python
import os

# ✅ 短路保护：只有在 path 非空时才做昂贵的 os 操作
def is_hidden_file(path: str) -> bool:
    return bool(path) and os.path.basename(path).startswith(".")

# ❌ 没有保护：即使 path 为空也会调用函数
def is_hidden_file_bad(path: str) -> bool:
    return os.path.basename(path).startswith(".")     # path="" 时仍会执行

# ✅ 保护「容器非空」再做 min/max（空容器会抛 ValueError）
def average_score(scores: list[int]) -> float:
    return scores and sum(scores) / len(scores) or 0.0
```

上面第三行是个真实的隐患：**它靠 `and/or` 的返回值语义拼出来，结果碰巧对，但推导不出来**。

```python
def average_score(scores: list[int]) -> float:
    return scores and sum(scores) / len(scores) or 0.0

print(average_score([10, 20]))     # 15.0   结果正确，但你要靠推理才敢这么信
print(average_score([-5, -10]))    # -7.5   也正确（-7.5 是真值，or 不生效）
print(average_score([]))           # 0.0    and 短路拿到 []，[] or 0.0 → 0.0
```

**它为什么这么难推理**：`A and B or C` 实际是 `(A and B) or C`，中间结果可能是 `False`、`None`、`[]`、`""`、`0` 中任意一种假值，而**每一种假值的来源都不同**：

- `[]` 来自 `scores` 为空 → 短路，跳过除法
- `0.0` 来自平均值为零 → `or` 生效，把 `-5 和 5 的平均值 0.0` 换成了字面量 `0.0`（**这次碰巧等价，下次换个默认值就是 bug**）

第二个隐患更致命：**它同时承担「判断」和「取值」两个职责**。如果默认值不是 `0.0` 而是 `None` 或 `-1`，语义会立刻崩坏：

```python
# ❌ 如果业务要求「空列表返回 None」
def bad(scores: list[int]) -> float | None:
    return scores and sum(scores) / len(scores) or None
# avg([-5, -10]) → -7.5；avg([0, 0]) → None（❌ 平均值是 0.0，却被当成「没有值」）

# ✅ 明确的三元版本：语义一目了然，不受 and/or 短路规则影响
def average_score_safe(scores: list[int]) -> float | None:
    """空列表返回 None，其他情况返回真实平均值（可能是 0.0）。"""
    return sum(scores) / len(scores) if scores else None

print(average_score_safe([10, 20]))     # 15.0
print(average_score_safe([-5, -10]))    # -7.5
print(average_score_safe([0, 0]))       # 0.0    ✅ 关键：平均值 0.0 不再被吞掉
print(average_score_safe([]))           # None   ✅ 真正区分了「空」和「零」
```

> ⭐ **经验法则**：`and/or` 链条只适合「取个非零非空的默认值」这类场景。一旦**默认值本身可能是合法的假值**（`0`、`0.0`、`None`、`False`），就必须改用三元表达式。

**短路求值的可观察验证**：

```python
calls = []

# and：左边 False → 右边不执行
result = (len(calls) > 0) and calls.append(1)
print(calls)              # []
print(result)             # False

# or：左边 True → 右边不执行
calls.clear()
result = (len(calls) == 0) or calls.append(1)
print(calls)              # []
print(result)             # True
```

**⚠️ 副作用表达式放进 `and`/`or` 的陷阱**：

```python
items = [1, 2, 3]

# ❌ 危险写法：append 返回 None（假值），结果不直观
cond = len(items) > 0 and items.append(99)
print(cond)               # None（append 返回 None）
print(items)              # [1, 2, 3, 99]  确实执行了

# ✅ 明确意图：先判断再单独执行
if len(items) > 0:
    items.append(99)
    cond = True
else:
    cond = False
```

更简洁的安全写法：

```python
cond = len(items) > 0
if cond:
    items.append(99)
```

**核心结论**：

> `and` / `or` 的短路语义是「条件 + 保护」的组合语法。
> - 右侧**贵**或有**副作用** → 放右边，让短路帮你跳过
> - 右侧**便宜** → 放右边无所谓
> - 右侧会**崩溃** → **必须**放右边，并确保左侧能拦住它

### 2.4 真值判断（Truthy / Falsy）

**一句话定义**：Python 中任何对象都可以用在条件里，解释器会调用 `__bool__`（或 `__len__`）把对象转成 `bool`。转为 `False` 的值叫 **Falsy**，其余叫 **Truthy**。

**为什么需要它**：它让 `if data:` 这样的判断足够简洁，无需写 `if data is not None and len(data) > 0:`。

**完整的 Falsy 清单（共 10 种值）**：

| 值 | 类型 | 说明 |
| --- | --- | --- |
| `False` | 布尔 | 布尔假 |
| `None` | 空值 | 空对象 |
| `0` | 整数 | 整数零 |
| `0.0` | 浮点 | 浮点零 |
| `0j` | 复数 | 复数零 |
| `""` | 字符串 | 空字符串 |
| `"   "` | 字符串 | ⚠️ 只含空白的字符串**也是 Falsy** |
| `[]` | 列表 | 空列表 |
| `{}` | 字典 | 空字典 |
| `set()` | 集合 | 空集合 |

**其余一切都是 Truthy**：

```python
truthy = [1, -1, 0.1, "0", "False", [0], {"k": None}, {0}, (0,), object()]
for v in truthy:
    print(f"  bool({v!r:<16}) = {bool(v)}")
# 全部是 True
```

**⚠️ 三个最反直觉的案例**：

```python
# 1. 非空字符串一律为 True，哪怕内容是 "0" 或 "False"
print(bool("0"))              # True    ⚠️ 字符串 "0" 是真值！
print(bool("False"))          # True    ⚠️ 字符串 "False" 也是真值！

# 判断是不是数字字符串，要用 isdigit()
print("0".isdigit())          # True  ✅ 正确的判断方式

# 2. 只含空格的字符串仍是 True
print(bool(" "))              # True
print(bool(" ".strip()))      # False    ← strip 后才变 False

# 3. 函数和类对象永远为 True
print(bool(len))              # True    函数对象本身恒为真
print(bool(print))            # True
```

**⚠️ 一个必须澄清的误解：纯空格字符串不是 Falsy**

很多资料（包括一些入门文章）会说「只含空格的字符串也是假值」。**这是错的**：

```python
print(len("   "))          # 3    ← 长度不为 0
print(bool("   "))         # True ← 所以是 Truthy
print(bool(""))            # False ← 只有完全空字符串才是 Falsy
print(bool("   ".strip())) # False ← strip 之后才是 Falsy
```

原因很直接：`str` 的真值由 `__len__` 决定，而 `"   "` 的长度是 3。**Python 不会自动 strip 再判断**。

这条误解在真实项目里代价很大：用户输入一个空格，你的程序以为「他没填」，于是走了默认值分支，而实际上用户是「填了但是空的」——这两种情况在业务上往往要区别对待。

**实用推论：处理用户输入时先 `strip` 再判断**

```python
raw_input = "   "

if raw_input.strip():          # ✅ 先去掉空白再判断，才能识别「只填了空格」
    print(f"有效输入：{raw_input.strip()}")
else:
    print("输入为空或只有空白")
```

⚠️ `examples/L05_conditionals.py` 的 Falsy 清单里有一行 `"   "`，它打印出来的 `bool` 结果是 `True`。这恰好证明：**判定真值要看运行结果，不要背表格**。

**⚠️ 不要写 `== True` / `== False`**：

```python
value = 1

# ❌ 多余且有风险
if value == True:
    print("真")

# ✅ 直接判断
if value:
    print("真")
```

写 `== True` 的三个问题：

1. **阻止自定义对象的真值语义**：一个对象如果定义了 `__bool__` 返回 `False`，但 `__eq__` 让它等于 `True`，那 `if obj == True` 会得到 `True`——完全违背直觉。
2. **对非布尔类型产生误导**：`if 1 == True` 成立，但写代码时很少有人真的想表达「这个数字等于布尔真」。
3. **掩盖意图**：读者需要停下来判断「这是在比较布尔值，还是在判断真值」。

**明确需要区分 `True` / `False` 和「非零 / 非空」时**，用 `is`：

```python
flag = True

if flag is True:               # ✅ 明确表达「这个值就是布尔 True」
    print("确实是布尔 True")

if flag == 1:                  # ⚠️ True == 1 在 Python 中成立，但这不是你想说的
    print("True 等于 1")
```

**用真值判断简化「参数校验」**：

```python
def process(name: str, tags: list[str], config: dict | None = None) -> str:
    """用真值判断做参数校验和默认值填充。"""
    name = name.strip() or "匿名"               # 空串和纯空白都变成「匿名」
    tag_text = ",".join(tags) or "无标签"       # 空列表变成「无标签」
    cfg = config or {}                         # None 和 {} 都变成空字典（⚠️ 见下方说明）
    return f"{name}[{tag_text}] 配置项={len(cfg)}"

print(process("  ", []))              # 匿名[无标签] 配置项=0
print(process("张三", ["a", "b"]))     # 张三[a,b] 配置项=0
```

⚠️ `config or {}` 的一个隐蔽问题：如果调用方传入的是一个**非空字典**，它返回原对象；如果传入**空字典**，返回的是**新的 `{}`**。当你要修改这个字典时，两种情况行为不同：

```python
def bad(cfg: dict | None = None) -> dict:
    result = cfg or {}        # 传入 {} 时得到新的字典，修改不影响调用方
    result["x"] = 1
    return result

original: dict = {}
bad(original)
print(original)               # {} ← 调用方的字典没有被改

def good(cfg: dict | None = None) -> dict:
    result = {} if cfg is None else cfg   # 只把 None 换成新字典
    result["x"] = 1
    return result

original = {}
good(original)
print(original)               # {'x': 1} ← 修改生效，符合直觉
```

**规则**：`or` / 真值判断适合「取默认值」；`is None` 判断适合「区分没传 和 传了空值」这两种语义。

### 2.5 and / or 的返回值：不是 bool

**一句话定义**：`and` 返回**第一个假值**，如果全是真值则返回**最后一个值**；`or` 返回**第一个真值**，如果全是假值则返回**最后一个值**。

这是 Python 最容易被误解的语义之一。很多人以为 `a and b` 等价于 C/Java 的 `a && b`。

```python
# and：返回第一个 Falsy，否则返回最后一个
print(0 and 5)              # 0        ← 返回了第一个假值本身
print("" and 5)             # ''
print([] and 5)             # []
print(3 and 5)              # 5        ← 全真，返回最后一个
print("a" and "b")          # 'b'

# or：返回第一个 Truthy，否则返回最后一个
print(0 or 5)               # 5        ← 返回了第一个真值本身
print("" or "默认")          # '默认'
print([] or {})             # {}
print(3 or 5)               # 3        ← 第一个就为真，后面的不计算
```

**它和 `bool` 的关系**：把结果套上 `bool()`，就是标准的逻辑运算：

```python
print(bool(0 and 5))        # False
print(bool(3 and 5))        # True
```

**实用场景 1：取默认值（比三元更简洁，但有陷阱）**

```python
def get_grade(score: int | None) -> str:
    """未传分数时给默认分。"""
    real_score = score or 0        # ⚠️ score=0 也会变成 0（碰巧对），但 score=0 语义是「真实的零分」
    return "A" if real_score >= 90 else "B"


# ⚠️ 危险场景：0 是合法值时会被误判为「没传」
def process_2(score: int | None) -> str:
    """⚠️ score=0 时 score or -1 会得到 -1，把合法的 0 分当成缺失。"""
    adjusted = score or -1
    return f"分数 {adjusted}（-1 表示缺考）"

print(process_2(0))            # 分数 -1（缺考）  ← 但 0 分是合法输入
print(process_2(None))         # 分数 -1（缺考）  ← 这个是对的
```

**安全写法：用三元表达式明确区分「假值」和「None」**：

```python
def process_3(score: int | None) -> str:
    """✅ 三元只把 None 当作缺失，0 分原样保留。"""
    adjusted = score if score is not None else -1
    return f"分数 {adjusted}"

print(process_3(0))            # 分数 0  ✅
print(process_3(None))         # 分数 -1 ✅
```

**实用场景 2：配置合并（`or` 做兜底）**

```python
user_config = {"theme": "dark"}
default_config = {"theme": "light", "lang": "zh", "page_size": 20}

# ⚠️ or 整体兜底：用户配置非空就全用用户的，缺项不补
merged_bad = user_config or default_config
print(merged_bad)              # {'theme': 'dark'}  ← lang 和 page_size 丢了

# ✅ 逐项兜底
merged_good = {**default_config, **user_config}
print(merged_good)             # {'theme': 'dark', 'lang': 'zh', 'page_size': 20}  ✅
```

**实用场景 3：链式取值（配合函数调用，注意副作用）**

```python
data = {"user": {"profile": {"name": "张三"}}}

# 逐层判断，每层都用 and 保护
name = data.get("user") and data["user"].get("profile") and data["user"]["profile"].get("name")
print(name)                    # 张三

# ✅ 更好：字典链的取值可以一次完成判断
profile = data.get("user", {}).get("profile", {})
print(profile.get("name", "未知"))   # 张三
```

**⚠️ 陷阱：`and` 链条的返回值可能是 `None` 或 `{}`，调用者容易忘记处理**

```python
# a and b 中 a 是空列表时，结果是空列表而不是 False
result = [] and "x"
print(result)                  # []
print(type(result))            # <class 'list'>  ← 不是布尔！
if result == False:           # ⚠️ 空列表 == False → True，能用但不直观
    print("看起来对")

# ✅ 明确需要 bool 时显式转换
if not result:
    print("明确的假值判断")
```

**速记表**：

| 表达式 | 返回值 | 规则 |
| --- | --- | --- |
| `a and b` | `a`（若 `a` 为假）或 `b` | 第一个 Falsy，否则最后一个 |
| `a or b` | `a`（若 `a` 为真）或 `b` | 第一个 Truthy，否则最后一个 |
| `not a` | `bool` 的取反 | 唯一返回真 bool 的逻辑运算符 |

### 2.6 三元表达式

**一句话定义**：`值1 if 条件 else 值2` 是一个**表达式**（不是语句），值为三个部分之一。

```python
age = 20
status = "成年" if age >= 18 else "未成年"
print(status)                 # 成年
```

**为什么需要它**：某些位置只能放「值」而不能放「语句」。比如 `x = 5` 的右边必须是一个表达式，写不了 `if/else` 语句块。

```python
# ❌ 语法错误：if 是语句，不能放在右边
x = "成年" if age >= 18 else "未成年"    # ✅ 这个其实可以
# y = if age >= 18: "成年" else "未成年"  # ❌ 这个不行

# 真正需要三元的场景：函数调用参数、字典构造、f-string 内嵌
def render(user: str | None) -> str:
    """三元让「函数调用时决定显示什么」变得可行。"""
    name = user.strip() if user else "匿名用户"
    return f"<用户>{name}</用户>"

print(render("  李四  "))      # <用户>李四</用户>
print(render(None))            # <用户>匿名用户</用户>
```

**适用 1：二选一赋值**

```python
score = 45
result = "及格" if score >= 60 else "不及格"
print(result)                 # 不及格
```

**适用 2：给变量提供默认值**

```python
# 对输入做清洗后兜底
for raw in ("", "  ", "Alice"):
    name = raw.strip() or "默认名"
    print(f"{raw!r:8} -> {name}")
# ''       -> 默认名
# '  '     -> 默认名
# 'Alice'  -> Alice
```

**⚠️ 误用 1：多分支嵌套三元**

```python
n = 85

# ❌ 能跑，但需要读者在脑内构建一棵决策树
bad = "A" if n >= 90 else "B" if n >= 80 else "C" if n >= 60 else "D"
print(bad)                    # B

# ✅ 用 if/elif，层级一目了然
if n >= 90:
    good = "A"
elif n >= 80:
    good = "B"
elif n >= 60:
    good = "C"
else:
    good = "D"
print(good)                   # B
```

Python 官方风格指南明确指出：**三元表达式只在「两个分支」时使用**。三个以上分支一律用 `if/elif/else`。

**⚠️ 误用 2：有副作用的三元**

```python
counter = {"n": 0}

def bump() -> int:
    """带副作用：计数并返回。"""
    counter["n"] += 1
    return counter["n"]

# ❌ 不要这么写：读者无法确定 bump 是否被调用
result = bump() if some_condition else bump()   # 语义模糊

# ✅ 先算好值再三元
first = bump()
second = bump() if first > 0 else 0
print(first, second, counter)     # 1 2 {'n': 2}
```

三元的两个分支应该是「纯粹的值」，任何有副作用的操作都应该拆出来单独执行。

**⚠️ 误用 3：三元作为子表达式时忘记加括号**

```python
label = ""
x = 1

# ❌ 整个表达式是 or：解析为 label or ('A' if x else 'B')
# 由于 label 是空串（假值），会取右边，结果碰巧对
# 但如果 label 非空，结果就完全错了
result_wrong = label or ("A" if x else "B")
print(result_wrong)           # 'A'  ← 碰巧正确，但逻辑不是你想的

# ✅ 三元作为子表达式时，整个三元必须加括号
result_right = label if label else ("A" if x else "B")
print(result_right)           # 'A'  ← 语义明确
```

验证差异：

```python
name = "张三"
x = 1

# ❌ 解析为 name or (...)，name 为真 → 直接返回 name，x 完全没被用上
wrong = name or ("A" if x else "B")
print(wrong)                  # '张三'

# ✅ 三元优先
right = ("A" if x else "B") if name else "默认值"
print(right)                  # 'A'
```

**决策表**：

| 场景 | 用什么 |
| --- | --- |
| 两个分支赋值 | ✅ 三元 |
| 需要打印 + 赋值 + 调试 | ❌ if 语句（能看清执行了哪支） |
| 三个以上分支 | ❌ if/elif/else |
| 分支里有副作用 | ❌ if 语句 |
| 作为 f-string / 函数参数 | ✅ 三元（只能放表达式） |

### 2.7 嵌套 if 与扁平化重构

**一句话定义**：嵌套 if 是把 if 放在另一个 if 的代码块里。层级越深，缩进越深，代码向右滑，可读性越差。

**嵌套的真实代价**：

```python
age, has_pass, is_vip = 20, False, False

if age >= 18:
    if has_pass:
        if is_vip:
            access = "VIP 通道"
        else:
            access = "普通通道"
    else:
        access = "无票，拒绝"
else:
    access = "未成年，禁止"

print(access)                 # 无票，拒绝
# 缩进已达 3 层，再加一层判断就失控
```

行业经验：**超过 2 层嵌套就应该考虑重构**。

---

**⭐ 扁平化手法 1：提取中间变量**

把「多个分支共有的前提条件」算成一个有意义的布尔变量，让内层只剩一层。

```python
age, has_pass, is_vip = 20, False, False

# 提取共同前提条件到一个命名清晰的变量
is_adult_with_pass = age >= 18 and has_pass

if is_adult_with_pass:
    if is_vip:
        access = "VIP 通道"
    else:
        access = "普通通道"
else:
    access = "无权进入"

print(access)                 # 无权进入
```

提取变量时，**变量名要表达业务含义**。`is_adult_with_pass` 比 `cond` 好一百倍——它本身就是一句业务描述。

---

**⭐ 扁平化手法 2：卫语句（guard clause）提前返回 —— 工程上最推荐**

核心思想：**把「异常/退出情况」提前处理掉，让主干逻辑保持在最外层缩进**。

```python
def check_access(age: int, has_pass: bool, is_vip: bool) -> str:
    """用卫语句写出的等价实现，全部在同一缩进层。"""
    if age < 18:                       # 卫语句 1：先挡掉未成年
        return "未成年，禁止"
    if not has_pass:                   # 卫语句 2：再挡掉无票
        return "无票，拒绝"
    if is_vip:                         # 剩余情况只需一层判断
        return "VIP 通道"
    return "普通通道"                   # 兜底
```

三个调用都在同一层级读起来：

```python
print(check_access(20, True, True))     # VIP 通道
print(check_access(20, False, True))    # 无票，拒绝
print(check_access(15, True, True))     # 未成年，禁止
```

**卫语句的三个要点**：

1. **顺序按「最可能被拒绝的情况」排**，让常见情况尽早退出。
2. **每个卫语句只做一个判断**，不要 `if age < 18 or not has_pass: return "..."`——那样把两个不同的拒绝原因混在一起了，调用者无法区分。
3. **最后的正常路径落在函数最外层**，缩进最浅，可读性最好。

**参数校验必须用卫语句**，这是 Python 社区的强约定：

```python
def calc_bmi(weight_kg: float, height_m: float) -> tuple[float, str]:
    """BMI = 体重(kg) / 身高(m)²。参数校验是业务函数的第一道防线。"""
    if weight_kg <= 0 or height_m <= 0:       # 卫语句：非法输入直接抛错
        raise ValueError("身高体重必须为正数")

    bmi = weight_kg / (height_m ** 2)

    # 从高到低判断，用「下界包含」的方式避免边界重叠
    if bmi < 18.5:
        return bmi, "偏瘦"
    if bmi < 24.0:
        return bmi, "正常"
    if bmi < 28.0:
        return bmi, "偏胖"
    return bmi, "肥胖"                            # 兜底：以上之外
```

注意这里**故意不用 `elif`**，而是用连续 `if` + 提前 `return`。因为每个分支都 `return` 了，走到下一个 `if` 就意味着上一个没命中，语义和 `elif` 等价但少了缩进。

---

**⭐ 扁平化手法 3：查表 / 字典映射**

当你在**连续判断「同一个变量的不同取值」**时，字典比 if 链更短也更易扩展。

```python
# if 链：新增一个等级就要改结构
def grade_chain(score: int) -> str:
    """if 链版本。"""
    if score >= 90:
        return "A"
    if score >= 80:
        return "B"
    if score >= 60:
        return "C"
    return "D"

# 查表：数据与逻辑分离
GRADE_MAP = {90: "A", 80: "B", 60: "C", 0: "D"}

def grade_table(score: int) -> str:
    """查表版本，按阈值降序找第一个满足的。"""
    for threshold in sorted(GRADE_MAP, reverse=True):
        if score >= threshold:
            return GRADE_MAP[threshold]
    return GRADE_MAP[0]
```

验证等价：

```python
for s in (95, 85, 65, 30):
    print(f"{s:3} -> if链={grade_chain(s)} 查表={grade_table(s)}")
#  95 -> if链=A 查表=A
#  85 -> if链=B 查表=B
#  65 -> if链=C 查表=C
#  30 -> if链=D 查表=D
```

**查表更适合的场景**：取值**完全枚举**（不是范围）的时候。

```python
# 城市 → 区域，完全是枚举映射
CITY_ZONE = {
    "北京": "华北", "天津": "华北", "石家庄": "华北",
    "上海": "华东", "杭州": "华东", "南京": "华东",
    "广州": "华南", "深圳": "华南",
}

def get_zone(city: str) -> str:
    """用查表代替 if 链；查不到时用 dict.get 提供默认值。"""
    return CITY_ZONE.get(city, "未知")

for c in ("北京", "深圳", "拉萨"):
    print(f"{c} -> {get_zone(c)}")
# 北京 -> 华北
# 深圳 -> 华南
# 拉萨 -> 未知
```

**三种手法的选择**：

| 手法 | 适用条件 | 例子 |
| --- | --- | --- |
| 提取中间变量 | 嵌套浅（2 层），条件本身可复用 | 参数校验 |
| 卫语句 | 有「不满足就退出」的场景 | 函数参数校验、分层判断 |
| 查表 | 值是**枚举**的，或映射关系明确 | 状态码、城市归属、等级折扣 |

### 2.8 match 语句（Python 3.10+）

**一句话定义**：`match` 是「结构化模式匹配」语句，把一个值和一系列**模式**依次比对，命中第一个匹配的分支。

**为什么需要它**：`if/elif` 只能比较「值是否相等」。当需要同时匹配「类型 + 值 + 结构」时，`if` 需要写很多层 `isinstance` 和 `and`，可读性差。`match` 把这些组合成一个声明式的模式。

```python
def handle_status(code: str) -> str:
    """用 match 把状态码分发写清楚。"""
    match code:
        case "200":
            return "成功"
        case "404" | "403":           # | 表示「或」，多个值共用一个分支
            return "客户端错误"
        case "500" | "502":
            return "服务器错误"
        case _:                        # _ 是通配符，相当于 else
            return "未知状态码"
```

⚠️ **`match` 不需要 `break`**：整条链只会执行一个分支，执行完自动离开。

---

**能力 1：值的分发**

```python
command = {"action": "add", "name": "苹果", "count": 3}

def run(cmd: dict) -> str:
    """字典模式 + 值捕获。"""
    match cmd:
        case {"action": "quit"}:
            return "退出程序"
        case {"action": "add", "name": str(name), "count": int(n)}:
            return f"添加 {name} × {n}"          # 同时匹配「键存在 + 类型正确」
        case {"action": "add", "name": str(name)}:
            return f"添加 {name}（数量默认 1）"
        case {"action": other}:
            return f"未知命令：{other}"
        case _:
            return "非法命令格式"

print(run(command))                                    # 添加 苹果 × 3
print(run({"action": "add", "name": "香蕉"}))           # 添加 香蕉（数量默认 1）
print(run({"action": "fly"}))                          # 未知命令：fly
```

对比用 `if` 写同样的逻辑：

```python
def run_if(cmd: dict) -> str:
    """if 版本：需要 4 层嵌套 + 多次字典查询。"""
    if "action" not in cmd:
        return "非法命令格式"
    action = cmd["action"]
    if action == "quit":
        return "退出程序"
    if action == "add" and "name" in cmd and isinstance(cmd["name"], str):
        name = cmd["name"]
        count = cmd.get("count")
        if isinstance(count, int):
            return f"添加 {name} × {count}"
        return f"添加 {name}（数量默认 1）"
    return f"未知命令：{action}"
```

`match` 版本把「存在性 + 类型」检查合并进了模式，可读性优势明显。

---

**能力 2：类型 + 值的组合（if 写不干净的地方）**

```python
def describe(item: object) -> str:
    """同时匹配类型和值 —— 这是 match 的真正杀手锏。"""
    match item:
        case None:                                   # 精确匹配 None
            return "空值"
        case int() | float() if item == 0:           # 类型匹配 + if 守卫
            return "数字零"
        case int() | float():                         # 匹配任何数值
            return f"数字 {item}"
        case str() as text if text == "":             # as 绑定 + 守卫
            return "空字符串"
        case str() as text:                           # as 把值绑到 text
            return f"字符串「{text}」"
        case [x, y]:                                  # 序列模式，固定长度 2
            return f"二元列表 [{x}, {y}]"
        case [x, *rest]:                              # *rest 匹配剩余全部
            return f"列表，首元素 {x}，其余 {len(rest)} 个"
        case {"type": "user", "name": str(name)}:     # 字典模式 + 类型约束
            return f"用户对象，姓名 {name}"
        case {"type": "user"}:                        # 只看部分键
            return "用户对象（缺少姓名）"
        case _:                                       # 兜底
            return f"其他类型：{type(item).__name__}"
```

用 `if` 实现同样的功能需要：

```python
def describe_if(item: object) -> str:
    """if 版本：六层嵌套，且易错。"""
    if item is None:
        return "空值"
    if isinstance(item, (int, float)):
        if item == 0:
            return "数字零"
        return f"数字 {item}"
    if isinstance(item, str):
        if item == "":
            return "空字符串"
        return f"字符串「{item}」"
    if isinstance(item, list):
        if len(item) == 2:
            return f"二元列表 [{item[0]}, {item[1]}]"
        if len(item) > 0:
            return f"列表，首元素 {item[0]}，其余 {len(item) - 1} 个"
    if isinstance(item, dict):
        if item.get("type") == "user":
            if isinstance(item.get("name"), str):
                return f"用户对象，姓名 {item['name']}"
            return "用户对象（缺少姓名）"
    return f"其他类型：{type(item).__name__}"
```

两种写法的输出完全一致，但 `match` 版本把「什么类型 + 什么结构 + 什么值」写成了一个可扫读的声明。

**能力 3：序列模式的进阶用法**

```python
def parse_point(value: object) -> str:
    """演示序列模式和类模式。"""
    match value:
        case []:                                      # 恰好是空列表
            return "空序列"
        case [x] if x == 0:                           # 单元素且值为 0
            return "单元素 0"
        case [0, *rest]:                              # 第一个是 0
            return f"以 0 开头，共 {len(rest) + 1} 个元素"
        case [first, second]:                         # 恰好两个元素
            return f"两点：({first}, {second})"
        case [*items]:                                # 任意非空列表
            return f"{len(items)} 个元素"
        case other:
            return f"非列表：{other!r}"
```

**⚠️ `match` 的四条适用边界**：

1. **不要用它替代简单的数值判断**：`if x > 10:` 比 `case x if x > 10:` 直白得多。`match` 的价值在于「结构化」，不是「条件判断」。
2. **分支顺序仍然重要**：守卫不成立会**继续往下匹配**。

```python
def guard_demo() -> None:
    """守卫失败会继续往下匹配，不会直接跳到 case _。"""
    match 1:
        case n if n > 100:
            print("不会到这里")
        case 1:
            print("✅ 守卫不成立时，case 1 依然能匹配上")
```

3. **它不是「更省的 if」**：如果只是把 5 个 `elif x == "a"` 改成 5 个 `case "a"`，收益不大（虽然更整齐）。真正值得用 `match` 的场景是**涉及类型或结构解构**。
4. **需要 Python 3.10+**：本课程环境为 3.13。如果需要兼容旧版本，用 `sys.version_info` 判断或改用 `if` + `isinstance`。

**什么时候用 `match` 决策表**：

| 场景 | 建议 |
| --- | --- |
| 判断类型（`isinstance` 链） | ✅ `match case int() / str()` 明显更清晰 |
| 解构字典 / 序列 | ✅ `match` 是最自然的写法 |
| 多值分发（纯 `==`） | ⚠️ 两者都行，`match` 更整齐但收益有限 |
| 范围判断（`x > 10`） | ❌ 用 `if` |
| 组合条件的复杂布尔逻辑 | ❌ 用 `if`，`match` 不适合表达复杂布尔 |

### 2.9 实战：把业务规则做成「可配置的条件表」

条件分支散落在代码各处时，最难维护的是「改一个规则要找三个地方」。**把数据（阈值）和逻辑（判断）分离**，是条件分支最高级的用法。

```python
# 规则表：数据与逻辑分离，改规则不用改代码
DISCOUNT_RULES = [
    # (条件函数, 折扣率, 规则名)
    (lambda vip, amount: vip and amount >= 5000, 0.70, "VIP 大额"),
    (lambda vip, amount: vip, 0.85, "VIP"),
    (lambda vip, amount: amount >= 1000, 0.90, "大额"),
    (lambda vip, amount: amount >= 500, 0.95, "小额"),
]


def calc_discount_table(vip: bool, amount: float) -> tuple[float, str]:
    """按规则表逐条匹配，返回 (折扣后金额, 命中的规则名)。"""
    for condition, rate, name in DISCOUNT_RULES:
        if condition(vip, amount):          # 规则表的第一条 if 链
            return round(amount * rate, 2), name
    return round(amount, 2), "无折扣"
```

**⚠️ 规则表的三条使用纪律**：

1. **顺序即优先级**：从上到下第一个命中的生效，所以「更具体的规则」必须放前面。
2. **规则之间要互斥或有覆盖意识**：`VIP 大额` 必须排在 `VIP` 前面，否则 0.85 会先命中。
3. **规则表适合「变化频繁」的业务**：如果规则一年改一次，写成 `if` 链更直接；如果是运营每天都在调的活动规则，规则表的价值就体现出来了。

**规则表的另一层价值：可测试**。

```python
def verify_rules() -> None:
    """规则表可以直接用断言批量验证。"""
    assert calc_discount_table(True, 6000) == (4200.0, "VIP 大额")
    assert calc_discount_table(True, 100) == (85.0, "VIP")
    assert calc_discount_table(False, 2000) == (1800.0, "大额")
    assert calc_discount_table(False, 100) == (100.0, "无折扣")
    print("✅ 规则表全部断言通过")
```

把「判断逻辑」变成「数据 + 一个通用执行器」后，测试和变更的成本都会大幅下降。这个思路在 L13（函数）和 L18（面向对象）里会继续展开。

```python
def calc_discount(level: str, amount: float, is_member: bool) -> float:
    """根据等级、金额、会员身份计算最终应付 —— 演示多条件组合。"""
    # 第一步：等级折扣，用字典查表（扁平化手法 3）
    level_rate = {"A": 0.85, "B": 0.90, "C": 0.95}
    if level not in level_rate:
        raise ValueError(f"未知等级：{level}")
    price = amount * level_rate[level]
    # 第二步：满减，用 and 合并两个条件
    if amount >= 1000 and is_member:
        price -= 50
    # 第三步：会员额外 9 折，注意顺序（先减后折 vs 先折后减结果不同）
    if is_member:
        price *= 0.9
    # ⚠️ 顺序陷阱：(amount - 50) * 0.9 ≠ amount * 0.9 - 50
    return round(price, 2)
```

## ⚠️ 四、常见错误清单

| 错误现象 | 原因 | 正确写法 |
| --- | --- | --- |
| `SyntaxError: invalid syntax. Maybe you meant '=='` | 把赋值 `=` 写成了判断 `if x = 1:` | `if x == 1:` |
| `if x := 5:` 恒为真 | 海象表达式返回的是赋的值，非零即真 | `if (x := 5) > 0:` 或先赋值再判断 |
| `0.1 + 0.2 == 0.3` 为 `False` | 浮点二进制表示误差 | `abs(a - b) < 1e-9`；金额用整数存「分」 |
| 明明是 18 岁却被判为「未成年」 | 写成了 `18 < age`（排除 18） | `age >= 18` 或 `age > 17` |
| 用 1-based 计数循环时 `data[i]` 越界 | 计数 1-based，列表下标 0-based | `data[i - 1]`，或用 `enumerate(data, start=1)` |
| 等级判断永远走不进「优秀」分支 | `elif` 顺序把宽松条件写在前面 | 从严格到宽松排列 `elif` |
| `if` 链结束后用变量报 `NameError` | 某个分支没覆盖到，变量未赋值 | 末尾加 `else` 兜底 |
| `max(空列表)` 抛 `ValueError` | 条件里调用了会失败的昂贵操作 | `if data and max(data) > 3:` 用短路保护 |
| `bool("0")` 期望 `False` 得到 `True` | 非空字符串一律为真 | 用 `"0".isdigit()` 判断数字串 |
| `if data == True:` 判断不出自定义对象的假 | `==` 覆盖了真值语义 | 直接写 `if data:` |
| `score or 0` 让合法的 0 分变成缺考 | `or` 只看真假值，不区分 `None` 和 `0` | `score if score is not None else 0` |
| `config or {}` 修改后调用方的字典没变 | 传入空字典时 `or` 返回**新**字典 | `{} if config is None else config` |
| `label or ("A" if x else "B")` 结果不对 | 整体被解析成 `or` 表达式 | 整个三元加括号：`(三元) if label else ...` |
| 三元嵌套三层后完全读不懂 | 超过两个分支就该用 `if/elif` | 改写为 `if/elif/else` |
| `not a == b` 判断出错 | `not` 优先级高于 `==` | `not (a == b)` 或 `a != b` |
| `a and b and c` 结果是 `[]` 而不是 `False` | `and` 返回操作数而非 bool | 需要 bool 时套 `bool(...)` |
| `match` 语句在 3.9 上报 `SyntaxError` | 结构化模式匹配需要 3.10+ | `sys.version_info` 判断或改用 `if` |
| `match` 的守卫不成立就再无分支匹配 | 守卫失败会继续往下匹配，不是直接走 `_` | 确保最后有 `case _` 兜底 |
| 空列表 `max()` 在分支里被提前计算 | 条件顺序写反 | 昂贵/会失败的操作放 `and` 右侧 |

## 🧠 五、知识点速查表

### if 链与优先级

```text
if 条件1:      # 自上而下，第一个成立就停，其余全部跳过
elif 条件2:    # 相当于 else: if ...
elif 条件3:
else:          # 兜底，强烈建议写

优先级（高 → 低）：not  >  比较运算  >  and  >  or
  混用 and/or  → 必须加括号
  not a == b   → 解析为 (not a) == b，危险
  18 <= age <= 60  ✅ 链式比较，每个操作数只求值一次
```

### 短路求值

```text
a and b  → a 是 Falsy 就返回 a，不算 b；全真返回 b
a or  b  → a 是 Truthy 就返回 a，不算 b；全假返回 b

✅ 保护昂贵/会崩溃的操作：if data and max(data) > 3:
✅ 保护副作用：if ok and risky_call():
❌ 副作用表达式放进 and：cond = len(xs) > 0 and xs.append(1)  # 返回 None
```

### Truthy / Falsy

```text
Falsy（共 10 种）：
  False  None  0  0.0  0j  ""  []  {}  set()  以及空字节串 b""

⚠️ 常见误解：「   」纯空格字符串是 Falsy —— 错！
   Python 不会自动 strip。len("   ") == 3 → bool("   ") 是 True
   只有完全空字符串 "" 才是 Falsy。处理用户输入要先 strip 再判断。

⚠️ 其他反直觉：
  bool("0")      = True     数字串请用 isdigit()
  bool("False")  = True
  bool([0])      = True     非空容器就是真
  bool(len)      = True     函数对象恒为真

✅ 写 if x:       ❌ 不写 if x == True:
⚠️ x or default 会把合法的 0/""/[] 当成「没传」
   要区分就用 x if x is not None else default
```

### 三元表达式

```text
值1 if 条件 else 值2

✅ 用于：二选一赋值、函数参数、f-string 内嵌、默认值
❌ 不用：三分支以上、分支有副作用、作为子表达式时忘加括号
⚠️ label or ("A" if x else "B") 整体是 or，语义完全不同
```

### 扁平化三手法

```text
1) 提取中间变量：is_adult_with_pass = age >= 18 and has_pass
2) 卫语句（最推荐）：异常情况提前 return，主干留在最外层
     if age < 18: return "未成年"
     if not has_pass: return "无票"
     return "普通通道"
3) 查表：值是枚举的，用 dict.get(值, 默认值)
   ⚠️ 阈值范围判断 → 先排序再从高到低找第一个满足
经验：嵌套超过 2 层就该重构
```

### match 语句（3.10+）

```text
match 值:
    case 模式1 | 模式2: ...     # | 或
    case 类型() as 变量: ...     # 类型模式 + 绑定
    case [x, *rest]: ...        # 序列模式
    case {"键": str(name)}: ...  # 字典模式 + 类型约束
    case _ : ...                 # 兜底

不用 break；分支顺序重要；守卫不成立会继续往下匹配
✅ 适合：类型分发、字典/序列解构
❌ 不适合：范围判断、复杂布尔逻辑
```

### 四大陷阱速查

```text
1) if x = 1:            → SyntaxError，用 ==
   if (x := 5):         → 海象，恒为真，除非 (x := 5) > 0
2) 0.1 + 0.2 == 0.3    → False！用 abs(a-b) < 1e-9
   金额 → 整数存分：1990 + 1990 = 3980 分，精确
3) 18 < age <= 60       → 排除了 18！用 18 <= age <= 60 或 age > 17
   range(1, len+1) + data[i] → 越界，用 data[i-1] 或 enumerate
4) a or b 返回操作数不是 bool
   0 or 5 → 5 ；0 and 5 → 0 ；[] and "x" → []
```

## 📝 六、本课小结

- **if/elif/else 是「整条链只执行一个分支」**，且条件自上而下依次求值。这个语义导致**分支顺序有意义**：严格条件必须写在宽松条件之前。
- **给变量赋值的 if 链末尾总是写 `else`**，让「所有路径都有赋值」成为一眼可见的性质。
- **优先级 `not > 比较 > and > or`**，混用 `and` 和 `or` 时括号是必须的正确性保障，不是美化。`not a == b` 是最危险的一种省略。
- **短路求值是保护机制**：`and` 右侧「贵」或「会崩溃」时，把它放右边并确保左边能拦住。这比先算后判更安全，也更快。
- **`and`/`or` 返回的是操作数而非 bool**：`0 or 5` 是 `5`，`[] and "x"` 是 `[]`。这带来简洁的默认值写法，但也带来「0 被当成缺失」的风险——区分 `None` 和 `0` 时必须用 `is not None`。
- **Falsy 只有 10 种值；纯空格 `"   "` 是 Truthy**（因为 `len == 3`，Python 不会自动 strip）。`bool("0")` 和 `bool("False")` 都是 `True`。不要写 `== True`。判定真值要看运行结果，不要背二手表格。
- **三元只用于两个分支**；三分支以上用 `if/elif`，分支有副作用时用 `if`。三元作为子表达式时整个要加括号。
- **扁平化三手法**：提取中间变量（嵌套浅时）、卫语句（工程首选）、查表（值是枚举时）。嵌套超过 2 层就该重构。
- **`match` 的真正价值是「类型 + 结构」解构**，不是把 `if x == "a"` 换个写法。守卫不成立会继续往下匹配，所以末尾永远要 `case _`。
- **四大陷阱**：赋值写成判断（`=` vs `==`，海象表达式）、浮点相等（用容差或整数存分）、边界 off-by-one（`>` vs `>=`，1-based 计数 vs 0-based 下标）、`and/or` 返回值不是 bool。

> **一句话总结**：条件分支的价值不在于「学会 if 这个语法」，而在于**学会把业务规则表达成互斥、有序、可验证的结构**——分支顺序决定正确性，卫语句决定可维护性，规则表决定可扩展性。

**第 8 题（30 分）· 可解释的推荐规则引擎**

- **背景**：电商推荐、风控拦截、消息触达都需要「多规则竞争 + 冲突仲裁」。真实系统里最难的不是「判断」，而是「**为什么命中了这条规则**」。
- **要求**：新建 `rule_studio.py`，实现一个带**冲突仲裁**和**可解释输出**的规则引擎：
  1. **规则模型**：每条规则包含 `id`、`name`、`priority`（数字，越小越优先）、`when`（条件函数）、`then`（动作）、`enabled`（开关）。条件函数用 `def` 定义，接受数据字典返回 `bool`；
  2. **仲裁策略可配置**，至少实现三种：
     - `first_hit`：命中第一条就返回
     - `highest_priority`：所有命中规则中优先级最高的胜出
     - `max_effect`：按 `then` 描述的影响强度打分，得分最高者胜出
  3. **组合模式可配置**：策略为 `collect` 时返回**全部命中规则**（用于「多标签推荐」）；
  4. **可解释输出**：每次决策返回 `Decision` 对象，必须包含：命中的规则列表（id + name + 理由）、落选但命中的候选、被跳过的规则及原因（`disabled` / `条件为假`）、策略名、耗时（毫秒，用 `time.perf_counter()`）；
  5. **规则可注册与热更新**：支持 `register(rule)`、`enable/disable(rule_id)`，并支持从 JSON 文件加载规则（条件用「简单表达式字符串」或「字段+算子+值」的结构化描述）；
  6. **试运行模式（dry-run）**：不真正执行 `then` 动作，只报告「如果执行会命中什么」；
  7. **A/B 对比**：同一个数据集分别用三种策略跑，输出对比表格（命中数不同、耗时对比）；
  8. **测试集**：至少 15 条数据，构造出「三条规则都命中但优先级不同」「只有一条命中」「全部落空」三类场景。
- **输出**：
  1. `rule_studio.py` 完整代码；
  2. 三种策略的运行结果对比表；
  3. 一次 dry-run 的完整决策解释（要能看到为什么 A 胜出、B 和 C 被跳过）；
  4. 一份「规则引擎设计中最容易犯的 5 个错误」的分析。
- **验收标准**：
  - 7 项要求全部实现且有实测输出；
  - `Decision` 必须能解释**每一条落选规则的原因**（这是本题的核心考察点）；
  - 三种策略的对比必须用真实数据跑出来，不能只写结论；
  - 只用标准库（`json` / `time` / `argparse`）；
  - 每处都有中文注释。

**关键点 1：把「规则」建模成数据类，「条件」和「动作」都是可替换的函数**

```python
from dataclasses import dataclass, field
from typing import Callable
import json
import time
from pathlib import Path

# 条件函数：输入数据字典，返回 bool
Condition = Callable[[dict], bool]
# 动作函数：输入数据字典，返回可序列化的结果
Action = Callable[[dict], object]


@dataclass
class Rule:
    """一条规则：id 唯一，priority 越小越优先。"""
    id: str                                  # 规则标识
    name: str                                # 人类可读的名字（解释输出要用）
    when: Condition                           # 条件函数
    then: Action                              # 动作函数
    priority: int = 100                      # 优先级，数字越小越优先
    effect: float = 1.0                      # 影响强度，用于 max_effect 策略
    enabled: bool = True                     # 开关，支持热更新
    skipped_reason: str = ""                 # 最近一次求值被跳过的原因


@dataclass
class Decision:
    """一次决策的完整解释 —— 本题的核心数据结构。"""
    winner: Rule | None                      # 最终胜出的规则（collect 模式可能为 None）
    matched: list[Rule] = field(default_factory=list)   # 所有命中的规则
    skipped: list[tuple[Rule, str]] = field(default_factory=list)  # (规则, 原因)
    strategy: str = ""                       # 使用的仲裁策略
    cost_ms: float = 0.0                     # 求值耗时（毫秒）
    dry_run: bool = False                    # 是否为试运行
```

**关键点 2：仲裁策略必须是「可替换的策略对象」，而不是一堆 if**

```python
def arbiter_first_hit(matched: list[Rule]) -> Rule | None:
    """策略 A：命中第一条就返回（matched 已按 priority 排好序）。"""
    return matched[0] if matched else None


def arbiter_highest_priority(matched: list[Rule]) -> Rule | None:
    """策略 B：所有命中规则中优先级最高（数字最小）的胜出。"""
    return min(matched, key=lambda r: r.priority) if matched else None


def arbiter_max_effect(matched: list[Rule]) -> Rule | None:
    """策略 C：按影响强度打分，得分最高的胜出；同分时按优先级。"""
    return min(matched, key=lambda r: (-r.effect, r.priority)) if matched else None


# 策略注册表：新增策略只需加一条，不需要改引擎代码
ARBITERS = {
    "first_hit": arbiter_first_hit,
    "highest_priority": arbiter_highest_priority,
    "max_effect": arbiter_max_effect,
}
```

**关键点 3：可解释性的实现关键 —— 每条规则都要记录「为什么没被选中」**

```python
def evaluate(rules: list[Rule], data: dict, strategy: str = "first_hit",
             dry_run: bool = False) -> Decision:
    """对一条数据求值，返回带完整解释的 Decision。"""
    if strategy not in ARBITERS:
        raise ValueError(f"未知策略 {strategy}，可选：{sorted(ARBITERS)}")

    start = time.perf_counter()              # 计时开始
    matched: list[Rule] = []
    skipped: list[tuple[Rule, str]] = []

    for rule in rules:
        if not rule.enabled:
            skipped.append((rule, "disabled"))        # 开关关掉的要说清楚
            continue
        if rule.when(data):                            # 条件函数求值
            matched.append(rule)
        else:
            skipped.append((rule, "条件为假"))          # 条件不满足也要说清楚

    matched.sort(key=lambda r: r.priority)             # 按优先级升序（数字小的在前）
    winner = ARBITERS[strategy](matched) if strategy != "collect" else None

    cost_ms = (time.perf_counter() - start) * 1000     # 转成毫秒
    return Decision(winner=winner, matched=matched, skipped=skipped,
                    strategy=strategy, cost_ms=cost_ms, dry_run=dry_run)


def explain(decision: Decision, data: dict) -> str:
    """把 Decision 渲染成可读文本 —— 这是规则引擎最有价值的输出。"""
    lines = ["=" * 60, f"策略：{decision.strategy}"
             f"{'（试运行）' if decision.dry_run else ''}", "=" * 60]
    lines.append(f"输入数据：{data}")
    lines.append(f"耗时：{decision.cost_ms:.3f} ms")

    lines.append("\n【胜出规则】")
    if decision.winner is None:
        lines.append("  （无 —— 所有规则都未命中）")
    else:
        lines.append(f"  ✅ {decision.winner.id} · {decision.winner.name}"
                     f"  priority={decision.winner.priority} effect={decision.winner.effect}")

    lines.append("\n【其他命中但落选的候选】")
    others = [r for r in decision.matched if r is not decision.winner]
    if not others:
        lines.append("  （无）")
    for r in others:
        lines.append(f"  - {r.id} · {r.name}  priority={r.priority} "
                     f"effect={r.effect}（被策略 '{decision.strategy}' 排在后面）")

    lines.append("\n【被跳过的规则及原因】")
    for rule, reason in decision.skipped:
        lines.append(f"  - {rule.id} · {rule.name}：{reason}")

    return "\n".join(lines)
```

**关键点 4：从 JSON 加载规则时，必须把「数据」翻译成「函数」**

```python
OPS = {
    "==": lambda a, b: a == b,
    "!=": lambda a, b: a != b,
    ">": lambda a, b: a > b,
    ">=": lambda a, b: a >= b,
    "<": lambda a, b: a < b,
    "<=": lambda a, b: a <= b,
    "in": lambda a, b: a in b,               # 值在列表中
}


def load_rule_from_dict(spec: dict) -> Rule:
    """把 JSON 字典翻译成 Rule 对象。

    JSON 里无法直接表达函数，所以用「结构化描述」表示条件：
        {"field": "amount", "op": ">=", "value": 1000}
    再由本函数把结构翻译成真正的闭包函数。
    """
    when_spec = spec["when"]
    op_name = when_spec["op"]
    if op_name not in OPS:
        raise ValueError(f"未知算子 {op_name}，可选：{sorted(OPS)}")
    op_func = OPS[op_name]
    field = when_spec["field"]
    expected = when_spec["value"]

    # 闭包：把结构化条件变成「数据字典 -> bool」的函数
    def when(data: dict) -> bool:
        if field not in data:
            raise KeyError(f"数据中缺少字段 {field}，可用字段：{sorted(data)}")
        return bool(op_func(data[field], expected))

    def then(data: dict) -> dict:
        return {"action": spec["action"], "by": spec["id"], "data": data}

    return Rule(id=spec["id"], name=spec["name"], when=when,
                then=then, priority=spec.get("priority", 100),
                effect=spec.get("effect", 1.0))


def load_rules(path: str) -> list[Rule]:
    """从 JSON 文件加载规则列表。"""
    specs = json.loads(Path(path).read_text(encoding="utf-8"))
    return [load_rule_from_dict(s) for s in specs]
```

**关键点 5：dry-run 与开关热更新**

```python
def set_enabled(rules: list[Rule], rule_id: str, enabled: bool) -> list[Rule]:
    """热更新规则开关。⚠️ 顺序即优先级，禁用不等于删除，保留位置便于审计。"""
    for rule in rules:
        if rule.id == rule_id:
            rule.enabled = enabled
            return rules
    raise KeyError(f"规则不存在：{rule_id}")


def run_action(rule: Rule | None, data: dict, dry_run: bool = False) -> object:
    """执行动作；dry_run 时只报告不执行。"""
    if rule is None:
        return {"action": "none"}
    if dry_run:
        return {"action": rule.name, "executed": False}   # 试运行不真正执行
    return rule.then(data)
```

5. 把 `when` 换成 JSON 里的表达式字符串（如 `"age >= 18 and amount > 100"`），用 `eval` 配合受限命名空间实现——⚠️ 但要警告 `eval` 的安全风险。

</details>
