## 📖 二、知识讲解

### 2.1 字典的创建与本质：哈希表

**一句话定义**：字典（`dict`）是**键 → 值**的映射容器：键**唯一且可哈希**，值可以是任意对象。

**四种创建方式**：

```python
a = {"name": "张三", "age": 20}              # 1. 字面量（最常用）
b = dict(name="张三", age=20)                # 2. dict() + 关键字参数
c = dict([("name", "张三"), ("age", 20)])    # 3. 从键值对序列
d = {k: v for k, v in [("name", "张三"), ("age", 20)]}   # 4. 推导式
print(a == b == c == d)
# 期望输出: True
```

⚠️ **`{}` 是空字典，不是空集合**：

```python
print(type({}).__name__, type(set()).__name__)
# 期望输出: dict set
```

这个坑非常常见：`{}` 在 Python 里表示**空字典**，空集合必须写 `set()`（L11 会详讲）。

**⭐ 本质：字典是一张哈希表**

这是整个 L10 的**核心**。字典的存取过程是这样的：

```text
存进去时： key → hash(key) → 算出一个下标 → 存进对应位置
取出来时： key → hash(key) → 算出【同一个】下标 → 直接定位
```

**关键在于：取的时候不需要和任何其他元素比较。** 算一次哈希值就直接知道数据在哪，所以查询是 **O(1)**。

对比列表：列表的元素是紧挨着排的，要找某个值只能**从头一个个比**，所以是 **O(n)**。

**这个区别的代价**：字典要为哈希表结构额外花空间。实测：

```python
import sys

print(sys.getsizeof({"a": 1, "b": 2, "c": 3}))     # 184 字节
print(sys.getsizeof(("a", "b", "c")))              # 64 字节
print(sys.getsizeof(["a", "b", "c"]))              # 88 字节
# 期望输出: 184
# 期望输出: 64
# 期望输出: 88
```

字典比同规模的元组/列表大不少——因为它要额外维护**哈希表头 + 稀疏索引数组**。**用空间换查询速度**，这是哈希表的本质。

### 2.2 键必须可哈希（呼应 L09）

**一句话定义**：字典的键必须是**可哈希**（`hash()` 能算出稳定哈希值）且**不可变**的对象。

**可以作为键的类型**：

```python
for key in ["name", 42, (1, 2), True, None, frozenset({1, 2})]:
    _ = {key: "v"}                            # 全部合法
print("以上都能当键")
# 期望输出: 以上都能当键
```

**不能作为键的类型**：

```python
for key in [[1], {}, {1}]:                     # 列表、字典、集合
    try:
        _ = {key: "v"}
    except TypeError as exc:
        print(type(exc).__name__)
# 期望输出: TypeError
# 期望输出: TypeError
# 期望输出: TypeError
```

**⭐ 为什么键必须不可变（这是根本原因）**：

假设键是可变的。你把 `{key: value}` 存进字典时，Python 算了一次 `hash(key)` 得到下标 `i`，把数据放在 `i` 这个位置。然后你修改了 `key`，它的哈希值变成了 `i2`。此时你再用这个 `key` 去查——Python 算出 `i2`，去 `i2` 找，那里是空的。**原来放在 `i` 的那条记录就永久「丢失」了**。

所以字典要求一个**哈希一致性**约束：

```text
hash(key) 相等  ⟺  key 相等
```

只有当「键相等 ⟹ 哈希相等」时，字典才能保证「用同一个键永远能找回那条记录」。不可变对象天然满足这个条件。

**⭐ 呼应 L09：元组为什么「有时可以当键」**：

```python
print(hash((1, 2)))                            # 元组可哈希 ✅
try:
    hash(([1], 2))
except TypeError as exc:
    print(exc)                                  # 含列表 → 不可哈希 ⚠️
# 期望输出: -3550055125485641917
# 期望输出: unhashable type: 'list'
```

规则和 L09 一致：**元组可哈希 ⟺ 每个元素都可哈希**。`(1, 2)` 全是不可变数字，可以当键；`([1], 2)` 含列表，元组本身虽然不可变，但它的哈希值会随列表内容变化，所以不可哈希。

### 2.3 增删改查

```python
d = {"a": 1, "b": 2}

d["c"] = 3                             # 增：直接赋值
d.update({"a": 10, "d": 4})            # 增/改：批量，有则更新无则新增
d["a"] = 100                           # 改：就是赋值（键存在时）
```

**删除的三种写法**：

```python
tmp = {"a": 1, "b": 2, "c": 3}
del tmp["a"]                           # 方式1：del，不存在会 KeyError
tmp.pop("b")                           # 方式2：pop，不存在会 KeyError
print(tmp.pop("zzz", None))            # 方式3：pop 带默认值，安全
# 期望输出: None
```

**查询的三种写法**：

```python
d = {"a": 100}
print(d["a"], d.get("a"))              # 100 100
print(d.get("zzz"))                    # None  不存在返回 None
print(d.get("zzz", 0))                 # 0     不存在返回指定默认值
# 期望输出: 100 100
# 期望输出: None
# 期望输出: 0
```

⚠️ **下标查不到会抛 `KeyError`**：

```python
d = {"a": 1}
try:
    _ = d["不存在的键"]
except KeyError as exc:
    print(f"KeyError: {exc}")
# 期望输出: KeyError: '不存在的键'
```

⚠️ **别用 `d.get(k)` 的结果直接参与运算**——`None` 会引发 `TypeError`。要么用默认值，要么显式判断。

### 2.4 三种遍历方式

```python
d = {"苹果": 3, "香蕉": 5, "橙子": 2}

print(list(d))                      # ['苹果', '香蕉', '橙子']   只遍历键（默认）
print(list(d.values()))             # [3, 5, 2]               只遍历值
print([(k, v) for k, v in d.items()])   # [('苹果', 3), ...]  遍历键值对
# 期望输出: ['苹果', '香蕉', '橙子']
# 期望输出: [3, 5, 2]
# 期望输出: [('苹果', 3), ('香蕉', 5), ('橙子', 2)]
```

**`items()` 返回的是「视图对象」而不是列表**：

```python
d = {"苹果": 3}
view = d.items()
print(type(view).__name__)
# 期望输出: dict_items
```

⚠️ **视图是「动态」的**：它反映字典的**当前**内容，不是某一刻的快照。

```python
d = {"a": 1}
view = d.keys()
d["b"] = 2
print(len(view))
# 期望输出: 2
```

⚠️ 另外，`("a", 1) in d.items()` 是按**整对**判断，不是只看键：

```python
d = {"a": 1}
print(("a", 1) in d.items(), ("a", 2) in d.items())
# 期望输出: True False
```

**⭐ `items()` 比 `keys()` + 查值快一倍**

```python
import time

big = {f"k{i}": i for i in range(50_000)}

t0 = time.perf_counter()
for _ in range(20):
    total = 0
    for k in big:
        total += big[k]                 # 每个键都要再哈希查一次
t1 = time.perf_counter()
for _ in range(20):
    total = 0
    for _k, v in big.items():          # 值直接给到，不用再查
        total += v
t2 = time.perf_counter()
print(f"keys(): {(t1 - t0) * 1000:.1f} ms, items(): {(t2 - t1) * 1000:.1f} ms")
```

实测 `items()` 版本大约快一倍——因为它**少做了一半的哈希查询**。所以**遍历时永远优先用 `items()`**。

### 2.5 遍历时修改字典：`RuntimeError`

**⚠️ 改变字典「大小」会抛异常**：

```python
d = {"a": 1}
try:
    for k in d:
        d[k + "_x"] = 0                # 新增键
except RuntimeError as exc:
    print(exc)
# 期望输出: dictionary changed size during iteration
```

删除也一样：

```python
d = {"a": 1, "b": 2}
try:
    for k in d:
        del d[k]
except RuntimeError as exc:
    print(exc)
# 期望输出: dictionary changed size during iteration
```

**⚠️ 但「只改值、不加不减」是安全的**：

```python
d = {"a": 1, "b": 2}
for k in d:
    d[k] = 99                          # 只改值，大小没变
print(d)
# 期望输出: {'a': 99, 'b': 99}
```

**为什么这样设计**：遍历字典靠的是一个**内部下标**在哈希表里前进。如果遍历过程中往表里插入新键，哈希表可能需要**扩容重排**，那遍历用的下标就失效了，行为完全不可预测。所以 Python 选择**直接报错**——宁可让你明确知道「不能这么干」，也不给你一个静默出错的结果。

> 💡 这和 L08「循环中删除列表元素」是同一类问题，但注意区别：列表是**静默漏元素**，字典是**直接报错**。报错反而是更好的设计。

**✅ 两种正确写法**：

```python
# 写法一：遍历键的快照
t = {"a": 1, "b": 2, "c": 3}
for k in list(t):                       # list(t) 是键的快照
    if t[k] < 3:
        del t[k]
print(t)                                # {'c': 3}   a=1 和 b=2 都被删了

# 写法二：字典推导式重建（推荐，不动原字典）
src = {"a": 1, "b": 2, "c": 3}
t2 = {k: v for k, v in src.items() if v >= 2}
print(t2, src)                          # {'b': 2, 'c': 3} {'a': 1, 'b': 2, 'c': 3}
```

⚠️ 注意上面两个例子的**过滤条件不同**（`< 3` 和 `>= 2`），所以结果不一样——这是刻意的，避免你看混。

### 2.6 字典合并

```python
a = {"x": 1, "y": 2}
b = {"y": 20, "z": 3}

print(a | b)                            # {'x': 1, 'y': 20, 'z': 3}  右边覆盖左边
print(a)                                # {'x': 1, 'y': 2}   原字典不变

c = a.copy()
c |= b                                   # 原地合并
print(c)                                # {'x': 1, 'y': 20, 'z': 3}
# 期望输出: {'x': 1, 'y': 20, 'z': 3}
# 期望输出: {'x': 1, 'y': 2}
# 期望输出: {'x': 1, 'y': 20, 'z': 3}
```

**两种写法等价**：`a | b` 和 `{**a, **b}` 结果相同，`|` 更简洁。

⚠️ **字典不支持 `+`**：

```python
try:
    _ = {"a": 1} + {"b": 2}
except TypeError as exc:
    print(exc)
# 期望输出: unsupported operand type(s) for +: 'dict' and 'dict'
```

⚠️ **`update` 返回 `None`，会原地修改**：

```python
d = {"x": 1}
result = d.update({"z": 9})
print(result, d)                        # None {'x': 1, 'z': 9}
# 期望输出: None {'x': 1, 'z': 9}
```

⚠️ 所以 `x = d.update(...)` 这种写法**一定错**：更新生效了，但 `x` 是 `None`。这是和列表 `append` 一样的坑（L08 讲过）。

### 2.7 嵌套字典与安全取值

```python
config = {
    "db": {"host": "localhost", "port": 5432},
    "app": {"name": "myapp", "debug": True},
}
print(config["db"]["host"])
# 期望输出: localhost
```

⚠️ **逐层 `get` 很啰嗦，而且中间层缺失就断了**：

```python
print(config.get("cache", {}).get("host", "默认"))
# 期望输出: 默认
```

这个写法能工作，但每层都要写一个默认值，一旦层数多起来就很难维护。

**✅ 实战：用循环下钻**：

```python
def deep_get(data: dict, path: str, default: object = None) -> object:
    """按 'a.b.c' 形式的路径安全取值。"""
    current: object = data
    for key in path.split("."):
        if not isinstance(current, dict) or key not in current:
            return default              # 任何一层断了就返回默认值
        current = current[key]
    return current


print(deep_get(config, "db.host"))        # localhost
print(deep_get(config, "cache.host"))     # None   中间层不存在，安全返回
print(deep_get(config, "db.port", 0))     # 5432
```

这个函数在真实项目里非常有用（配置读取、日志解析都用得上），L27-L31 的标准库专题会进一步讨论。

### 2.8 三大专用字典

#### `defaultdict` —— 自动创建默认值

```python
from collections import defaultdict

dd = defaultdict(list)
dd["苹果"].append(3)                     # 不用先判断键是否存在
dd["香蕉"].append(5)
dd["苹果"].append(2)
print(dict(dd))
# 期望输出: {'苹果': [3, 2], '香蕉': [5]}
```

对比普通字典，同样的逻辑要写 4 行：

```python
plain = {}
for item, price in [("苹果", 3), ("香蕉", 5), ("苹果", 2)]:
    if item not in plain:
        plain[item] = 0
    plain[item] += price
print(plain)
# 期望输出: {'苹果': 5, '香蕉': 5}
```

`defaultdict` 把「不存在就建 + 然后累加」这两步合并成一步。

⚠️ **`defaultdict` 的陷阱：读也会创建**

```python
trap = defaultdict(list)
print(trap["从未出现过的键"])             # []
print(dict(trap))                        # {'从未出现过的键': []}  ⚠️ 字典被污染了！
```

**只是「读」了一下，字典却多了一个键**。因为 `__getitem__` 找不到时**不知道你是要读还是要写**，只能一律创建。

**使用原则**：只在「确定要写入」的场景用 `defaultdict`，**不要用 `x = dd[k]` 的方式试探存在性**——要用就 `k in dd` 或 `dd.get(k)`。

#### `Counter` —— 专门计数

```python
from collections import Counter

words = ["apple", "banana", "apple", "orange", "banana", "apple"]
cnt = Counter(words)
print(dict(cnt))
print(cnt["apple"], cnt["从未出现"])       # 3 0   ⚠️ 不存在的键返回 0 而不报错
print(cnt.most_common(2))                  # [('apple', 3), ('banana', 2)]
print(sum(cnt.values()))                   # 6
# 期望输出: {'apple': 3, 'banana': 2, 'orange': 1}
# 期望输出: 3 0
# 期望输出: [('apple', 3), ('banana', 2)]
# 期望输出: 6
```

⭐ **`Counter` 的三个优势**：

1. **不存在的键返回 0**，不像普通字典那样 `KeyError`；
2. **内置统计功能**：`most_common(n)` 取前 n 个（排行榜场景直接能用）；
3. **一行搞定**：手写计数要 6 行，`Counter` 只要 1 行。

另外它支持运算符：`cnt1 & cnt2` 取交集（两边都出现的）、`cnt1 | cnt2` 取并集、`cnt1 - cnt2` 取差集。

#### `OrderedDict` —— 大部分场景已无必要

⚠️ **Python 3.7+ 起，普通 `dict` 已经保证「保持插入顺序」**：

```python
print(list({"b": 1, "a": 2, "c": 3}))     # ['b', 'a', 'c']   就是插入顺序
# 期望输出: ['b', 'a', 'c']
```

所以 `OrderedDict` 在「保序」这个需求上**已经被普通字典取代**了（`dict` 更快、更省内存）。

**但它仍有两个独有能力**：

```python
od = OrderedDict([("a", 1), ("b", 2), ("c", 3)])
od.move_to_end("a")                       # 把 a 移到末尾
print(list(od))                           # ['b', 'c', 'a']

od2 = OrderedDict([("a", 1), ("b", 2)])
print(od2.popitem(last=False))            # ('a', 1)  弹出【第一个】
# 期望输出: ['b', 'c', 'a']
# 期望输出: ('a', 1)
```

⚠️ 普通 `dict.popitem()` 只能弹出**最后一个**（LIFO 语义）；想弹出第一个就必须 `next(iter(d))` 再 `del` 两步。

**适用场景**：实现 **LRU 缓存**（Least Recently Used）时，`move_to_end` + `popitem(last=False)` 是标准组合。

### 2.9 字典推导式

```python
words = ["apple", "banana", "cherry", "date"]

print({w: len(w) for w in words})
# 期望输出: {'apple': 5, 'banana': 6, 'cherry': 6, 'date': 4}

print({w: len(w) for w in words if len(w) > 5})
# 期望输出: {'banana': 6, 'cherry': 6}
```

**键值互换**（反转映射）：

```python
scores = {"张三": 88, "李四": 92, "王五": 79}
print({v: k for k, v in scores.items()})
# 期望输出: {88: '张三', 92: '李四', 79: '王五'}
```

**从平行列表构建**：

```python
names = ["张三", "李四", "王五"]
nums = [88, 92, 79]
print({n: s for n, s in zip(names, nums)})
# 期望输出: {'张三': 88, '李四': 92, '王五': 79}
```

**值带条件转换**：

```python
passed = {k: ("及格" if v >= 85 else "不及格") for k, v in scores.items()}
print(passed)
# 期望输出: {'张三': '及格', '李四': '及格', '王五': '不及格'}
```

> 💡 字典推导式是「**转换 + 过滤**」的最短路径。凡是「遍历字典生成新字典」的需求，都应该先想想能不能用推导式一行搞定。

### 2.10 ⚠️ `get` 的隐藏成本：默认值总会被求值

这是本课最容易被忽略、但在性能敏感场景很关键的知识点。

**实测**：

```python
calls = []

def expensive_default() -> int:
    calls.append(1)
    return 0

d = {"present": 1}
calls.clear()
_ = d.get("present", expensive_default())   # 键【存在】！
print(len(calls))                            # 1   ⚠️ 白算了
```

⚠️ **即使键存在，`expensive_default()` 也被调用了一次**，结果被直接丢弃。

**原因**：Python 是**先求值实参、再调用函数**的。写 `d.get(k, f())` 时，`f()` 在 `get` 被调用**之前**就已经算完了，`get` 只是「有键就用旧值，没键才用这个已经算好的值」。

**✅ 正确写法：只在真的缺失时才计算**：

```python
calls.clear()
value = d.get("absent")
if value is None:
    value = expensive_default()
print(len(calls))                            # 1   键不存在时才算
```

```python
calls.clear()
value = d.get("present")
if value is None:
    value = expensive_default()
print(len(calls))                            # 0   键存在时一次都不算 ✅
```

> 💡 **判断标准**：`get` 的默认值如果只是常量（`0`、`""`、`[]`），随便用；如果默认值需要**计算**（查数据库、格式化字符串、建对象），一定要用「先 get 再判断」的写法。

### 2.11 性能对比：字典 O(1) vs 列表 O(n)

**在 20 万元素里找一个不存在的元素**：

```python
big_dict = {f"key_{i}": i for i in range(200_000)}
big_list = [f"key_{i}" for i in range(200_000)]

t0 = time.perf_counter()
for _ in range(1000):
    _ = "key_199999" in big_dict        # O(1)
t1 = time.perf_counter()
for _ in range(1000):
    _ = "key_199999" in big_list        # O(n)
t2 = time.perf_counter()

print(f"字典: {(t1 - t0) * 1000:.2f} ms")
print(f"列表: {(t2 - t1) * 1000:.2f} ms")
# 期望输出: 字典: 0.02 ms
# 期望输出: 列表: 1314.48 ms
```

实测约 **0.02 ms vs 1314 ms**——相差约 6 万倍。

**⭐ 更重要的是「增长曲线」**：

| 元素数 | 字典查找 | 增长 | 列表查找 | 增长 |
| --- | --- | --- | --- | --- |
| 50,000 | 0.01 ms | — | 65.28 ms | — |
| 100,000 | 0.01 ms | 0.70× | 132.98 ms | 2.04× |
| 200,000 | 0.01 ms | 1.03× | 256.00 ms | 1.93× |
| 400,000 | 0.01 ms | 1.08× | 1194.51 ms | 4.67× |

**数据量每翻一倍**：
- **字典耗时基本不变**（0.70× ~ 1.08×）→ 这就是 **O(1)**；
- **列表耗时约翻倍甚至更多**（1.93× ~ 4.67×）→ 这是 **O(n)**（超出是因为还有缓存未命中的开销）。

> 💡 这张表比「快 6 万倍」这个数字更有说服力，因为它说明**数据量越大，差距越悬殊**。10 个元素时两者差不多，10 万个元素时列表已经不可用了。

### 2.12 实战：配置字典与安全访问

```python
DEFAULTS = {
    "app": {"name": "myapp", "debug": False, "port": 8080},
    "db": {"host": "localhost", "port": 5432, "name": "test"},
    "log": {"level": "INFO", "file": "app.log"},
}


def merge_config(user: dict) -> dict:
    """把用户配置合并到默认配置上：深合并，用户值优先。"""
    result = {}
    for section, defaults in DEFAULTS.items():
        # 用户提供了这一节就基于用户的，否则用默认的
        user_section = user.get(section, {})
        result[section] = {**defaults, **user_section}      # 逐节深合并
    return result


def get_path(data: dict, path: str, default: object = None) -> object:
    """按 'a.b.c' 路径取值，任何一层缺失都返回默认值。"""
    current: object = data
    for key in path.split("."):
        if not isinstance(current, dict) or key not in current:
            return default
        current = current[key]
    return current


user_cfg = {"app": {"debug": True}, "db": {"port": 5433}}
final = merge_config(user_cfg)

print(final["app"]["debug"], final["app"]["name"])
# 期望输出: True myapp
print(final["db"]["port"], final["db"]["host"])
# 期望输出: 5433 localhost
print(final["log"]["level"])
# 期望输出: INFO

print(get_path(final, "db.port"), get_path(final, "db.user"), get_path(final, "x.y.z", "默认"))
# 期望输出: 5433 None 默认
```

这个模式（**默认配置 + 深合并 + 安全取值**）是真实项目里处理配置的标准做法。

## ⚠️ 四、常见错误清单

| 错误现象 | 原因 | 正确写法 |
| --- | --- | --- |
| `{[1]: 'v'}` 抛 `TypeError` | 列表不可哈希 | 换成元组 `(1,)` |
| `hash(([1], 2))` 抛 `TypeError` | 元组含不可哈希元素 | 换成全不可变元素 |
| `d['k']` 抛 `KeyError` | 下标找不到就报错 | `d.get('k')` 或 `d.get('k', 默认值)` |
| `None` 参与运算抛 `TypeError` | `get` 返回了 `None` | 显式判断或给默认值 |
| `x = d.update(...)` 得到 `None` | `update` 不返回值 | 分两行写 |
| 遍历时加/删键抛 `RuntimeError` | 改变大小会让下标失效 | 遍历 `list(d)` 或用推导式 |
| 以为遍历时改值也会报错 | 改值不改变大小 | 改值是安全的 |
| `d.get(k, f())` 中 `f()` 白跑 | 实参先求值 | 先 `get` 再判断 `None` |
| `dd[k]` 只是读却污染了字典 | `defaultdict` 读也创建 | 用 `k in dd` 或 `dd.get(k)` |
| 认为 `OrderedDict` 才能保序 | 3.7+ 的 `dict` 已保序 | 直接用 `dict` |
| `{"a":1} + {"b":2}` 抛 `TypeError` | 字典不支持 `+` | 用 `|` 或 `{**a, **b}` |
| `list(d.values())` 当成去重 | 值可能重复 | 需要唯一就用 `set(d.values())` |
| 用列表做「去重容器」查元素 | 列表查找是 O(n) | 改用集合或字典 |
| `d.items()` 当成列表用 | 它是视图对象 | 需要列表就 `list(d.items())` |

## 📝 六、本课小结

- **字典的本质是哈希表**：存和取都通过 `hash(key)` 直接算出下标，**不需要和任何元素比较**，所以查询是 **O(1)**。代价是要为哈希表结构（表头 + 稀疏索引）额外花内存——实测 3 键字典 184 字节 vs 同规模元组 64 字节。
- **键必须可哈希的根本原因是「防止记录丢失」**：如果你能改掉键的值，它的哈希值就变了，原位置再也找不回那条记录。所以字典要求 `hash(key) 相等 ⟺ key 相等`。
- **元组当键的规则和 L09 一致**：`(1, 2)` ✅ 但 `([1], 2)` ❌，因为**元组可哈希 ⟺ 每个元素都可哈希**。
- **`d[k]` 找不到报 `KeyError`，`d.get(k)` 返回 `None`**。要参与运算的值必须用 `get(k, 默认值)` 或显式判断，否则 `None` 会引发 `TypeError`。
- **遍历优先用 `items()`**——它比 `keys()` + 再查值**快一倍**，因为少做了一半的哈希查询。
- **遍历时改「值」安全，改「大小」报 `RuntimeError`**。原因是插入可能导致哈希表扩容重排，让遍历用的下标失效。正确写法是遍历 `list(d)` 快照，或用字典推导式重建（后者不修改原字典）。
- **字典合并用 `|`（新字典）或 `|=`（原地）**，**不支持 `+`**。`update()` 返回 `None`，所以 `x = d.update(...)` 一定是错的。
- **`defaultdict` 的陷阱是「读也创建」**：用 `dd[k]` 试探存在性会**污染字典**。要判断存在请用 `k in dd` 或 `dd.get(k)`。
- **`Counter` 相比手写计数有三个优势**：不存在的键返回 0 而不报错、内置 `most_common(n)`、一行搞定（手写要 6 行）。
- **`OrderedDict` 在 3.7+ 后大部分场景已无必要**，因为普通 `dict` 已保证插入顺序且更快更省。但 `move_to_end(k)` 和 `popitem(last=False)` 仍是独有能力，**LRU 缓存**必须用它。
- **⚠️ `get` 的默认值表达式总会被求值**：写 `d.get(k, f())` 时 `f()` 在 `get` 调用前就执行了，**即使键存在也白算**。默认值需要计算时必须「先 get 再判断 `None`」。
- **性能差距用「增长曲线」比「快 N 倍」更有说服力**：实测 20 万元素查找，字典 0.02 ms vs 列表 1314 ms；且**数据量每翻倍，字典耗时基本不变（1.0× 左右），列表耗时约翻倍**——这才是 O(1) 与 O(n) 的本质区别。
- **列表当「去重容器 + 成员判断」是性能杀手**：`x in list` 是 O(n)，而 `x in set` 是 O(1)。这直接引出下一课的集合。

> **一句话总结**：字典用「**空间换时间**」，把「挨个比较」的 O(n) 查找变成了「算一次哈希」的 O(1) 定位——代价是键必须不可变、内存要额外开销。而它的三个易错点（遍历时改大小、`defaultdict` 读污染、`get` 默认值白算）都是**惰性求值和视图语义**带来的连锁反应，理解了原理就不会再踩。

**关键点 1：来源追踪（第 2 题的核心设计）**

思路：合并时不只记录「最终值」，还要记录「这个值是谁贡献的」。用一个「来源字典」和主配置**并行维护**。

```python
import os


class ConfigSystem:
    """带来源追踪的层次化配置系统。"""

    def __init__(self, defaults: dict) -> None:
        self._defaults = defaults
        self._sources: dict[str, str] = {}      # "db.port" → "命令行"
        self._record(defaults, "默认值")

    def _record(self, data: dict, label: str, prefix: str = "") -> None:
        """递归给每个叶子节点打上来源标签。"""
        for key, value in data.items():
            path = f"{prefix}{key}"
            if isinstance(value, dict):
                self._record(value, label, f"{path}.")
            else:
                self._sources[path] = label

    def _apply(self, data: dict, label: str, prefix: str = "") -> None:
        """合并用户配置并更新来源（后覆盖前，优先级更高）。"""
        for key, value in data.items():
            path = f"{prefix}{key}"
            if isinstance(value, dict) and isinstance(self._defaults.get(key), dict):
                self._apply(value, label, f"{path}.")
            else:
                self._current[path] = value
                self._sources[path] = label       # ⭐ 覆盖来源标签
```

**关键点 2：环境变量的层级约定（第 8 题）**

```python
def load_env(prefix: str = "APP") -> dict:
    """用【双下划线】表示嵌套层级：APP_DB__PORT=5433 → {"db": {"port": 5433}}。

    ⚠️ 为什么用双下划线而不是单下划线？因为单下划线是键名里本来就有的字符
       （比如 log_level），用双下划线可以无歧义地切开层级。
    """
    result: dict = {}
    for env_key, raw in os.environ.items():
        if not env_key.startswith(prefix + "__"):
            continue
        parts = [p.lower() for p in env_key[len(prefix) + 2:].split("__")]
        current = result
        for part in parts[:-1]:              # 逐层下钻创建字典
            current = current.setdefault(part, {})
        # ⭐ 按目标字段的类型自动转换，否则环境变量永远是字符串
        current[parts[-1]] = cast_value(raw)
    return result


def cast_value(raw: str) -> object:
    """把环境变量的字符串转成合适的类型。"""
    if raw.lower() in ("true", "false"):
        return raw.lower() == "true"
    if raw.isdigit():
        return int(raw)
    if "," in raw:
        return [p.strip() for p in raw.split(",")]
    return raw
```

⚠️ **`cast_value` 是必需的**：环境变量在操作系统层面**永远是字符串**，如果不转换，配置里的 `port` 会变成 `"5433"` 而不是 `5433`，然后任何数值比较都会静默出错。

**关键点 3：增量合并（第 7 题的性能关键）**

思路：L09 讲过的**结构共享**——如果某个子树完全没变，就**复用**它，不重新深合并。

```python
import copy


def deep_merge_incremental(base: dict, override: dict) -> dict:
    """⭐ 只重建【真正变化的子树】，没变的部分直接复用。

    对比朴素 deep_merge：它总是为每一层创建新字典；
    这里如果子树内容没变，就返回【原对象】，省掉递归和分配。
    """
    result = base.copy()                      # 顶层永远新建（便宜）
    for key, new_value in override.items():
        old_value = base.get(key)
        if isinstance(old_value, dict) and isinstance(new_value, dict):
            merged = deep_merge_incremental(old_value, new_value)
            # ⭐ 关键：内容没变就复用原对象，避免结构共享失效
            result[key] = merged if merged != old_value else old_value
        else:
            result[key] = new_value
    return result


def reuse_ratio(a: dict, b: dict) -> float:
    """统计两个字典之间共享的子对象比例，用 id() 验证。"""
    ids_a = collect_container_ids(a)
    ids_b = collect_container_ids(b)
    if not ids_a:
        return 0.0
    return len(ids_a & ids_b) / len(ids_a)


def collect_container_ids(obj: object) -> set[int]:
    """递归收集所有容器（dict/list/set）的 id。"""
    found: set[int] = set()
    if isinstance(obj, dict):
        found.add(id(obj))
        for k, v in obj.items():
            found |= collect_container_ids(k) | collect_container_ids(v)
    elif isinstance(obj, (list, set)):
        found.add(id(obj))
        for item in obj:
            found |= collect_container_ids(item)
    return found
```

**关键点 4：不可变配置快照（第 5 题）**

```python
import copy
from types import MappingProxyType


class FrozenConfig:
    """不可变配置：任何修改都抛异常。

    ⭐ 为什么配置要不可变？因为配置会在程序运行中被【多处读取】。
       如果某个模块不小心改了它，其他模块拿到的就不一致了——极难排查。
       呼应 L09：不可变性带来「可安全共享」。
    """

    _FROZEN = "配置是只读的，不能修改（需要修改请重新加载）"

    def __init__(self, data: dict) -> None:
        # ⭐ 关键：先 deepcopy 再冻结，否则冻结的是【调用方的对象】
        self._data = self._deep_freeze(copy.deepcopy(data))

    def _deep_freeze(self, obj: object) -> object:
        """递归地把 dict 包成 MappingProxyType、list 包成 tuple。"""
        if isinstance(obj, dict):
            return MappingProxyType(
                {k: self._deep_freeze(v) for k, v in obj.items()}
            )
        if isinstance(obj, list):
            return tuple(self._deep_freeze(v) for v in obj)
        return obj

    def __getitem__(self, key: str) -> object:
        return self._data[key]

    def __setitem__(self, key: str, value: object) -> None:
        raise TypeError(self._FROZEN)

    def __delitem__(self, key: str) -> None:
        raise TypeError(self._FROZEN)

    def get(self, path: str, default: object = None) -> object:
        """按 'a.b.c' 路径取值。"""
        current: object = self._data
        for part in path.split("."):
            if not isinstance(current, (dict, MappingProxyType)) or part not in current:
                return default
            current = current[part]
        return current
```

⚠️ **`MappingProxyType` 只冻结最外层**：所以必须**递归**冻结所有子字典，否则内层照样能被改。这是一个很容易漏掉的点。

def modify_while_iterating() -> None:
    """遍历时改值 vs 改大小的区别。"""
    print("  【遍历时改大小】→ RuntimeError")
    try:
        d = {"a": 1, "b": 2}

    except RuntimeError as exc:
        print(f"    新增键 → {exc}")

    try:
        d = {"a": 1, "b": 2}
        for k in d:
            del d[k]
    except RuntimeError as exc:
        print(f"    删除键 → {exc}")

    print("  【遍历时只改值】→ 安全")
    d = {"a": 1, "b": 2}
    for k in d:
        d[k] = 99
    print(f"    改值后 {d}")

    print("\n  三种正确写法（删除值 < 3 的键）：")

    t1 = src.copy()
    for k in list(t1):

    for k, v in list(t2.items()):
        if v < 3:

    print(f"    写法2 items() 快照   → {t2}")

    t3 = {k: v for k, v in src.items() if v >= 3}

class LruCache:
    """⭐ 用 OrderedDict 实现的 LRU 缓存——它唯一不可替代的场景。"""

    def __init__(self, capacity: int) -> None:
        self._data: OrderedDict[str, object] = OrderedDict()
        self._capacity = capacity

    def get(self, key: str) -> object | None:
        """命中则移到末尾（标记为最近使用）。"""
        if key not in self._data:
            return None
        self._data.move_to_end(key)             # ⭐ OrderedDict 独有能力
        return self._data[key]

    def put(self, key: str, value: object) -> None:
        """写入；超容量时淘汰【最久未使用】的（第一个）。"""
        if key in self._data:
            self._data.move_to_end(key)
        self._data[key] = value
        if len(self._data) > self._capacity:
            self._data.popitem(last=False)      # ⭐ 弹出第一个（最久未用）

def deep_get(data: dict, path: str, default: object = None) -> object:
    """按 'a.b.c' 取值，任何一层缺失返回默认值。

    ⚠️ 定义在【模块级】——ConfigReader 也要用它。
    """
    current: object = data
    for part in path.split("."):
        if not isinstance(current, dict) or part not in current:
            return default
        current = current[part]
    return current


def deep_set(data: dict, path: str, value: object) -> None:
    """按 'a.b.c' 赋值，自动创建中间层。"""
    parts = path.split(".")
    current = data
    for part in parts[:-1]:                    # 逐层下钻
        if part not in current or not isinstance(current[part], dict):
            current[part] = {}                 # ⭐ 不存在就建（注意会覆盖非 dict 值）
        current = current[part]
    current[parts[-1]] = value

def deep_merge(base: dict, override: dict) -> dict:
    """递归合并两个字典：override 覆盖 base，返回新字典，两者都不被修改。

    ⚠️ 定义在【模块级】而不是函数内——因为 ConfigReader 也要用它。
       把工具函数定义在另一个函数里会让它无法被复用。
    """
    result = base.copy()
    for key, new_value in override.items():
        if (key in result and isinstance(result[key], dict)
                and isinstance(new_value, dict)):
            result[key] = deep_merge(result[key], new_value)   # 递归
        else:
            result[key] = new_value
    return result

class ConfigReader:
    """配置读取模块：默认值 + 深合并 + 类型转换。"""

    DEFAULTS = {
        "app": {"name": "myapp", "debug": False, "port": 8080},
        "db": {"host": "localhost", "port": 5432, "name": "test"},
    }

    def __init__(self, user_cfg: dict | None = None) -> None:
        self._cfg = deep_merge(self.DEFAULTS, user_cfg or {})

    def get(self, path: str, default: object = None) -> object:
        return deep_get(self._cfg, path, default)

    def get_int(self, path: str, default: int = 0) -> int:
        """带类型转换的取值：环境变量等来源可能是字符串。"""
        value = self.get(path)
        try:
            return int(value)
        except (TypeError, ValueError):
            return default

    def get_bool(self, path: str, default: bool = False) -> bool:
        value = self.get(path)
        if isinstance(value, bool):
            return value
        if isinstance(value, str):
            return value.lower() in ("true", "1", "yes", "on")
        return default

    def as_dict(self) -> dict:
        """返回只读视图，防止调用方改坏内部状态。"""
        return MappingProxyType(self._cfg)

**第 4 题「迷你索引」的核心：索引失效会返回什么错误结果**

这是本题的重点——它能让你体会「索引必须同步维护」的真实代价。

```python
class FastIndex:
    """列表存行 + 字典索引。"""

    def __init__(self, fields: list[str]) -> None:
        self.fields = list(fields)
        self.rows: list[list] = []
        self.index: dict[str, dict[object, list[int]]] = {}

    def insert(self, row: list) -> int:
        """插入一行并【同步维护索引】。"""
        self.rows.append(row)
        pos = len(self.rows) - 1
        for field in self.index:               # ⭐ 每个已建的索引都要更新
            value = row[self.fields.index(field)]
            self.index[field].setdefault(value, []).append(pos)
        return pos

    def fast_find(self, field: str, value: object) -> list[int]:
        """O(1) 查询：一次哈希直接拿到所有行号。"""
        if field not in self.index:
            self.build_index(field)            # 懒建索引
        return self.index[field].get(value, [])

    def naive_find(self, field: str, value: object) -> list[int]:
        """O(n) 查询：全表扫描。作为性能对照。"""
        col = self.fields.index(field)
        return [i for i, row in enumerate(self.rows) if row[col] == value]
```

```python
def longest_unique_substr_hash(s: str) -> int:
    """最长无重复子串 O(n)：用字典记录每个字符【最后一次出现的位置】。

    ⭐ 为什么这能降到 O(n)？因为我们不再枚举子串，而是
       「右指针右移一格 → 检查是否重复 → 不重复就更新长度」，
       每个字符只处理常数次。
    """
    last_seen: dict[str, int] = {}             # 字符 → 最后出现的位置
    best = start = 0
    for i, ch in enumerate(s):
        if ch in last_seen and last_seen[ch] >= start:
            # 重复了：把左边界跳到「重复字符上次位置 + 1」
            start = last_seen[ch] + 1
        last_seen[ch] = i                      # 记录当前位置
        best = max(best, i - start + 1)
    return best


def group_anagrams_hash(words: list[str]) -> list[list[str]]:
    """字母异位词分组：用【字典计数键】做 O(n·k) 分组。

    ⭐ 技巧：把每个词的字符计数变成一个 tuple 当字典键。
       「同一组异位词」的计数键天然相同 → 一次哈希就分好组。
    """
    groups: dict[tuple, list[str]] = {}
    for w in words:
        counts = [0] * 26                     # 用计数 tuple 当键
        for ch in w:
            counts[ord(ch) - ord('a')] += 1
        groups.setdefault(tuple(counts), []).append(w)
    return list(groups.values())
```

**为什么这两个题值��做**：它们体现了哈希优化最核心的思路——**把「反复比较」换成「反复查表」**。数组/字符串的问题里，凡是「需要判断某个元素之前有没有出现过」，都可以用字典或集合把 O(n) 的查找降成 O(1)。
