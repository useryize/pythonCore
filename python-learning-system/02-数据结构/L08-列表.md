## 📖 二、知识讲解

### 2.1 列表的创建与本质：动态数组

**一句话定义**：列表（`list`）是 Python 内置的**有序、可变、可重复**的序列容器；在 CPython 中它的底层实现是**动态数组**。

**为什么需要它**：L01 只讲了「列表是一种容器」。但要真正用好它，必须知道它的物理结构——因为**物理结构直接决定了每种操作的复杂度**。

**三种创建方式**：

```python
nums = [1, 2, 3]                                        # 方式1：字面量（最常用）
empty: list[int] = []                                   # ⚠️ 空列表用 []，空「集合」要用 set()
list(range(1, 4))                                      # 方式2：list(可迭代对象) → [1, 2, 3]
[n * n for n in range(4)]                              # 方式3：推导式（L07 讲过，数据变换首选）
[0] * 3                                                # 方式4：乘法（⚠️ 有陷阱，见下）
```

⚠️ **重要提醒**：`list(集合)` 的顺序由哈希表决定，**不是插入顺序**。如果你需要保留原始顺序，必须用「`seen` 集合 + `unique` 列表」（L07 的保序去重模式）。

---

**⭐ 本质：动态数组的三个组成部分**

「动态数组」这个结构由三部分组成：

| 组成 | 含义 | 决定了什么 |
| --- | --- | --- |
| **连续内存块** | 所有元素紧挨着存放，靠下标算偏移量 | 能 O(1) 随机访问 |
| **长度（size）** | 现在有几个元素 | `len()` 返回它 |
| **容量（capacity）** | 底层内存能装几个元素 | 通常 ≥ 长度，是「预留空间」 |

**为什么要有「容量」这个概念**：如果每次 `append` 都恰好只申请 1 个位置，那么连续追加 100 万次就要申请 100 万次内存，而每次申请都可能触发「找新块 → 拷贝全部数据」——那是 O(n²)。

所以 CPython 采用**超额分配**：容量不够时，不申请「正好够用」的大小，而是一次多要约 12.5%。

```python
import sys

growing: list[int] = []                        # 从空列表开始连续 append
previous_size = 0
for i in range(30):
    growing.append(i)
    current_size = sys.getsizeof(growing)      # 底层容量换算成的字节数
    if current_size != previous_size:          # 只有内存变大时才打印
        print(f"长度 {len(growing):>2} → {current_size} 字节")
        previous_size = current_size
```

输出：

```text
长度  1 → 88 字节      长度  9 → 184 字节      长度 25 → 312 字节
长度  5 → 120 字节     长度 17 → 248 字节
```

⚠️ 注意：**长度从 1 涨到 5，内存一次都没变**。这正是超额分配的证据——容量早就预留好了，所以这 4 次 `append` 全都没有触发内存分配。

**这个设计的取舍**（面试高频）：**得到**的是 `append` 的**平均** O(1) 复杂度（大多数时候只改长度标记，不用搬数据）；**付出**的是内存占用略大于实际需要（有预留的空槽），而且容量信息对外不可见。

> 💡 这个「用空间换时间」的思路在计算机科学里极其常见。理解它，你就不需要死记「append 是 O(1)」——你能自己推出来。

---

**⚠️ 头号陷阱：`[x] * n` 是「重复引用」而不是「复制内容」**

```python
# ❌ 危险写法：[0] 只创建了【一个】列表对象，* 3 只是复制了它的引用 3 份
a = [[0]] * 3
a[0].append(9)
print(a)                       # [[0, 9], [0, 9], [0, 9]]   ⚠️ 三格全变了！
print(a[0] is a[1] is a[2])    # True   ← 三个格子是同一个对象

# ✅ 正确写法：推导式，每轮都创建一个新对象
b = [[0] for _ in range(3)]
b[0].append(9)
print(b)                       # [[0, 9], [0], [0]]   ✅ 互不影响
```

⚠️ 同样的道理适用于 `["ab"] * 3`：三个元素是同一个字符串对象的引用。字符串不可变，所以这样写**恰好没问题**；但换成可变对象（列表、字典、集合）就是实打实的 bug。

**判断口诀**：`[x] * n` 复制的是**引用**，推导式创建的是**新对象**。凡是需要「每份各自独立」，就用推导式。

### 2.2 索引与负索引

**一句话定义**：列表元素按位置编号，**从 0 开始**；负数表示从末尾往回数。

```python
fruits = ["苹果", "香蕉", "橙子", "葡萄", "西瓜"]

fruits[0]                     # '苹果'    正索引：从左往右，0 到 4
fruits[-1]                    # '西瓜'    负索引：-1 是最后一个（取末尾的标准写法）
fruits[-5]                    # '苹果'    -len 刚好回到 0

# 越界抛 IndexError（取值和赋值都报），且列表不会自动扩容
fruits[5]                     # IndexError: list index out of range
fruits[9] = "荔枝"             # IndexError: list assignment index out of range
```

**为什么「越界就报错」是好设计**：如果返回 `None`，你会在后续几行才收到一个莫名其妙的 `AttributeError`，错误信息指向错误的行。**立即失败（fail fast）**能让你第一时间定位到真正的问题。

### 2.3 增：append / extend / insert

```python
nums = [1, 2, 3]
nums.append(4)                # 追加【一个】元素 → [1, 2, 3, 4]
nums.extend([5, 6])           # 逐个追加【多个】元素 → [1, 2, 3, 4, 5, 6]
nums.insert(1, 99)            # 在下标 1 处插入 99 → [1, 99, 2, 3, 4, 5, 6]

# ⚠️ 最经典的坑：append 一个列表不会展开
trap = [1, 2]
trap.append([3, 4])
print(trap)                   # [1, 2, [3, 4]]   ⚠️ 元素个数是 3，不是 4
print(type(trap[2]).__name__) # 'list'   ← 确认第 3 个元素本身是个列表

trap = [1, 2]
trap.extend([3, 4])
print(trap)                   # [1, 2, 3, 4]   ← 这才是想要的效果
```

**记忆方法**：`append` 是「追加**一个**元素」，你给它什么它就放什么；`extend` 是「展开**多个**元素」。

| 方法 | 语义 | 复杂度 |
| --- | --- | --- |
| `append(x)` | 末尾追加 1 个元素 x | 平均 O(1) |
| `extend(it)` | 末尾追加可迭代对象的**所有**元素 | O(k)，k 是元素个数 |
| `insert(i, x)` | 在下标 i 处插入 x | O(n)（要搬后面所有元素） |

⚠️ `insert` 的位置超出范围**不报错**，直接把元素放到末尾：`[1, 4].insert(100, 99)` → `[1, 4, 99]`。

**为什么 `insert` 是 O(n)**：列表的物理结构是「连续内存」，在中间插一个元素意味着**后面所有元素都要往后挪一位**。这和数组在中间插入的代价是一样的。

### 2.4 删：remove vs pop vs del vs clear

这是最容易混淆的一组，因为它们的**匹配对象**和**返回值**都不同：

| 写法 | 按什么删 | 返回值 | 找不到时 |
| --- | --- | --- | --- |
| `lst.remove(x)` | **值** x（第一次出现） | `None` | `ValueError` |
| `lst.pop()` | 删最后一个 | **被删的元素** | `IndexError`（空列表时） |
| `lst.pop(i)` | **下标** i | **被删的元素** | `IndexError` |
| `del lst[i]` | **下标** i | `None` | `IndexError` |
| `lst.clear()` | 删全部 | `None` | 空列表也不报错 |

```python
data = ["a", "b", "c", "b", "d"]
data.copy().remove("b")      # 按【值】删 → ['a', 'c', 'b', 'd']   注意第二个 'b' 还在
data.copy().pop(1)           # 按【下标】删并【返回】它 → 'b'
del data.copy()[1]           # 按【下标】删但【无返回值】
```

⚠️ **删不存在的东西会报错**：`data.remove("不存在")` 抛 `ValueError: list.remove(x): x not in list`，`data.pop(99)` 抛 `IndexError: pop index out of range`。

**⚠️ `remove` 只删第一个——想删全部必须循环或用推导式**

```python
# ⚠️ 循环 remove 能删光，但效率低（每轮都要从头扫描找元素）
all_b = ["b"] * 5
while "b" in all_b:
    all_b.remove("b")
print(all_b)                  # []

# ✅ 推导式更清晰，且只遍历一次
print([x for x in ["a", "b", "c", "b", "d"] if x != "b"])   # ['a', 'c', 'd']
```

### 2.5 改与只读方法

```python
nums = [3, 7, 1, 7, 4, 7]

nums.index(7)                 # 1   第一次出现的位置（找不到抛 ValueError）
nums.count(7)                 # 3   一共出现几次
7 in nums                     # True   只关心「有没有」，是布尔值
```

⚠️ **`index` 和 `in` 的区别要分清**：`index` 回答「**在哪**」（要一个下标），`in` 回答「**有没有**」（要一个布尔）。找不到时前者报错、后者返回 `False`。

**⚠️ `reversed` 返回的是「迭代器」而不是新列表**：`type(reversed(nums)).__name__` 是 `'list_reverseiterator'`，而且 `list(rev)` 第一次得到 `[7, 4, 7, 1, 7, 3]`，第二次得到 `[]`——**迭代器只能消费一次**。需要「反向的新列表」时用 `nums[::-1]`。

**需要「反向的新列表」时，用切片更直观**：`nums[::-1]` 返回真正的列表，可重复遍历。

**`sorted` 与 `sort` 的区别（L07 已讲，这里再强调一次）**：

```python
original = [5, 2, 8, 1]
print(sorted(original, reverse=True))   # [8, 5, 2, 1]，original 仍是 [5, 2, 8, 1]  ✅

inplace = [5, 2, 8, 1]
result = inplace.sort(reverse=True)
print(result)                  # None   ⚠️ 返回 None，这是最常见的错误来源
print(inplace)                 # [8, 5, 2, 1]
```

### 2.6 切片：Python 最优雅的语法之一

**一句话定义**：`lst[start:stop:step]` 返回一个**新列表**，取出 `start`（含）到 `stop`（不含）之间、按 `step` 步进的元素。

```python
data = list(range(10))

data[2:5]                     # [2, 3, 4]         stop 不含
data[:5]                      # [0, 1, 2, 3, 4]   start 省略 = 从头
data[5:]                      # [5, 6, 7, 8, 9]   stop 省略 = 到尾
data[:]                       # 完整复制（新对象）
data[-3:]                     # [7, 8, 9]         负索引
data[::2]                     # [0, 2, 4, 6, 8]   每隔一个
data[1:8:3]                   # [1, 4, 7]         区间内每 3 个取 1 个
data[::-1]                    # 反转，不改原列表
```

**三个必须记住的规则**：① **`stop` 不含**——`data[2:5]` 是下标 2、3、4 共 3 个元素，和 `range(2, 5)` 一致；② **切片超界不报错，会自动截断**，这和单点索引不同；③ **切片是「浅拷贝」**——改副本的**元素**不影响原列表，但改副本的**内层列表**会。

```python
data[0:100]                   # [0,1,...,9]   ✅ 和 data 一模一样（切片超界自动截断）
data[100:200]                 # []            ✅ 空列表
data[5]                       # IndexError    ❌ 但单点索引越界会报错

shallow = data[:3]
shallow[0] = 999
print(data[0])                # 0   ← 外层是独立副本

nested = [1, [2, 3]]
copy_n = nested[:]
copy_n[1].append(4)
print(nested)                 # [1, [2, 3, 4]]   ⚠️ 内层列表是共享的！（下一节详讲）
```

**⭐⭐ 切片赋值：用切片做增、删、改**

这是切片最强大也最少被用到的能力——**赋值长度可以和被替换的区间不同**。

```python
# 改：替换一段，长度可以不同
board = [0] * 5
board[1:4] = [7, 8]           # → [0, 7, 8, 0]  用 2 个替换 3 个，长度从 5 变成 4

# 删：替换成空列表
board = [0] * 5
board[1:4] = []               # → [0, 0]  等价于 del board[1:4]

# 增：起点 == 终点 = 插入
board = [0] * 5
board[2:2] = [1, 1, 1]        # → [0, 0, 1, 1, 1, 0, 0, 0]  等价于 insert

# 实战：批量重置某段数据
scores = [90, 85, 0, 0, 0, 78, 92]
scores[2:5] = [-1] * 3        # 把中间的缺失值统一标记为 -1
print(scores)                 # [90, 85, -1, -1, -1, 78, 92]
```

> 💡 **记忆口诀**：`start == stop` 是「插入」，`[]` 是「删除」，其他是「替换」。

### 2.7 浅拷贝 vs 深拷贝（最容易出事故的一节）

Python 变量**不存值，只存指向对象的指针**（`a = 5; b = a` 是两个变量指向同一个整数对象）。所谓「拷贝」，拷的是指针还是对象，就是浅拷贝和深拷贝的分界。

**四种「拷贝」写法的关系**：

```python
import copy

original = [1, [2, 3], [4, 5]]

slice_copy = original[:]                 # 浅拷贝
method_copy = original.copy()            # 浅拷贝（等价于 original[:]）
list_copy = list(original)               # 浅拷贝（⚠️ list() 不是深拷贝！）
shallow = copy.copy(original)            # 浅拷贝（对任意对象都适用）
deep = copy.deepcopy(original)           # ✅ 深拷贝
alias = original                          # ⚠️ 直接赋值不是拷贝，是同一个对象
```

**⭐ 浅拷贝到底拷了什么（用 `is` 一测就知道）**：

```python
original = [1, [2, 3], [4, 5]]
shallow = original[:]

print(shallow == original)               # True    内容相同
print(shallow is original)               # False   外层是不同对象 ← 这就是「拷贝」
print(shallow[1] is original[1])         # True    ⚠️ 内层是同一个对象！被共享了

# 事故现场：通过副本修改「内层」列表
shallow[1].append(99)
print(original)                          # [1, [2, 3, 99], [4, 5]]   ⚠️ 原列表被改了！

# 深拷贝则递归到底，改内层也不影响原对象
fresh = [1, [2, 3], [4, 5]]
copy.deepcopy(fresh)[1].append(99)       # fresh 仍然是 [1, [2, 3], [4, 5]]   ✅
```

**为什么会这样**：浅拷贝只新建了**最外层那个列表**，并把外层的 3 个元素的指针复制过去。内层那两个列表是同一个对象，改它就是改「大家共用的那一个」。

**性能代价实测**：

```python
import copy
import time

big = [[i] * 1000 for i in range(200)]   # 200 × 1000 个元素

t0 = time.perf_counter()
_ = copy.copy(big)
t1 = time.perf_counter()
_ = copy.deepcopy(big)
t2 = time.perf_counter()
print(f"copy.copy: {(t1 - t0) * 1000:.2f} ms, copy.deepcopy: {(t2 - t1) * 1000:.2f} ms")
```

实测 `copy.copy` 约 0.00 ms，`copy.deepcopy` 约 32 ms。原因是深拷贝要**递归复制 20 万个对象**，而浅拷贝只复制 200 个指针。

**⭐ 选择决策表**：元素全是**不可变**对象（数字/字符串/纯不可变元组，如 `[1, 2, 3]`）→ 浅拷贝足够；元素含**可变**对象且需要独立修改（如 `[[1], [2]]`、`[{"k": 1}]`）→ `deepcopy`；只是想「不改动原列表的**结构**」（排序、去重，如 `sorted(x)`）→ 浅拷贝；**不确定就 `deepcopy`**——宁可慢，不要错。

**⚠️ 三条常见误解澄清**：① **`list(original)` 不是深拷贝**——`list([1,[2]])` 的内层仍是共享的，它和 `original[:]` 完全等价；② **循环里不要用 `lst += [...]`**——它会原地扩展列表，迭代器会不断遇到「新元素」而可能死循环，请用 `for x in lst[:]`；③ **`deepcopy` 不处理「不可拷贝」的对象**——打开的文件对象、数据库连接会抛 `TypeError: cannot pickle`。

### 2.8 列表当栈与当队列

**栈（Stack）——后进先出（LIFO）**：用列表末尾操作，**全是 O(1)**。`append` + `pop` 的组合**天然就是栈**，不需要任何额外东西：

```python
stack = []
stack.append("a")              # push
stack.append("c")
stack.pop()                    # 'c'   ← 最后进的先出来
```

**队列（Queue）——先进先出（FIFO）**：问题来了。`q.append(4)` 入队没问题，但 `q.pop(0)` 出队是 **O(n)**——删除第一个元素后，后面所有元素都要**往前挪一位**。10 万个元素的列表，每次 `pop(0)` 都要搬 10 万个指针。`insert(0, x)`（头部插入）同理。

**实测对比**：

```python
from collections import deque
import time

lst = list(range(100_000))
dq = deque(range(100_000))

t0 = time.perf_counter()
for _ in range(10_000):
    if lst:
        lst.pop(0)             # O(n)
t1 = time.perf_counter()
for _ in range(10_000):
    if dq:
        dq.popleft()           # O(1)
t2 = time.perf_counter()

print(f"list.pop(0): {(t1 - t0) * 1000:.1f} ms, deque.popleft(): {(t2 - t1) * 1000:.1f} ms")
```

实测结果约为 `1827 ms` vs `0.3 ms`——**相差约 6000 倍**。

**为什么 `deque` 能做到 O(1)**：它的内部是**双向链表**，两端都维护着指针。删头部只需改一个指针，**不需要移动任何数据**。

> 💡 **结论**：栈用列表（`append`/`pop` 都是 O(1)），队列用 `deque`。这是 L28 标准库专题会再次展开的内容，但你现在就该记住这个结论——它能让你避免一个严重卡顿的性能问题。

### 2.9 常见坑

**⚠️ 坑 1：所有「原地修改」的方法都返回 `None`**

`result = bad.append(3)` 后 `result` 是 `None`，而 `bad` 确实变成了 `[1, 2, 3]`——**修改成功了，只是没有返回值**。受影响的完整清单：`append`、`extend`、`insert`、`remove`、`clear`、`sort`、`reverse`、`lst[i] = x`、`del lst[i]`。

---

**⚠️⚠️ 坑 2：循环中删除元素（最隐蔽的坑）**

**机制**：`for` 循环靠内部下标前进；而 `remove` 让后面的元素**整体左移一位**。于是紧跟在被删元素后面的那个元素，会被循环**跳过**。

```python
buggy = [5, 1, 2, 3, 4, 6]
for num in buggy:
    if num < 5:
        buggy.remove(num)
print(buggy)                   # [5, 2, 4, 6]   ⚠️ 2 和 4 被漏掉了！正确应是 [5, 6]
```

**逐步追踪**（务必理解这个过程）：第 1 轮读到 5，不满足；第 2 轮读到 1 并删掉它，列表变成 `[5,2,3,4,6]`——**2 从下标 2 挪到了 1**；第 3 轮循环前进到下标 2，读到的是 **3** 而不是 2，于是**2 被跳过**；删掉 3 后列表变成 `[5,2,4,6]`；第 4 轮读到 6，不满足——**4 也被跳过了**。

**⚠️⚠️ 最危险的地方：这个 bug「时灵时不灵」**。对 `[1, 2, 3, 4, 5, 6, 7, 8]` 用**同样的错误写法**删偶数，结果居然是 `[1, 3, 5, 7]`——**恰好正确**。

**为什么这比稳定出错更糟糕**：测试时数据「碰巧」通过，上线后遇到另一批数据就悄悄出错。**测试通过 ≠ 逻辑正确**——这是工程上最需要警惕的直觉陷阱。

**✅ 三种正确写法**：

```python
data = [5, 1, 2, 3, 4, 6]

# 写法 1：遍历切片副本（最贴近原意图）
fixed1 = data.copy()
for num in fixed1[:]:           # ⚠️ 关键在 [:]，遍历的是副本
    if num < 5:
        fixed1.remove(num)      # 删的仍然是原列表
print(fixed1)                   # [5, 6]

# 写法 2：推导式重建（推荐：只遍历一次，最清晰）
print([n for n in data if n >= 5])          # [5, 6]

# 写法 3：倒着遍历（从后往前删，不影响未处理的下标）
fixed3 = data.copy()
for i in range(len(fixed3) - 1, -1, -1):
    if fixed3[i] < 5:
        del fixed3[i]
print(fixed3)                   # [5, 6]
```

---

**⚠️ 坑 3：`remove` 与 `del` 语义完全不同**

`items = [1, 2, 3, 2, 4]`：`items.remove(2)` 按**值**删 → `[1, 3, 2, 4]`（只删第一个 2）；而 `del del_me[1]` 按**下标**删 → `[1, 3, 2, 4]`（下标 1 恰好也是 2，纯属巧合）。

**判断标准**：你手上拿到的是**值**就用 `remove`，拿到的是**位置**就用 `del`/`pop`。

### 2.10 实战：用列表做一个待办任务栈

```python
# 用列表实现一个待办栈：压栈用 append（O(1)），出栈用 pop（O(1)）
tasks: list[str] = []
finished: list[str] = []


def push(task: str) -> None:
    """压入任务。"""
    tasks.append(task)
    print(f"  📥 加入「{task}」，待办 {len(tasks)} 件")


def pop() -> str | None:
    """取出一个任务，返回 None 表示待办已空。"""
    if not tasks:                       # 先判断，避免 pop 空列表报 IndexError
        return None
    task = tasks.pop()                  # 后进先出：最后压入的先取出
    finished.append(task)
    return task


push("写周报")
push("改 bug")
push("写测试")
while pop() is not None:               # 一直做到空
    pass
print(f"完成列表: {finished}")         # ['写测试', '改 bug', '写周报']
print("出栈顺序与压栈顺序相反   ← 后进先出，这就是栈")
```

## ⚠️ 四、常见错误清单

| 错误现象 | 原因 | 正确写法 |
| --- | --- | --- |
| `a = [[0]] * 3` 后改一格，三格全变 | `*` 复制的是引用 | `[[0] for _ in range(3)]` |
| `lst.append([3, 4])` 元素个数不对 | `append` 只加一个元素 | 用 `extend([3, 4])` |
| `result = lst.append(x)` 得到 `None` | 原地方法不返回值 | 分两行写 |
| `[3, 1, 2].sort()` 拿返回值遍历报错 | `sort` 返回 `None` | `sorted([3, 1, 2])` |
| `remove` 只删掉了一个重复值 | `remove` 只删第一次出现 | 循环删或用推导式过滤 |
| `remove("不存在")` 抛 `ValueError` | 找不到会报错 | 先 `if x in lst:` 或用推导式 |
| `lst.remove(x)` 和 `del lst[i]` 行为不同 | 前者按值、后者按下标 | 明确你要删的是值还是位置 |
| `pop(0)` 在大数据上极慢 | O(n)，每次都要搬所有元素 | `collections.deque.popleft()` |
| 循环里 `remove` 导致元素被漏掉 | 删除让后面元素左移，循环继续前进 | 遍历副本 `lst[:]` 或用推导式 |
| 循环里 `remove` 在某些数据上「看起来对」 | bug 时灵时不灵 | **永远不要依赖这种巧合** |
| 循环里 `del lst[i]` 抛 `IndexError` | 长度在变，`range(len())` 的上界失效 | 遍历副本或倒着遍历 |
| 切片副本改了内层，原数据也变 | 切片是浅拷贝 | `copy.deepcopy(x)` |
| `list([[1],[2]])` 认为是深拷贝 | `list()` 只复制一层 | `copy.deepcopy(...)` |
| `list(集合)` 后顺序不对 | 集合无序 | 用列表，或「seen 集合 + unique 列表」 |
| `x[-1]` 拿到的是第二个元素 | 负索引从 -1 开始 | `x[-1]` 是最后一个 |
| 切片 `[0:100]` 越界不报错但单点 `[100]` 报错 | 切片和索引的规则不同 | 两者行为不一致，注意区分 |
| 把 `reversed(x)` 当列表用 | 它是迭代器，只能消费一次 | `list(reversed(x))` 或 `x[::-1]` |
| `lst.insert(100, x)` 没报错 | 位置超范围直接追加 | 检查下标范围 |
| 循环中 `lst += [...]` 导致死循环 | `+=` 原地扩展列表，迭代器会一直有新元素 | 用 `for x in lst[:]` 或先拷贝 |

## 📝 六、本课小结

- **列表的本质是「动态数组」**：连续内存 + 长度 + 容量。这解释了为什么下标访问是 O(1)（直接算偏移），也解释了为什么 `append` 是平均 O(1）——因为 CPython 预留了约 12.5% 的超额空间，攒够一截才跳级扩容。
- **`[x] * n` 复制的是引用，不是内容**。需要「n 份各自独立」必须用推导式 `[x for _ in range(n)]`。这是初学者第一个真正的「引用」坑。
- **`append` 加一个元素，`extend` 展开多个元素**。`append([3,4])` 会得到长度 3 的列表而不是 4，因为 `append` 拿到什么就放什么。
- **删除方法的匹配对象各不相同**：`remove` 按**值**（且只删第一个、找不到报 `ValueError`）、`pop` 按**位置**（且**返回**被删元素）、`del` 按**位置**（不返回）、`clear` 清空。
- **所有原地修改方法都返回 `None`**。这是「赋值给变量再使用」这类 bug 的唯一来源。
- **切片语法 `lst[start:stop:step]` 的 `stop` 不含**，且**切片超界自动截断而单点索引超界报错**——两者规则不一致，必须分别记忆。
- **切片赋值是最强的「批量操作」手段**：起点等于终点是插入、空列表是删除、其他是替换，而且**赋值长度可以和被替换区间不同**。
- **浅拷贝只复制最外层容器，内层对象被共享**。用 `is` 一测就知道：`slice_copy is original` 为 `False` 但 `slice_copy[1] is original[1]` 为 `True`。含可变对象且要独立修改时必须用 `deepcopy`，代价是递归复制带来的时间开销（实测 200×1000 元素约 32 ms）。
- **栈用列表（`append`/`pop` 都是 O(1)），队列用 `collections.deque`**。实测 10 万元素出队 1 万次，`list.pop(0)` 约 1827 ms，`deque.popleft()` 约 0.3 ms——相差约 6000 倍。
- **循环中删除元素会让部分元素被漏掉**，因为删除使后续元素左移而循环继续前进。正确写法是遍历副本 `lst[:]` 或用推导式重建。**这个 bug 时灵时不灵**（`[1..8]` 删偶数恰好正确），所以它比稳定出错更危险。
- **`sorted` 返回新列表、`list.sort()` 原地改并返回 `None`**；`lst[::-1]` 返回新列表、`reversed(lst)` 返回只能消费一次的迭代器。成对记忆才不会混。

> **一句话总结**：列表的一切设计都源于「**动态数组**」这一个物理结构——它带来了 O(1) 的下标访问和平均 O(1) 的尾部增删，代价是中间插删是 O(n)、拷贝是浅的。本课真正要掌握的**不是方法清单**，而是**「看到一个操作，先问它在这块连续内存上要搬多少东西」**这个思维习惯。

**关键点 1：为什么 `CowList` 能省下大量深拷贝**

思路：把「拷贝」推迟到「第一次写入」这一刻。未写入前所有持有者共享同一份数据——数据传给 10 个模块而没人改它，深拷贝 0 次就够；一旦有人要改，才为**那个调用者**单独复制。

```python
import copy


class CowList:
    """写时复制的列表包装器：把 deepcopy 从「构造时」推迟到「第一次写入时」。"""

    def __init__(self, data: list, name: str = "cow") -> None:
        self._name = name
        self._data = data                 # 未修改时所有 CowList 共享这一份
        self._copied = False              # 是否已经为「我」复制过
        self.copy_count = 0               # 统计实际发生了几次深拷贝

    def read(self) -> list:
        """只读访问，永远不触发拷贝。"""
        return self._data

    def ensure_writable(self) -> None:
        """第一次写入前调用：还没复制就复制一份。"""
        if not self._copied:
            self._data = copy.deepcopy(self._data)
            self._copied = True
            self.copy_count += 1

    def write(self, index: int, value: object) -> None:
        """写入前先确保自己拥有独立副本。"""
        self.ensure_writable()
        self._data[index] = value


# 演示：把同一份数据发给 8 个「模块」
shared = [list(range(100)) for _ in range(20)]
modules = [CowList(shared, f"module{i}") for i in range(8)]
modules[7].write(0, [999])                  # 只有第 8 个模块触发了深拷贝

for m in modules:
    print(f"{m._name}: {'已独立' if m._copied else '共享中'}，累计深拷贝 {m.copy_count} 次")
total = sum(m.copy_count for m in modules)
print(f"朴素 deepcopy 需要 {len(modules)} 次，写时复制实际只用 {total} 次")
```

**关键点 2：`RowBuffer` 用扁平数组换内存**

思路：嵌套列表 200 行 = 200 个列表对象 + 200 个内部数组；扁平数组只有 1 个列表对象 + 1 个内部数组。而且 `get_row` 返回的是**切片**，外部拿到的是新对象——**根本不需要深拷贝**。

```python
class RowBuffer:
    """扁平化的二维缓冲区：用「一个列表」存所有值，行号换算成偏移量。"""

    def __init__(self, rows: list[list[int]]) -> None:
        self.cols = len(rows[0]) if rows else 0
        self.flat: list[int] = [v for row in rows for v in row]   # 关键：拼成【一个】列表
        self.row_len = self.cols

    def append_row(self, row: list[int]) -> None:
        """追加一行，长度必须与行宽一致。"""
        if len(row) != self.cols:
            raise ValueError(f"每行必须是 {self.cols} 个元素，收到 {len(row)} 个")
        self.flat.extend(row)

    def get_row(self, i: int) -> list[int]:
        """取第 i 行。返回的是【切片】，是新对象，改它不影响内部。"""
        start = i * self.row_len
        return self.flat[start:start + self.row_len]

    def set_value(self, i: int, j: int, v: int) -> None:
        """修改第 i 行第 j 列。偏移量 = i * 行宽 + j。"""
        self.flat[i * self.row_len + j] = v

    def column(self, j: int) -> list[int]:
        """取第 j 列：等差切片。"""
        return self.flat[j::self.row_len]
```

**关键点 3：`detect_shared` 与 `deep_merge`**

`detect_shared` 用递归 + `id()` 统计每个容器被引用几次，出现 >1 次的就是「共享点」（浅拷贝的隐患所在）。`deep_merge` 则利用这个结论做**结构共享**：对每个子字典先判断「`override` 有没有动它」，没动就直接复用（零拷贝），动了才递归新建——这与 immutable 持久化树（HAMT）同思路。

```python
def deep_merge(base: dict, override: dict) -> dict:
    """递归合并字典，复用【未被修改的子结构】。"""
    result = base.copy()                    # 先浅拷贝顶层（便宜）
    for key, new_value in override.items():
        if key not in base:
            result[key] = new_value         # 新增：直接放
        elif isinstance(base[key], dict) and isinstance(new_value, dict):
            result[key] = deep_merge(base[key], new_value)   # 只有这一支会新建
        else:
            result[key] = new_value         # 子结构被整体替换，无需深拷贝
    return result
```

    for expr, result in cases:

def demo_immutable_and_bounds() -> None:
    """验证切片不改变原列表，以及切片与索引的越界差异。"""
    data = list(range(10))
    snapshot = data[:]

    print(f"\n  原列表没变: {data == snapshot}   切片是新对象: {data[:] is not data}")

        _ = data[100]
    except IndexError as exc:
        print(f"  data[100] → IndexError: {exc}   ❌ 单点索引越界会报错")

    """切片赋值：改 / 删 / 增。"""
    board = [0] * 5
    board[1:4] = [7, 8]
    print(f"  改 board[1:4] = [7,8] → {board}")

    board[1:4] = []
    print(f"  删 board[1:4] = []     → {board}")

    board = [0] * 5
    board[2:2] = [1, 1, 1]
    print(f"  增 board[2:2] = [1,1,1] → {board}")


def rotate(lst: list, k: int) -> list:
    """用切片实现列表左旋 k 位（k 可以超过长度，也可以是负数）。"""
    n = len(lst)
    if n == 0:
        return lst[:]
    k %= n                                      # 关键：取模，兼容 k > n 和负数 k
    return lst[k:] + lst[:k]

"""基础题第 3 题：深浅拷贝与引用陷阱。"""

import copy
import time


def demo_five_copies() -> None:
    """五种拷贝方式，逐层用 id() 验证。"""
    original = [[[1, 2], [3]], [[4]]]
    makers = {
        "切片 original[:]": lambda x: x[:],
        ".copy()": lambda x: x.copy(),
        "list(x)": lambda x: list(x),
        "copy.copy()": lambda x: copy.copy(x),
        "copy.deepcopy()": lambda x: copy.deepcopy(x),
    }
    for name, make in makers.items():
        c = make(original)
        print(f"  {name:<20} 外层共享={c is original}  "
              f"第二层共享={c[0] is original[0]}  第三层共享={c[0][0] is original[0][0]}")
    print("  → 只有 deepcopy 三层全 False（全部新建）\n")


def demo_accident() -> None:
    """事故场景：浅拷贝改内层，原对象被连带修改。"""
    original = [[1], [2]]
    shallow = copy.copy(original)
    shallow[0].append(99)
    print(f"  ⚠️ 浅拷贝后 original = {original}   ← 被连带修改")

    fresh = [[1], [2]]
    copy.deepcopy(fresh)[0].append(99)
    print(f"  ✅ 深拷贝后 fresh     = {fresh}\n")


def demo_alias_and_list() -> None:
    """证明「赋值不是拷贝」，以及 list() 不是深拷贝。"""
    a = [[1], [2]]
    alias = a
    alias[0].append(9)
    print(f"  赋值不是拷贝：a[0] = {a[0]}   a is alias → {a is alias}")

    b = [[1], [2]]
    c = list(b)
    c[0].append(9)
    print(f"  list() 不是深拷贝：b[0] = {b[0]}   b[0] is c[0] → {b[0] is c[0]}\n")


def demo_perf() -> None:
    """实测浅拷贝与深拷贝的耗时差。"""
    big = [[i] * 1000 for i in range(200)]
    t0 = time.perf_counter()
    _ = copy.copy(big)
    t1 = time.perf_counter()
    _ = copy.deepcopy(big)
    t2 = time.perf_counter()
    print(f"  copy.copy     : {(t1 - t0) * 1000:.2f} ms")
    print(f"  copy.deepcopy : {(t2 - t1) * 1000:.2f} ms")


if __name__ == "__main__":
    demo_five_copies()
    demo_accident()
    demo_alias_and_list()
    demo_perf()
```

**什么时候该用 `deepcopy` 的 5 条规则**：① 元素含可变对象且要独立修改；② 缓存/模板数据怕被污染；③ 跨模块传递大对象且所有权不清；④ 写单元测试需要完全隔离的夹具；⑤ **不确定时直接用**——深拷贝的「错」只是慢，浅拷贝的「错」是数据被悄悄改掉。

"""基础题第 4 题：栈、队列与待办管理器。"""

import time
from collections import deque


class EmptyStackError(Exception):
    """空栈异常：比 IndexError 更能表达意图。"""


class TaskStack:
    """基于列表的栈。"""

    def __init__(self) -> None:
        self._items: list[str] = []

    def push(self, item: str) -> None:
        self._items.append(item)

    def pop(self) -> str:
        if not self._items:
            raise EmptyStackError("栈是空的，无法弹出")
        return self._items.pop()

    def peek(self) -> str:
        if not self._items:
            raise EmptyStackError("栈是空的，无法查看栈顶")
        return self._items[-1]

    def is_empty(self) -> bool:
        return not self._items

    def size(self) -> int:
        return len(self._items)

    def clear(self) -> None:
        self._items.clear()


class TaskManager:
    """按优先级出任务的待办管理器（数字越小优先级越高）。"""

    def __init__(self) -> None:
        self._tasks: list[tuple[int, str]] = []

    def add(self, task: str, priority: int = 5) -> None:
        self._tasks.append((priority, task))

    def complete_next(self) -> str | None:
        """取出优先级最高（数字最小）的任务。"""
        if not self._tasks:
            return None
        # 用 min 按 (优先级, 名称) 排序，取第一个；index 找下标避免直接 pop
        best = min(range(len(self._tasks)), key=lambda i: self._tasks[i])
        return self._tasks.pop(best)[1]

    def complete_all(self) -> list[str]:
        done = []
        while (task := self.complete_next()) is not None:
            done.append(task)
        return done


def demo_queue_perf() -> None:
    """实测 list.pop(0) 与 deque.popleft() 的出队耗时差。"""
    lst = list(range(100_000))
    dq = deque(range(100_000))
    t0 = time.perf_counter()
    for _ in range(10_000):
        if lst:
            lst.pop(0)
    t1 = time.perf_counter()
    for _ in range(10_000):
        if dq:
            dq.popleft()
    t2 = time.perf_counter()
    print(f"  list.pop(0)     : {(t1 - t0) * 1000:.1f} ms")
    print(f"  deque.popleft() : {(t2 - t1) * 1000:.1f} ms")


def demo_delete_pitfalls() -> None:
    """三个循环删除的失败案例（含「看似正确」的那个）。"""
    print("\n  案例1 [5,1,2,3,4,6] 删 <5：")
    a = [5, 1, 2, 3, 4, 6]
    for n in a:
        if n < 5:
            a.remove(n)
    print(f"    ❌ 结果 {a}   ← 2 和 4 被漏掉，正确应是 [5, 6]")

    print("  案例2 [1,2,3,4,5] 全删：")
    b = [1, 2, 3, 4, 5]
    for n in b:
        b.remove(n)
    print(f"    ❌ 结果 {b}   ← 只删了一半")

    print("  案例3 [1..8] 删偶数（看似正确！）：")
    c = [1, 2, 3, 4, 5, 6, 7, 8]
    for n in c:
        if n % 2 == 0:
            c.remove(n)
    print(f"    ⚠️ 结果 {c}   ← 恰好正确，但这只是巧合，不能依赖")

    print("\n  ✅ 两种正确写法：")
    d = [5, 1, 2, 3, 4, 6]
    for n in d[:]:                              # 遍历副本
        if n < 5:
            d.remove(n)
    print(f"    遍历副本 d[:] → {d}")
    print(f"    推导式重建    → {[n for n in [5, 1, 2, 3, 4, 6] if n >= 5]}")


if __name__ == "__main__":
    st = TaskStack()
    for t in ["写周报", "改 bug", "写测试"]:
        st.push(t)
    print(f"  栈大小 {st.size()}，栈顶 {st.peek()}")
    while not st.is_empty():
        print(f"  出栈 {st.pop()}")
    try:
        st.pop()
    except EmptyStackError as exc:
        print(f"  空栈 pop → {type(exc).__name__}: {exc}")

    tm = TaskManager()
    tm.add("写周报", 2)
    tm.add("改 bug", 1)
    tm.add("写测试", 3)
    print(f"\n  按优先级完成: {tm.complete_all()}")

    demo_queue_perf()
    demo_delete_pitfalls()
```

**关键点**：`complete_next` 用 `min(range(...), key=...)` 找出最优下标再 `pop`，**避免了「边遍历边删」**这个 bug；`while (task := ...)` 用了海象运算符（L05 讲过赋值表达式）。

```python
class MiniTable:
    """只用列表实现的数据表——用来体会「为什么真实项目要用字典/对象」。"""

    def __init__(self, fields: list[str]) -> None:
        if len(set(fields)) != len(fields):     # 字段名不能重复
            raise ValueError(f"字段名重复: {fields}")
        self.fields = list(fields)
        self.rows: list[list] = []
        self.index: dict[str, dict[object, list[int]]] = {}   # 字段 → 值 → 行号列表

    def build_index(self, field: str) -> None:
        """建立索引：把 O(n) 的扫描查询变成 O(1) 的哈希查询。"""
        if field not in self.fields:
            raise KeyError(f"字段不存在: {field}")
        index: dict[object, list[int]] = {}
        for i, row in enumerate(self.rows):
            value = row[self.fields.index(field)]
            index.setdefault(value, []).append(i)     # 同一个值可能有多个行号
        self.index[field] = index

    def insert(self, row: list) -> None:
        if len(row) != len(self.fields):
            raise ValueError(f"字段数不符: 期望 {len(self.fields)}，收到 {len(row)}")
        if "id" in self.fields:
            id_col = self.fields.index("id")
            key = row[id_col]
            if any(r[id_col] == key for r in self.rows):
                raise ValueError(f"重复的 id: {key}")
        self.rows.append(row)
```

**为什么第 5 题值得做**：有了 `build_index` 之后，「按字段查行号」从每次扫全表的 O(n) 变成 O(1)，但**每次 `insert` 之后索引就失效了**——这个维护成本正是「用字典/对象 + 真实数据库」要解决的问题。做完这题你就理解了为什么不该自己造轮子。

```python
def find_pair_sum_hash(nums: list[int], target: int) -> tuple[int, int] | None:
    """两数之和 O(n)：遍历时检查 need 是否已在 seen 里。"""
    seen: dict[int, int] = {}                    # 值 → 下标
    for idx, x in enumerate(nums):
        need = target - x
        if need in seen:                         # 哈希查询 O(1)，替代 O(n) 的 in 列表
            return x, need
        seen[x] = idx                             # ⚠️ 必须在 if 之后，否则会自己配自己
    return None


def remove_duplicates_inplace(nums: list[int]) -> int:
    """原地删除重复项：双指针 slow/fast，返回新长度。

    ⭐ 这是 Python 求「唯一数组」的标准写法：不新建列表，只在原列表上覆盖写。
    """
    if not nums:
        return 0
    slow = 0                                    # slow 指向「下一个写入位置」
    for fast in range(1, len(nums)):
        if nums[fast] != nums[slow]:            # 发现新值
            slow += 1
            nums[slow] = nums[fast]             # 写回，覆盖掉中间的垃圾
    return slow + 1                             # ⚠️ 返回长度，不是列表
```

**为什么双指针能降到 O(n)**：`fast` 每轮只前进一格（总共 n 格），`slow` 只在遇到新值时前进（最多 n 格），所以总操作数是 2n 而不是 n²/2——**每个元素只被访问常数次**。

> 💡 注意 `remove_duplicates_inplace` **返回长度而不是列表**，这是 LeetCode 等平台的惯用约定。调用方要写成 `k = remove_duplicates_inplace(nums)` 然后用 `nums[:k]` 取有效部分。
