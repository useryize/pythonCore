## 📖 二、知识讲解

### 2.1 集合的语义：它只干两件事

**一句话定义**：集合（`set`）是**无序的、元素唯一、可哈希**的容器。它专精两件事：

1. **自动去重**——放进来的重复元素只留一个；
2. **O(1) 成员判断**——`x in s` 是常数时间，而列表是 O(n)。

```python
dup = [1, 2, 2, 3, 3, 3, 4]
print(sorted(set(dup)))
# 期望输出: [1, 2, 3, 4]
```

**元素唯一意味着什么**：

```python
s = {1, 2, 3}
s.add(2)                          # 加一个已存在的元素
print(sorted(s))
# 期望输出: [1, 2, 3]
```

⚠️ `add` 已存在的元素**不报错也不重复添加**——这是集合的语义决定的，不是 bug。

---

### 2.2 ⭐ 为什么集合「必须无序」

这个知识点很多教程没讲清楚，导致初学者产生「集合应该是排好序的」的误解。

**根本原因**：集合的底层实现是**哈希表**（L10 讲过）。

```text
存入 {3, 1, 2}：
  hash(3)=3 → 放进槽位 3
  hash(1)=1 → 放进槽位 1
  hash(2)=2 → 放进槽位 2
遍历集合 = 从槽位 0 开始挨个扫
所以先扫到槽位 1 → 再扫到槽位 2 → 最后扫到槽位 3
看起来就是 1, 2, 3
```

**所以「有序」只是巧合**——因为小整数的哈希值恰好等于它自己。

⚠️ **只要范围一变，有序性立刻消失**：

```python
big = {50, 10, 30, 20, 40}
print(list(big) == sorted(big))    # 恒为 False —— 证明「有序」只是巧合
# 期望输出: False
```

⚠️ 在你的机器上它可能正好有序，也可能不是——**不要依赖它**。

---

### 2.3 ⚠️⚠️ 输出顺序的真相（小整数的假象 vs 字符串的真相）

这是本课**最容易搞错**的地方，也是你特别要求讲清楚的部分。

**情况一：小整数看起来总是有序的**

```python
s = {3, 1, 2}
print(s)                          # {1, 2, 3}
print(hash(1) == 1, hash(2) == 2) # True True   ← 哈希值 == 值本身
```

因为 `hash(整数) == 整数本身`（这是 Python 哈希的设计），所以小整数的**槽位下标恰好等于值**，遍历顺序就成了升序。

⚠️ **但这不是承诺**：

```python
big = {50, 10, 30, 20, 40}
print(sorted(big) == list(big))     # 恒为 False：打印顺序不是升序
# 期望输出: False
print(list(big) == list(range(50, 41, -1)))    # 也不是倒序
# 期望输出: False
```

**情况二：字符串的顺序每次运行都不同**

实测把 `print(list({'abc', 'xyz', 'hello', 'world'}))` 连续跑两次，会得到**不同的顺序**：

```text
第 1 次: ['world', 'hello', 'abc', 'xyz']
第 2 次: ['xyz', 'hello', 'abc', 'world']
```

**原因**：Python 默认开启 **哈希随机化**（`PYTHONHASHSEED`）。这是为了防止有人故意构造能拖慢程序的字符串键（哈希碰撞攻击）。随机化让**每次进程启动的哈希值都不同**，所以集合顺序也不同。

> ⚠️ **这是规范行为，不是 bug**。它是 Python 的一个安全设计。

**正确做法：需要有序输出就用 `sorted()`**：

```python
s = {"b", "a", "c"}
print(sorted(s))                   # ['a', 'b', 'c']   永远一致
```

> 💡 **一句话记住**：集合的顺序是**实现细节**，不是 API 的一部分。任何「按集合的顺序遍历」的需求，都应该改成 `sorted(s)`。

### 2.4 创建方式与空集合的坑

**三种创建方式**：

```python
a = {1, 2, 3}                      # 1. 字面量
b = set([1, 2, 3])                  # 2. set(可迭代对象)
c = {x for x in (1, 2, 3)}          # 3. 集合推导式
print(a == b == c)
# 期望输出: True
```

⚠️ **注意推导式会「重新计算」**：

```python
print(sorted({x * 2 for x in (1, 2, 3)}))    # [2, 4, 6]
```

**⚠️⚠️ 头号陷阱：空集合不能用 `{}`**

```python
print(type({}).__name__, type(set()).__name__)
# 期望输出: dict set
```

**为什么这样设计**：`{}` 在 Python 语法里必须表示「空映射」。试想如果 `{}` 表示空集合，那么 `{}['a'] = 1`（字典赋值）就没法解析了——Python 无法在**看到 `{}` 时就决定它是哪种类型**（Python 是动态类型）。

所以 Python 选择了：空集合只能用 `set()`。

⚠️ 这个坑的实际后果：

```python
try:
    _ = {} | {1}
except TypeError as exc:
    print(exc)
# 期望输出: unsupported operand type(s) for |: 'dict' and 'set'
```

⚠️ **`set(字典)` 取的是「键」**：

```python
print(sorted(set({"a": 1, "b": 2})))
# 期望输出: ['a', 'b']
```

这是因为**迭代字典默认就是遍历键**（L10 讲过）。想要键值对要写 `{frozenset(d.items())}` 之类。

### 2.5 增删查

```python
s = {1, 2, 3}
s.add(4)                           # 加一个
s.add(4)                           # 加已有的：静默无变化
s.update([5, 6])                   # 批量加
print(sorted(s))
# 期望输出: [1, 2, 3, 4, 5, 6]
```

**删除：`discard` 与 `remove` 的区别**：

```python
s = {1, 2, 3}
s.discard(99)                      # 删不存在的：静默，不报错
try:
    s.remove(99)                   # 删不存在的：报错
except KeyError as exc:
    print(exc)
# 期望输出: 99
```

⚠️ **选择标准**：

| 写法 | 不存在时 | 什么时候用 |
| --- | --- | --- |
| `discard(x)` | 静默跳过 | 「删掉它，不管在不在」（幂等操作） |
| `remove(x)` | 抛 `KeyError` | 「它必须存在，不存在就是 bug」 |

**⚠️ `pop()` 弹出的是「任意一个」**：

```python
s = {"a", "b", "c"}
x = s.pop()                        # 弹出哪个？不确定！
```

⚠️ 集合**没有**「弹出最小值」或「弹出第一个」的方法。如果需要确定性顺序，用 `min(s)` 或 `sorted(s)[0]`。

### 2.6 四个集合运算

**运算符写法和方法写法的对应关系**：

```python
a, b = {1, 2, 3}, {2, 3, 4}

print(sorted(a | b))               # 并集 [1, 2, 3, 4]
print(sorted(a & b))               # 交集 [2, 3]
print(sorted(a - b))               # 差集 [1]
print(sorted(a ^ b))               # 对称差 [1, 4]

print(sorted(a.union(b)))          # 方法写法，结果相同
print(sorted(a.intersection(b)))
print(sorted(a.difference(b)))
print(sorted(a.symmetric_difference(b)))
```

**数学含义**（记忆口诀：**一个是加，其余是减**）：

| 运算 | 符号 | 方法 | 含义 |
| --- | --- | --- | --- |
| 并集 | `\|` | `union` | 「或」：至少在一个里面 |
| 交集 | `&` | `intersection` | 「且」：两个都在 |
| 差集 | `-` | `difference` | 「只在 a」：a 有 b 没有 |
| 对称差 | `^` | `symmetric_difference` | 「异或」：只在其中一个（不都是） |

**⭐ 交集支持多参数**（很实用）：

```python
lists = [[1, 2, 3, 4], [2, 3, 4, 5], [3, 4, 5, 6]]
common = set(lists[0]).intersection(*lists[1:])
print(sorted(common))
# 期望输出: [3, 4]
```

这在「找出所有数据源都有的东西」的场景里特别好用。

**⚠️⚠️ 关键区别：运算符返回新集合，`update` 返回 `None`**

```python
x = {1, 2}
result = x | {3}                   # 运算符：返回【新集合】
print(sorted(result), sorted(x))  # [1, 2, 3] [1, 2]   x 未变 ✅

y = {1, 2}
none_result = y.update({3})       # 方法：返回 None，原地修改
print(none_result, sorted(y))     # None [1, 2, 3]
```

⚠️ 所以 `z = y.update(...)` 这种写法**一定错**：合并生效了，但 `z` 是 `None`。这是 L08/L10 反复强调的「原地方法返回 None」问题。

### 2.7 六个关系运算

**关系运算比较的是「集合之间的包含关系」**：

```python
small, big = {1, 2}, {1, 2, 3}

print(small <= big)                # True  子集（允许相等）
print(small < big)                 # True  真子集（不允许相等）
print(big >= small, big > small)   # True True   超集
print(small == {2, 1})             # True  ⚠️ 集合不关心顺序！
print(small.isdisjoint({9, 10}))   # True  没有交集
```

⚠️ **集合不关心顺序**：`{1, 2} == {2, 1}` 是 `True`，这和列表 `[1, 2] == [2, 1]`（`False`）完全不同。

| 符号 | 方法 | 含义 |
| --- | --- | --- |
| `==` `!=` | — | 元素集合是否相同 |
| `<=` | `issubset` | a 是 b 的子集（含相等） |
| `<` | — | a 是 b 的**真**子集 |
| `>=` | `issuperset` | a 是 b 的超集 |
| `>` | — | a 是 b 的**真**超集 |
| — | `isdisjoint` | a 和 b **没有**任何共同元素 |

**`isdisjoint` 的实用场景**：「验证两个集合完全不相交」——比 `not (a & b)` 更快，因为不需要构造结果集合。

### 2.8 `frozenset`：唯一可哈希的集合

**一句话定义**：`frozenset` 是**不可变**的集合，因此**可哈希**，能当字典键或集合元素。

```python
fs = frozenset([1, 2, 3])
print(type(fs).__name__)
# 期望输出: frozenset
```

**⭐ 核心价值：可哈希**

```python
print({frozenset([1, 2]): "v"})    # 可以当字典键 ✅
try:
    hash({1, 2})
except TypeError as exc:
    print(exc)
# 期望输出: unhashable type: 'set'
```

**⚠️ 但它没有修改方法**：

```python
fs = frozenset([1, 2, 3])
missing = [m for m in ("add", "update", "discard", "remove", "pop", "clear")
           if not hasattr(fs, m)]
print(missing)
# 期望输出: ['add', 'update', 'discard', 'remove', 'pop', 'clear']
```

**运算方法全部保留**：

```python
fs = frozenset([1, 2])
print(sorted(fs | frozenset([3])))   # [1, 2, 3]  返回【新的 frozenset】
```

**实战：需要「集合当字典键」时用 `frozenset`**

需求：统计每个「标签组合」出现几次，但标签组合本身不能变。

```python
tag_counts: dict[frozenset[str], int] = {}
for tags in [("python", "web"), ("web", "python"), ("data",), ("python", "web")]:
    key = frozenset(tags)            # 转成可哈希的
    tag_counts[key] = tag_counts.get(key, 0) + 1

print({"/".join(sorted(k)): v for k, v in tag_counts.items()})
# 期望输出: {'python/web': 3, 'data': 1}
```

⚠️ 注意 `("python", "web")` 和 `("web", "python")` 被正确识别为**同一个组合**——因为 `frozenset` 去重且不关心顺序。

> 💡 **选择标准**：需要修改用 `set`；需要当字典键/集合元素用 `frozenset`。不确定时用 `frozenset`（更安全）。

### 2.9 性能实测：list vs set

**成员判断**：

```python
import time

n = 200_000
lst = list(range(n))
st = set(range(n))
target = 999_999                    # 不存在（最坏情况）

t0 = time.perf_counter()
for _ in range(1000):
    _ = target in lst
t1 = time.perf_counter()
for _ in range(1000):
    _ = target in st
t2 = time.perf_counter()

print(f"列表: {(t1 - t0) * 1000:.2f} ms")
print(f"集合: {(t2 - t1) * 1000:.3f} ms")
print(f"倍数: {(t1 - t0) / max(t2 - t1, 1e-9):,.0f}×")
```

⚠️ 注意：具体毫秒数**每次运行都不同**，但「相差一万倍以上」这个量级是稳定的。实测约 **1000 ms vs 0.05 ms**——相差约 2 万倍。所以判断性能差异要看**倍数**，不要死记某个数字。

**⭐ 增长曲线（比「快 N 倍」更有说服力）**：

实测的增长倍数（**毫秒数因机器而异，但「倍数」这个规律稳定**）：

| 元素数翻倍 | 列表查找耗时倍数 | 集合查找耗时倍数 |
| --- | --- | --- |
| 50,000 → 100,000 | 约 2.0× | 约 1~2×（噪声） |
| 100,000 → 200,000 | 约 2.0× | 约 1.0× |
| 200,000 → 400,000 | 约 2.0× | 约 1~2×（噪声） |

列表**稳定翻倍**（O(n)），集合**在噪声范围内波动**（O(1)）。判定依据是看「倍数」而不是看绝对值。

**去重性能**：

```python
data = [i % 10_000 for i in range(200_000)]

# 朴素去重：列表查找 O(n) → 整体 O(n²)
manual: list[int] = []
for x in data:
    if x not in manual:
        manual.append(x)

# 高效去重
fast = set(data)
```

实测约 **11,000 ms vs 7 ms**——相差约 1500 倍（毫秒数因机器而异，量级稳定）。

> 💡 这就是「**把 O(n) 的查找换成 O(1) 查表**」这个优化思路的威力：外层循环跑了 n 次，每次的内部判断从 O(n) 降到 O(1)，整体就从 O(n²) 变成 O(n)。

### 2.10 去重实战：三种方式与保序性

```python
data = ["b", "a", "b", "c", "a", "d"]
```

| 方式 | 代码 | 保序？ |
| --- | --- | --- |
| 集合去重 | `set(data)` | ❌ 顺序丢失 |
| 集合 + 排序 | `sorted(set(data))` | ✅ 但变成升序 |
| seen + 列表 | 循环 + `seen` 集合 | ✅ **保留原顺序** |
| `dict.fromkeys` | `list(dict.fromkeys(data))` | ✅ **保留原顺序** |

**⭐ 保序去重的标准写法（L07 讲过，这里对比）**：

```python
# 方式一：seen 集合 + 结果列表
seen: set[str] = set()
unique: list[str] = []
for item in data:
    if item not in seen:            # 集合判断 O(1)，比列表快得多
        seen.add(item)
        unique.append(item)
print(unique)                        # ['b', 'a', 'c', 'd']

# 方式二：dict.fromkeys（3.7+ 最简洁）
print(list(dict.fromkeys(data)))     # ['b', 'a', 'c', 'd']
```

**方式二为什么能保序**：3.7+ 的 `dict` 保证插入顺序，而 `dict.fromkeys` 按**可迭代对象的顺序**插入键，所以去重的同时保留了原顺序。

⚠️ **细节：保留「第一次」还是「最后一次」出现**：

```python
pairs = [("a", 1), ("b", 2), ("a", 3)]
print(dict(pairs))                   # {'a': 3, 'b': 2}  ⚠️ 保留了【最后一次】的值
```

因为 `dict` 是「后来的键覆盖先前的值」。如果要保留**第一次**，需要用 `seen` 集合或反向遍历。

### 2.11 实战：用集合把 O(n²) 优化到 O(n)

**这是本课最有价值的部分**。

**问题：找出两个数组的交集**

```python
# ❌ 朴素：双重循环 O(n×m)
def intersect_naive(a: list[int], b: list[int]) -> list[int]:
    result = []
    for x in a:
        for y in b:
            if x == y:
                result.append(x)
    return result


# ✅ 优化：转成集合后用交集运算 O(n+m)
def intersect_fast(a: list[int], b: list[int]) -> list[int]:
    return sorted(set(a) & set(b))
```

**为什么优化有效**：朴素写法要做 n×m 次比较；优化后把其中一个转成集合，判断「是否在 b 中」从 O(m) 降到 O(1)，**外层循环跑 n 次就够**。

**更多同类优化**：

```python
# 判断是否所有元素都出现过（存在性检查）
def all_present(targets: list[int], available: list[int]) -> bool:
    """⚠️ 列表版 O(n×m)；把 available 转成集合后 O(n+m)。"""
    pool = set(available)             # 关键：建一次「查表结构」
    return all(t in pool for t in targets)


# 找重复出现的元素
def find_duplicates(items: list[int]) -> set[int]:
    seen: set[int] = set()
    dupes: set[int] = set()
    for x in items:
        if x in seen:                 # O(1) 判断，配合 seen 集合整体 O(n)
            dupes.add(x)
        seen.add(x)
    return dupes


# 找出列表中【唯一出现一次】的元素（O(n²) → O(n)）
def find_unique_once(items: list[int]) -> list[int]:
    counts: dict[int, int] = {}
    for x in items:
        counts[x] = counts.get(x, 0) + 1
    return [x for x, c in counts.items() if c == 1]
```

> 💡 **核心心法**：看到双重循环里有个「判断是否存在」，就问「**能不能用集合替掉一层循环**」。这个改写把 O(n·m) 变成 O(n+m)，是算法优化里最高性价比的一招。

## ⚠️ 四、常见错误清单

| 错误现象 | 原因 | 正确写法 |
| --- | --- | --- |
| `{}` 得到的是字典不是集合 | `{}` 语法上表示空映射 | `set()` |
| `{} | {1}` 抛 `TypeError` | 左边是字典 | `set() \| {1}` |
| 以为 `{3,1,2}` 一定打印成 `{1,2,3}` | 小整数哈希巧合 | 用 `sorted(s)` |
| 依赖集合顺序导致线上行为不一致 | 字符串哈希被随机化 | 永远用 `sorted(s)` |
| 跨次运行输出顺序不同以为是 bug | `PYTHONHASHSEED` 随机化 | 正常现象，不是 bug |
| `x = s.update({3})` 得到 `None` | `update` 返回 `None` | 分两行写 |
| `s.remove(不存在)` 抛 `KeyError` | `remove` 严格 | 用 `discard` |
| `s.discard(不存在)` 静默但没删掉 | `discard` 宽松 | 符合预期 |
| `s.pop()` 拿到的不确定是哪个 | 集合无序，`pop` 弹任意一个 | `min(s)` / `sorted(s)[0]` |
| `{[1, 2]}` 抛 `TypeError` | 列表不可哈希 | `{(1, 2)}` 或 `frozenset` |
| `set(字典)` 只得到键 | 迭代字典默认遍历键 | 要键值对用 `{frozenset(d.items())}` |
| `{1, 2} == {2, 1}` 意外为 `True` | 集合不关心顺序 | 列表才有顺序敏感 |
| 用 `in` 在列表里查导致 O(n²) | 列表查找线性 | 转成集合 |
| `list(set(...))` 后顺序乱了 | 集合无序 | `dict.fromkeys` 或 `sorted` |

## 📝 六、本课小结

- **集合的语义是「无序 + 唯一 + 可哈希」**，它专精两件事：**自动去重**和 **O(1) 成员判断**。`add` 已存在的元素不报错也不重复，这是语义决定的。
- **集合「必须无序」的根源是哈希表**：存入时按 `hash(元素)` 算槽位，遍历时按槽位顺序扫。顺序是**实现细节**，不是 API 的承诺。
- **⚠️ `{3,1,2}` 打印成 `{1,2,3}` 是巧合**，因为 `hash(整数) == 整数本身`，槽位下标恰好等于值。把范围换成 `{50,10,30,20,40}` 就有序性立刻消失。
- **⚠️ 字符串集合的顺序每次运行都不同**，因为 Python 默认开启 `PYTHONHASHSEED` **哈希随机化**（防止哈希碰撞攻击）。**这是规范行为，不是 bug**——需要有序输出永远用 `sorted(s)`。
- **空集合不能用 `{}`**：`{}` 在语法上必须表示「空映射」（否则 `{}['a']=1` 无法解析），所以空集合只能用 `set()`。这也是 `{} | {1}` 会抛 `TypeError` 的原因。
- **`set(字典)` 取的是「键」**，因为迭代字典默认遍历键，不是键值对。
- **`remove` 报错、`discard` 静默**：希望「不管在不在」用 `discard`，希望「必须存在」用 `remove`。
- **运算符返回新集合，`update` 返回 `None`**：`x = y.update(...)` 这种写法一定错。四个运算记「**一个是加（`|` 并集），其余是减（`&` 交、`-` 差、`^` 对称差）**」。
- **集合比较不关心顺序**：`{1,2} == {2,1}` 是 `True`（列表是 `False`）。子集用 `<=`，真子集用 `<`——差一个等号。
- **`frozenset` 是不可变集合，因此可哈希**——这是它唯一存在的理由。它能当字典键、能量化标签组合，但**没有** `add`/`discard`/`pop` 等修改方法，保留了全部运算方法。
- **性能差距用「增长曲线」比「快 N 倍」更有说服力**：实测 20 万元素查找，列表 945 ms vs 集合 0.043 ms（2 万倍）；且**数据量每翻倍，列表稳定 ×2.00，集合 ×1.0**——这才是 O(n) 与 O(1) 的本质区别。
- **去重有三种方式，只有两种保序**：`set()` 不保序；`seen` 集合 + 结果列表和 `list(dict.fromkeys(...))` 都保序（3.7+ 字典保证插入顺序）。⚠️ `dict(pairs)` 保留的是**最后一次**出现的值。
- **⭐ 最重要的心法**：看到双重循环里有「判断是否存在」，就问「**能不能用集合替掉一层循环**」。把 O(n) 的查找换成 O(1) 查表，整体从 O(n·m) 降到 O(n+m)——这是算法优化里性价比最高的一招。

> **一句话总结**：集合是「**为去重和成员判断而生的哈希表**」——它放弃了顺序（L09 的元组）和索引（L10 的字典），换来 O(1) 的存在性判断。而它最大的误解（以为输出有序）恰恰源于一个假象：**小整数的哈希值等于自身，于是槽位顺序恰好成了升序**。看穿这个巧合，你就真正理解了哈希表的存储方式。

**关键点 1：为什么基线版本真的是 O(n²)（曲线验证）**

思路：O(n²) 的特征是**数据量翻倍，耗时约 4 倍**。实测验证这个「4 倍」规律，就能证明你测的确实是平方复杂度。

```python
import time


def dedup_naive(items: list[int]) -> list[int]:
    """O(n²)：每加一个元素都要在结果列表里线性查找一次。"""
    result: list[int] = []
    for x in items:
        if x not in result:          # ⚠️ 列表查找是 O(len(result))
            result.append(x)
    return result


def show_quadratic_curve() -> None:
    """⭐ 用「耗时倍数」证明复杂度——这比口述更有说服力。"""
    print(f"{'n':>8} {'耗时(ms)':>10} {'相对上一个':>12}  说明")
    prev = 0.0
    for n in (1_000, 5_000, 10_000, 50_000, 100_000):
        data = [i % 10_000 for i in range(n)]
        t0 = time.perf_counter()
        _ = dedup_naive(data)
        elapsed = time.perf_counter() - t0
        # n 每变 5 倍，O(n²) 的耗时应该变 25 倍
        ratio = f"{elapsed / prev:.1f}×" if prev > 0 else "—"
        print(f"{n:>8} {elapsed * 1000:>10.1f} {ratio:>12}")
        prev = elapsed
    print("→ 观察「相对上一个」这一列：n 翻几倍，耗时就翻【平方】倍 → 确认 O(n²)")
```

**关键点 2：`dedup_incremental` vs `set()` 的场景差异（第 3 题）**

```python
def dedup_incremental(items: list[int]) -> list[int]:
    """边遍历边去重：内存里【同时】有输入列表和 seen 集合和结果列表。"""
    seen: set[int] = set()
    result: list[int] = []
    for x in items:
        if x not in seen:
            seen.add(x)
            result.append(x)
    return result


def compare_dedup_strategies() -> None:
    """⭐ 为什么大列表有时不该直接用 set(data)？"""
    # 场景 A：去重结果很小（比如 1 万条数据只有 10 个不同的值）
    few_unique = [i % 10 for i in range(200_000)]
    # 场景 B：去重结果很大（几乎每个都不同）
    many_unique = list(range(200_000))

    for name, data in [("去重结果很小", few_unique), ("去重结果很大", many_unique)]:
        # 策略1：一次性 set(列表)
        t0 = time.perf_counter()
        s1 = set(data)
        t1 = time.perf_counter()
        # 策略2：增量遍历
        s2 = dedup_incremental(data)
        t2 = time.perf_counter()
        print(f"{name}: set() {(t1 - t0) * 1000:.1f} ms vs 增量 {(t2 - t1) * 1000:.1f} ms")
```

**结论**：`set(data)` 更快，但会**一次性构造完整集合**（内存峰值高）；增量法内存友好（结果小的时候更省），但多了一次 Python 循环的开销。**数据量大且去重结果小时，增量法更稳。**

**关键点 3：join 的三种实现与数据倾斜（第 5 题）**

```python
def join_nested(users: list, orders: list) -> dict:
    """❌ 嵌套循环 O(n·m)：每个用户都要扫全部订单。"""
    result: dict = {}
    for u in users:
        uid = u["id"]
        result[uid] = [o for o in orders if o["user_id"] == uid]   # O(m) per user
    return result


def join_indexed(users: list, orders: list) -> dict:
    """✅ 建哈希索引 O(n+m)：先按 user_id 把订单分组。"""
    index: dict[object, list] = {}
    for o in orders:                      # 建索引一次 O(m)
        index.setdefault(o["user_id"], []).append(o)
    return {u["id"]: index.get(u["id"], []) for u in users}   # 每个用户 O(1)


def join_with_set_filter(users: list, orders: list) -> dict:
    """✅ 混合方案：先用集合筛掉【没有订单】的用户，再建索引。

    ⭐ 适用场景：绝大多数用户【没有】订单（真实业务中很常见）。
       先用集合 O(1) 过滤掉 95% 的用户，只对剩下的 5% 做处理。
    """
    user_ids = {u["id"] for u in users}   # 用户的 id 集合
    relevant = [o for o in orders if o["user_id"] in user_ids]  # 先过滤订单
    index: dict[object, list] = {}
    for o in relevant:
        index.setdefault(o["user_id"], []).append(o)
    return {u["id"]: index.get(u["id"], []) for u in users}
```

**关于数据倾斜的讨论**（这是本题的深度点）：

- **数据倾斜**指「少数用户占了绝大多数订单」（如一个企业客户有 100 万订单）。
- **嵌套循环**在倾斜下反而不太糟：总比较次数仍是 n·m，但**热点用户的结果很大**，循环体里的 `append` 是主要开销。
- **索引法**在倾斜下最稳：热点用户的订单一次性取到，后续都是 O(1) 的字典查询。
- **混合方案**在「绝大多数用户无订单」时最优，而在「绝大多数用户都有订单」时退化为索引法（但不会更差）。

**关键点 4：`frozenset` vs `tuple(sorted())` 做组合键（第 7 题）**

```python
def group_by_frozenset(records: list[dict]) -> dict:
    """用 frozenset 做键：天然去重且顺序无关。"""
    groups: dict[frozenset[str], list] = {}
    for r in records:
        key = frozenset(r["tags"])       # ⭐ 顺序无关，且自动去重
        groups.setdefault(key, []).append(r)
    return groups


def group_by_sorted_tuple(records: list[dict]) -> dict:
    """用排序后的元组做键：效果相同但需要排序开销。"""
    groups: dict[tuple[str, ...], list] = {}
    for r in records:
        key = tuple(sorted(r["tags"]))    # 必须先排序，否则 ("a","b") ≠ ("b","a")
        groups.setdefault(key, []).append(r)
    return groups
```

⚠️ **关键区别**：`frozenset` **自动去重**，所以 `["a", "a", "b"]` 和 `["a", "b"]` 会分到同一组；而 `tuple(sorted(...))` **不会去重**，`("a","a","b")` 和 `("a","b")` 是不同的键。**如果业务上「重复标签」应该视为相同，必须用 `frozenset`**。

```python
def find_pairs_with_diff_naive(nums: list[int], k: int) -> list[tuple[int, int]]:
    """O(n²)：对每个数，再遍历一遍找差为 k 的。"""
    pairs = []
    for i, x in enumerate(nums):
        for j in range(i + 1, len(nums)):
            y = nums[j]
            if abs(x - y) == k:
                pairs.append((x, y))
    return pairs


def find_pairs_with_diff_fast(nums: list[int], k: int) -> list[tuple[int, int]]:
    """O(n)：遍历一遍，用集合判断 x+k 是否存在。

    ⭐ 为什么能降到 O(n)？因为「差为 k」等价于「x+k 在集合里」，
       而集合判断是 O(1)。所以外层跑 n 次就够，不用再遍历。
    """
    pool = set(nums)
    seen: set[int] = set()          # ⭐ 用 seen 避免 (1,2) 和 (2,1) 重复输出
    pairs = []
    for x in nums:
        if x + k in pool and x not in seen:
            pairs.append((x, x + k))
        seen.add(x)
    return pairs
```

⚠️ `seen` 集合的作用很容易被忽略：不加它，`(1,2)` 和 `(2,1)` 会**都**输出（当 k=1 时）。

**第 4 题第 8 条「集合 vs 字典」的判据**（这题的深度点）：

| 需求 | 用集合 | 用字典 |
| --- | --- | --- |
| 只需要「判断是否存在」 | ✅ `x in s` | ✅ `k in d` |
| 需要「取回对应的值」 | ❌ 集合不存值 | ✅ `d[k]` |
| 需要「统计次数」 | ❌ | ✅ 计数字典 / `Counter` |

**一句话判据**：**只需要「有没有」就用集合；需要「是什么」就用字典**。

**第 5 题「容斥原理」的核心**：

```python
from itertools import combinations
from math import comb


def exactly_n_naive(sets: list[set], n: int) -> set:
    """朴素：逐个元素统计它出现在几个集合里。O(元素总数 × 集合数)。"""
    counts: dict[object, int] = {}
    for s in sets:
        for item in s:
            counts[item] = counts.get(item, 0) + 1
    return {item for item, c in counts.items() if c == n}


def exactly_n_inclusion_exclusion(sets: list[set], n: int) -> set:
    """⭐ 容斥原理：直接算「恰好出现 n 次」，避免统计每个元素。

    公式：恰好 n 次 = Σ_{k=n..m} (-1)^(k-n) × C(k,n) × (取 k 个交集的和)
    """
    m = len(sets)
    if not (1 <= n <= m):
        return set()
    result: set = set()
    for k in range(n, m + 1):
        # ⭐ 枚举所有「k 个集合的组合」
        for combo in combinations(sets, k):
            inter = combo[0].intersection(*combo[1:])
            count = comb(k, n)                # 组合数系数
            if (k - n) % 2 == 0:
                result |= {item for item in inter for _ in range(count)}
            else:
                dupes = {item for item in inter for _ in range(count)}
                result -= dupes
    return result
```

⚠️ **容斥的正确性依赖验证**，所以这道题的验收标准里写了「必须与朴素循环统计结果一致」——**两种算法交叉验证**是最好的确认方式。

> 💡 容斥的价值在于：当集合数量很少（≤ 5）而元素极多时，它避免了「逐元素统计」的大量哈希操作。但如果集合数量多，组合数会爆炸（`C(20, 10)` 超过 18 万），这时朴素法反而更好。**没有银弹，要看具体规模。**
