## 📖 二、知识讲解

### 2.1 PEP 8 是什么

**一句话定义**：PEP 8 是 Python 官方社区通过的一份 Python 代码风格指南（PEP = Python Enhancement Proposal，Python 增强提案）。

- 官方地址：<https://peps.python.org/pep-0008/>
- 另一个官方来源：<https://google.github.io/styleguide/pyguide.html>（Google 的 Python 风格指南，和 PEP 8 高度一致）

**为什么要有规范**：Python 的社区信条是 **"Explicit is better than implicit"（显式胜于隐式）** 和 **"Readability counts"（可读性至上）**。规范的直接目的不是「让程序跑得更快」，而是——

> **让 90% 的时间被用于读代码，只有 10% 用于写代码。** 而 Python 是少数「读代码的时间远多于写代码」的语言，因为它省掉了类型声明、大括号、分号这些噪音，代码密度高、信息量大，更需要靠规范来保证可读性。

⚠️ **PEP 8 是「指南」不是「法律」**。有些场合可以合理偏离（比如行宽由公司统一规定、用 `pyproject.toml` 做了自动化配置）。**关键是：在一个项目内部保持一致，比绝对遵守 PEP 8 更重要。**

#### PEP 8 核心要点速览（这些要背下来）

| 要点 | 规定 |
| --- | --- |
| 缩进 | **4 个空格**，同一代码块内保持一致 |
| 行长 | **79 字符**（PEP 8 原始规定）。现代项目常用 88（Black 默认）或 99/100 |
| 空行 | 顶层函数/类之间 **2 行**；类内方法之间 **1 行**；函数体内逻辑块之间 1 行 |
| 空格 | 运算符两侧、逗号后、括号内侧各 1 个空格 |
| 引号 | 统一用一种（本教材统一用双引号 `"`） |
| 命名 | 变量/函数 `snake_case`，常量 `UPPER_CASE`，类 `PascalCase` |
| import | 放在文件顶部，标准库 → 第三方 → 本地，三组之间空一行 |
| 注释 | 用 `#`，与代码同风格；解释「为什么」 |
| docstring | 模块、类、公开函数都要有，用三引号 |
| 编码 | UTF-8 |
| 优先 | 明确优于隐式（`== True` 而非 `if x:`） |

### 2.2 命名规范

**命名是代码风格里投入产出比最高的一项**。名字写对了，代码不用注释就能读懂；名字写错了，再好的注释也救不回来。

#### 四类命名规范

```python
# ========== 1. 变量和函数：snake_case（小写 + 下划线）==========
user_name = "张三"            # 普通变量
max_retry_count = 3           # 普通变量
total_price_after_discount = 99.9   # 再长的下划线名字也比含糊的短名字好

def calculate_total_price(items, discount_rate):
    """函数名也用 snake_case，动词开头。"""
    return sum(items) * (1 - discount_rate)


# ========== 2. 常量：UPPER_CASE（全大写 + 下划线）==========
MAX_FILE_SIZE_MB = 100        # 全大写，一眼看出是常量
DEFAULT_TIMEOUT_SECONDS = 30
API_BASE_URL = "https://api.example.com"


# ========== 3. 类：PascalCase（每个词首字母大写）==========
class ShoppingCart:
    """类名用大驼峰。"""

    def add_item(self, item):
        """方法名用 snake_case。"""
        self.items.append(item)


# ========== 4. 特殊的例外情况 ==========
__init__          # 前后双下划线：魔术方法（magic method），特殊用途
__name__          # 模块内置变量
_private           # 前单下划线：约定「内部使用，别从外部调」
_name_             # 后单下划线：避免与关键字/内置名冲突（如 class_）
```

#### 命名时该用什么词

| 用途 | ✅ 推荐 | ❌ 避免 |
| --- | --- | --- |
| 布尔值 | `is_valid`、`has_permission`、`should_retry`、`can_edit` | `flag`、`ok`、`b`、`valid_flag` |
| 列表 | `items`、`user_list`、`scores`（复数或加 `_list`） | ~~`data`~~、~~`a1`~~、~~`temp`~~（临时） |
| 计数 | `count`、`total_count`、`index` | ~~`num`~~（是编号还是数量？） |
| 布尔方法 | `is_empty()`、`has_key()`、`can_convert()` | `empty()`、`check()` |
| 字典 | `user_by_id`、`config_map` | ~~`map`~~（容易和内置 `map()` 混淆） |
| 布尔函数返回值 | 用 `is_`/`has_`/`should_` 开头 | — |

#### 必须避免的名字

> ⚠️ 下面代码块中的 `# ❌` 部分**故意保留了无法运行的写法**（`class = 5` 是
> 关键字作变量名，Python 会直接报 `SyntaxError`），这是为了让你看清错误长什么样。
> `# ✅` 部分才是可以正常运行的正确写法。

```python
# ❌ 绝对不要：和内置函数/关键字重名，覆盖后整个文件都会出错
list = [1, 2, 3]        # 覆盖内置 list()，后面就不能用 list() 了
dict = {}
type = "student"        # 覆盖内置 type()，报错信息都会变得莫名其妙
str = "hello"
sum = 0
id = 1
class = 5                # 关键字，直接 SyntaxError
print = 123              # 覆盖后 print() 用不了了

# ✅ 正确的绕开方式
user_list = [1, 2, 3]
user_dict = {}
user_type = "student"
text = "hello"
total = 0
user_id = 1

# ✅ 或者用下划线后缀（PEP 8 推荐的冲突规避方式）
list_ = [1, 2, 3]
class_ = 5
```

⚠️ **检查方法**：养成一个习惯——**看到不认识的名字，先问「它是不是内置函数？」** 执行 `print(type(list))` 或在 VS Code 里把光标放在名字上，能看到定义。

#### 命名做到什么程度算好

判断标准：**变量名能不能单独读懂这一行在做什么。**

```python
# ❌ 差：意思全靠注释
d = 86400
t = d * 3
print(f"{t}s")

# ✅ 好：名字自带含义，不需要注释
SECONDS_PER_DAY = 86400
three_days_in_seconds = SECONDS_PER_DAY * 3
print(f"{three_days_in_seconds}s")
```

⚠️ **注意平衡**：不要为了「名字长」而啰嗦。`user_id` 好，但 `user_identifier_for_database_table_row` 就过了。**目标是「足够清楚」，不是「越长越好」。**

### 2.3 常量定义与魔法数字

**魔法数字（magic number）**：直接硬编码在代码里的数字，读者不知道它是什么含义。

```python
# ❌ 差：60 是什么？为什么是 60？
if temperature > 60:
    print("过热")

if delay > 300:
    print("超时")

if width * height > 1920 * 1080:
    print("超过全高清")

# ✅ 好：提到模块顶部，命名成常量
MAX_SAFE_TEMPERATURE = 60
REQUEST_TIMEOUT_SECONDS = 300
FULL_HD_WIDTH = 1920
FULL_HD_HEIGHT = 1080

if temperature > MAX_SAFE_TEMPERATURE:
    print("过热")

if width * height > FULL_HD_WIDTH * FULL_HD_HEIGHT:
    print("超过全高清")
```

**为什么重要**：当「60」这个阈值需要改成「65」时，硬编码版本你要在 20 个文件里找；常量版本只需要改一行。**常量是「一处修改，全局生效」。**

**常量定义在哪个位置**：

| 常量的作用范围 | 定义位置 |
| --- | --- |
| 单个模块内使用 | 文件顶部，import 之后、函数定义之前 |
| 跨模块共享 | 专门建一个 `constants.py` 或 `config.py` |
| 类专属的常量 | 放在类内部（PEP 8 认可的做法） |

```python
"""订单模块：文件顶部集中定义常量。"""

from datetime import timedelta

# 常量区：全大写，一行一个，配一行中文说明
MAX_ORDER_ITEMS = 100           # 单笔订单最多 100 件商品
FREE_SHIPPING_THRESHOLD = 99    # 满 99 元免运费
VALID_PAYMENT_METHODS = ("alipay", "wechat", "card")   # 元组：不可变，更安全
ORDER_EXPIRED_AFTER = timedelta(hours=2)   # 超过 2 小时订单自动失效


def is_free_shipping(order_total: float) -> bool:
    """判断订单是否达到免运费门槛。"""
    return order_total >= FREE_SHIPPING_THRESHOLD
```

⚠️ **一个诚实的说明**：**PEP 8 并没有强制要求把常量定义在模块顶部**，它只是建议「把常量放在模块顶部并用全大写命名」（原文：constants are usually defined at the module level）。上面的做法是社区的通行惯例，本教材建议你从 W1 就照着做。

⚠️ **另一类「伪常量」**：写在类里的 `__init__` 中、每次实例化都重新算一遍的「常量」，效率低下：

```python
# ❌ 每个实例都重新拼一遍字符串，浪费
class Report:
    def __init__(self):
        self.header = "=" * 60      # 这个字符串不变，应该是常量

# ✅ 模块级算一次，所有实例共享
REPORT_HEADER = "=" * 60

class Report:
    def __init__(self):
        self.header = REPORT_HEADER
```

### 2.4 缩进与空格

#### 铁律：4 个空格，绝不混用 Tab

```python
# ✅ 正确：4 空格缩进
def outer():
    x = 1
    if x:
        y = 2          # 8 空格 = 嵌套两层
        return y
    return 0

# ❌ 错误 1：用 Tab 缩进
def outer():
	x = 1             # Tab 缩进，其他编辑器可能显示成 8 空格也可能不是

# ❌ 错误 2：2 空格缩进（不是不能用，但全项目必须统一，且与 PEP 8 不符）
def outer():
  x = 1
```

⚠️ **为什么 Tab 这么危险**：Python 规定「Tab 和空格混用时，按 8 空格对齐 Tab」。这意味着**你在 VS Code 里写的代码，用 IDLE 打开可能就变成完全不同的缩进层级**，触发 `IndentationError: unexpected indent`。**这是新手最常见的「在我机器上明明能跑」问题。**

⚠️ **怎么彻底避免**：VS Code 里 `Ctrl+,` 打开设置，搜 `insert spaces`，设为 `spaces`；再搜 `tab size`，设为 `4`。这样按 Tab 键实际插入的是 4 个空格。

#### 空格使用规则

```python
# ✅ 运算符两侧各一个空格
result = a + b * c
flag = (x > 0) and (y < 10)

# ✅ 逗号后一个空格，逗号前不加
result = f(a, b, c)

# ✅ 切片冒号两边都加空格（当表达式复杂时）
subset = data[1 : 10 : 2]       # 复杂表达式两边留空格更好读
first = data[0]                  # 简单表达式不加空格

# ✅ 括号内侧不留空格
result = f(a, b)                  # f( a, b ) 是错的
items = [1, 2, 3]                 # [ 1, 2, 3 ] 是错的

# ✅ 函数定义和调用时，参数之间逗号后加空格
def calculate(a, b):
    return a + b

# ✅ 字典冒号两侧留空格，逗号后留空格
config = {"name": "test", "debug": True}

# ❌ 一律错误：括号内加空格
result = ( a + b )
```

#### 续行规则（长表达式怎么换行）

```python
# ✅ 推荐：用括号包裹，然后按对齐原则换行
result = some_function(
    first_argument,
    second_argument,
    third_argument,
)

# ✅ 或者用反斜杠 \（不推荐，可读性差且容易漏）
result = first + \
         second

# ✅ 长条件用括号包起来换行
if (user_age >= 18
        and has_vip_status
        and country in ALLOWED_COUNTRIES):
    grant_access()

# ✅ 链式调用换行用括号（3.10+ 也支持更灵活的多行括号）
result = (
    data
    .filter(...)
    .sort(...)
    .limit(10)
)
```

### 2.5 注释：写「为什么」，不是「做什么」

**这是本篇最重要的一节。**

#### 反面教材：复述代码

```python
# ❌ 这些注释全部应该删掉，因为它们没有提供任何代码之外的信息
# 初始化变量
count = 0
# 循环 i 从 0 到 10
for i in range(10):
    # 如果 i 大于 5
    if i > 5:
        # 打印 i
        print(i)
```

**为什么坏**：代码本身已经说了这些事。读者要「把注释和代码对照着读」反而更累。

#### 正面教材：解释「为什么」

> ⚠️ 下面这段代码**只作阅读示范，不能整段复制运行**——它是若干独立片段的拼凑，
> 其中 `bisect_left` 等库函数没有导入，直接跑会报 `NameError`。
> 每一段请单独理解，不要当成完整程序。

```python
# ✅ 好的注释告诉你「代码本身看不出来的事」
count = 0
for i in range(10):
    if i > 5:
        count += 1

# 为什么只统计 6~9？业务规则：只有编号 6-9 的记录是「有效订单」，
# 其余是测试数据混进来的（见需求文档 §3.2）

# ✅ 解释「为什么用这个方案而不是显而易见的那个方案」
# 用二分查找而不是遍历：数据量有 200 万条，遍历平均要 1.5 秒，
# 二分查找稳定在 0.02 秒以内
index = bisect_left(sorted_ids, target_id)

# ✅ 解释「这个反直觉的写法是刻意的」
# 这里的 not x 不要改成 if x is None：
# 0 / "" / [] 都应该被视为「空」，用 `not` 语义才正确
if not values:
    return default

# ✅ 解释「这个数字从哪来」
# 60 是产品经理在 2026-09 的需求会上定的阈值，
# 改动需要找产品确认，不要自行调整
if score >= 60:
    pass

# ✅ 标注临时方案和 TODO（写清楚原因和预期）
# TODO(2026-11-01): 接口还没上线，先用本地假数据兜底，
# 上线后替换为 HTTPClient.fetch() —— 跟踪 issue #203
data = load_fake_data()
```

#### 注释的三条纪律

| 纪律 | 说明 |
| --- | --- |
| **不写废话** | 不解释「做什么」，只解释「为什么」 |
| **保持同步** | 代码改了注释必须一起改。**过时的注释比没有注释更糟**——它会误导人 |
| **少而精** | 一个函数里 1~3 条有效注释足够。满屏注释说明代码本身没写清楚 |

#### `# TODO` 注释的正确用法

```python
# ✅ 好的 TODO：说清楚「要做什么、为什么、什么时候」
# TODO(2026-11-01): 把 CSV 读取改用 pandas，200 行逻辑能缩到 20 行

# ❌ 无用的 TODO：只是标记「这里有问题」，不解决问题
# TODO: 这里有问题
```

### 2.6 docstring 规范

**docstring 是什么**：写在模块、类、函数开头的说明文档，运行时可以通过 `__doc__` 读取，也是 `help(func)` 显示的内容。

**基本格式**：

```python
def calculate_total_price(items: list[float], discount_rate: float) -> float:
    """一句话说明这个函数做什么（以动词开头，结尾带句号）。

    如果需要更多说明，在这里写第二段、第三段，
    描述算法思路、复杂度、注意事项等。

    Args:
        items: 商品价格列表，必须非空。
        discount_rate: 折扣率，取值 0~1 之间，0.2 表示打八折。

    Returns:
        折后总价，保留两位小数。

    Raises:
        ValueError: 当 items 为空或 discount_rate 超出 0~1 时抛出。
    """
    if not items:
        raise ValueError("商品列表不能为空")
    if not 0 <= discount_rate <= 1:
        raise ValueError("折扣率必须在 0 到 1 之间")
    return round(sum(items) * (1 - discount_rate), 2)
```

**格式要点**：

| 要素 | 规范 |
| --- | --- |
| 引号 | **三引号** `"""`（即使单行也用三引号，保持一致） |
| 第一行 | 一句话概述，**动词开头**，结尾带句号，紧跟在 `"""` 后（同一行或下一行都行，团队内统一即可） |
| 空行 | 第一行后空一行，再写详细说明 |
| `Args:` | 每个参数一行，格式 `参数名: 说明` |
| `Returns:` | 返回值说明；如果函数没有返回值（返回 `None`），**不写这一节** |
| `Raises:` | 会主动抛出的异常；不写它捕获后再抛出的内部异常 |
| 缩进 | `Args:` 等小节的内容缩进 4 空格 |

**其他位置的 docstring**：

```python
"""模块级 docstring：放在文件第一行，说明这个模块是干什么的。

可以写多行，第一行概述，后面写详细说明。
作者、版本、日期等元信息也可以放这里。
"""

import os


class ShoppingCart:
    """类级 docstring：说明这个类代表什么、有什么职责。

    Attributes:
        items: 购物车中的商品列表。
        owner: 购物车归属的用户名。
    """

    def __init__(self, owner: str) -> None:
        """方法 docstring：说明构造时做了什么。"""
        self.items = []
        self.owner = owner

    def add_item(self, item_name: str) -> None:
        """把商品加入购物车。

        Args:
            item_name: 商品名称。
        """
        self.items.append(item_name)
```

⚠️ **常见错误：docstring 说了不存在的参数**

```python
# ❌ Args 里写了 rate，但函数根本没有这个参数
def calculate(price):
    """计算总价。

    Args:
        price: 单价。
        rate: 折扣率。    # ← 这个参数不存在！
    """
    return price * 2

# ✅ 函数签名和 Args 必须严格一致
def calculate(price, rate):
    """计算总价。

    Args:
        price: 单价。
        rate: 折扣率。
    """
    return price * rate
```

### 2.7 代码布局：空行规则

**PEP 8 的空行规则（要背）**：

| 位置 | 空行数 |
| --- | --- |
| 顶层函数 / 类 定义之间 | **2 行** |
| 类内的方法之间 | **1 行** |
| 函数体内各逻辑块之间 | 1 行 |
| import 区 和代码区之间 | 2 行 |
| 模块顶部（docstring 之后） | 2 行 |

**正确的布局示例**：

```python
"""这个文件的说明。"""          # 模块 docstring

import sys
from pathlib import Path


from third_party import lib     # 1 空行分隔不同分组


from my_project.utils import helper   # 再 1 空行


MAX_SIZE = 100                  # 2 空行后开始常量定义


def first_function():           # 2 空行后开始函数定义
    x = 1
    return x


def second_function():          # ★ 2 空行
    y = 2
    return y


class MyClass:                 # ★ 2 空行

    def method_one(self):       # 类内方法之间只要 1 空行
        return 1

    def method_two(self):       # ★ 1 空行
        return 2


class OtherClass:               # ★ 类之间 2 空行

    def __init__(self):
        self.value = 0
```

**函数体内的逻辑块空行**：

```python
def process(data):
    result = []                 # 准备阶段

    for item in data:           # ★ 处理阶段之间空一行，视觉上分区
        if item > 0:
            result.append(item)

    return result               # 返回阶段
```

**为什么空行重要**：PEP 8 原文说得很直接——*surrounding functions and classes are separated by two blank lines*，空行是**「视觉上的分隔」，让读者能一眼看出代码的分组结构**。而且 Python 官方工具 `pycodestyle` 会检查这条规则，不符合会报警告。

### 2.8 行长限制

**规定**：PEP 8 原始规定是 **79 字符**，理由是当时编辑器默认宽度是 80 字符。

**现代实际情况**：

| 行宽 | 出处 | 备注 |
| --- | --- | --- |
| 79 | PEP 8 原文 | 历史原因 |
| **88** | Black 格式化工具默认 | ★ 现在最常见 |
| 100 | PyCharm 默认 | |
| 120 | 部分公司规范 | 容易过长 |

**本教材建议：单行不超过 88 字符**（够宽，不容易触发换行；又不至于让代码横向滚动）。

### 2.10 KISS 原则：什么时候不要用面向对象

**KISS = Keep It Simple, Stupid**（保持简单，傻瓜式）。核心理念：**「能简单解决，就不要复杂解决。」**

#### 什么时候该用面向对象

用类不是为了「显得高级」，而是因为遇到了这些信号：

| 信号 | 为什么需要类 |
| --- | --- |
| ① 数据和行为要**绑在一起** | 类的字段和方法天然属于同一实体 |
| ② 有**多个类型共享同一套操作** | 多态：`Circle` 和 `Square` 都能 `.area()` |
| ③ 需要**复用和继承** | 子类复用父类逻辑，避免复制粘贴 |
| ④ 需要**封装保护内部状态** | 私有属性 + 属性（property），防止外部乱改 |
| ⑤ 状态需要**跨函数传递** | 一个对象带着一堆数据到处走，比传 8 个参数好 |

#### 什么时候**不该**用类（初学者最常见的过度设计）

```python
# ❌ 反面教材：为了一个求和，套了三层设计模式

class AbstractCalculatorBase:          # 第 1 层：抽象基类
    def calculate(self, data):
        raise NotImplementedError


class ConcreteCalculatorImpl(AbstractCalculatorBase):   # 第 2 层：实现类
    def __init__(self):
        self._cache = {}               # 从头到尾没用过
        self._config = {}               # 从头到尾没用过
        self._logger = {}               # 从头到尾没用过

    def calculate(self, data):
        self._cache["last"] = data
        return {"total": sum(data), "average": sum(data) / len(data)}


# 调用方要多绕三层才能拿到结果
def get_stats(scores):
    return ConcreteCalculatorImpl().calculate(scores)


# ✅ 正面教材：两行函数，作用完全相同

def get_stats(scores):
    """汇总分数的总分和平均分。"""
    return {"total": sum(scores), "average": sum(scores) / len(scores)}
```

**上面这段的完整反面示例见 `examples/00_style_demo.py` 中的 `bad_05_ood_for_no_reason()` 与 `good_05_kiss()`。**

#### 判断该用函数的六条规则

| 规则 | 说明 |
| --- | --- |
| ① **先写函数** | 默认都用函数。类是需要**证明**的复杂度，不是默认选项 |
| ② **一个类一件事** | 如果类名里出现「并且（and）」「管理器（Manager）」，多半该拆成两个类或用函数 |
| ③ **不为「未来可能」而设计** | 「万一以后要加 SQLite 呢？」——**等真的加的时候再抽象**，那时候你才知道该怎么做 |
| ④ **继承层次超过 2 层就该重新考虑** | 超过 2 层继承，代码就很难追踪了。优先考虑组合而不是继承 |
| ⑤ **抽象必须有第二个实现** | 没有第二个子类，这个抽象层就是多余的 |
| ⑥ **写不出更好的就别硬上** | 如果写成函数和写成类的**代码量差不多**，那就用函数 |

#### 函数 vs 类的选择流程

```text
这个功能只是一次性计算，没有状态需要保存？
    └─ 是 → 用函数（KISS 原则）★ 默认走这条

需要保存状态，供后续多个操作反复使用？
    └─ 是 → 继续判断

有多个不同类型需要执行同一套操作（多态）？
    └─ 是 → 用类 + 继承/协议

只需要「数据 + 几个操作方法」，不需要继承？
    └─ 是 → 用类（但可以不继承基类，直接写）
    └─ 否 → 用函数 + 字典/dataclass
```

#### KISS 的其他体现

```python
# ❌ 为了「通用」而写一堆分支，实际只用得到一个
def process(data, mode="simple", is_async=False, cache=True, retry=3, encoding="utf-8"):
    if mode == "simple":
        ...
    elif mode == "advanced":
        ...
    elif mode == "custom":      # 从来没人调过
        ...

# ✅ 只实现现在真正需要的功能，需要时再加分支
def process(data):
    return [x * 2 for x in data]
```

**Pythonic 的做法**：Python 标准库里有大量「参数可选、行为可组合」的接口（如 `sorted(key=...)`、`print(*args, sep=...)`）。**但那是在有大量真实用户和明确需求之后才演进的。** 初学阶段的正确做法是：**先写最简单的版本，等你遇到第三种需求时，再考虑怎么抽象。**

⚠️ **最后一句忠告**：**过度设计比代码丑更严重。** 丑代码只是难看，过度设计会让代码**变得无法修改**——因为每加一个新功能都要穿过七八层你当初为了「将来」而造的抽象层。初学阶段，**能跑通的简单代码 > 优雅但复杂的代码。**

def filter_passing(scores: list[int]) -> list[int]:
    """筛选出所有及格分数。

    只做一件事：把及格的分数挑出来。

    Args:
        scores: 所有学生的分数列表。

    Returns:
        及格分数组成的列表，顺序与输入一致。

    Raises:
        ValueError: 传入的分数超出 0~100 合法区间时抛出。
    """
    # 先校验再计算：让函数在错误输入下立刻失败，而不是先算出一堆错误结果
    for score in scores:
        if not SCORE_MIN <= score <= SCORE_MAX:
            raise ValueError(f"分数 {score} 超出 0~100 的合法区间")

    # 用推导式替代 6 行 for 循环，可读性反而更高——这是 Python 的风格优势
    return [score for score in scores if score >= PASSING_SCORE]


def classify(score: float) -> str:
    """把单个分数转换为等级。

    Args:
        score: 单个分数，允许小数。

    Returns:
        等级字符串："A" / "B" / "C" / "D"。

    Raises:
        ValueError: 分数越界时抛出。
    """
    if not SCORE_MIN <= score <= SCORE_MAX:
        raise ValueError(f"分数 {score} 超出 0~100 的合法区间")

    # 从高分往低分判断，一旦命中就返回，逻辑扁平无需嵌套。
    # 注意使用 >= 而非 >：60 分应该算及格。
    if score >= EXCELLENT_SCORE:
        return "A"
    if score >= 80:
        return "B"
    if score >= PASSING_SCORE:
        return "C"
    return "D"


def summarize(scores: list[int]) -> dict[str, object]:
    """汇总一组分数的统计信息。

    Args:
        scores: 非空的分数列表。

    Returns:
        含 total / average / best / worst / level / passed_count 的字典。

    Raises:
        ValueError: 列表为空时抛出——平均值无法从空数据算出，
            静默返回 0 会让调用方误以为「全班都考 0 分」。
    """
    if not scores:
        raise ValueError("分数列表不能为空")

    total = sum(scores)
    # round 保留一位小数，避免出现 82.83333333333333 这种噪音
    average = round(total / len(scores), 1)

    # 显式列出返回的键，而不是让调用方猜字典里有什么
    return {
        "total": total,
        "average": average,
        "best": max(scores),
        "worst": min(scores),
        "level": classify(average),
        "passed_count": len(filter_passing(scores)),
    }


def format_report(subject: str, scores: list[int]) -> str:
    """把一份成绩单格式化成可读文本。

    Args:
        subject: 科目名，如 "语文"。
        scores: 该科目的所有分数。

    Returns:
        多行字符串，每行一个统计项。

    Raises:
        ValueError: 分数数据非法时，异常会向上传播给调用方处理。
    """
    stats = summarize(scores)

    # 用三引号字符串 + 文本内换行，比一连串 print 或字符串拼接好读得多
    return (
        f"【{subject}】\n"
        f"  总分：{stats['total']}\n"
        f"  平均分：{stats['average']}\n"
        f"  最高分：{stats['best']}\n"
        f"  最低分：{stats['worst']}\n"
        f"  及格人数：{stats['passed_count']}\n"
        f"  综合等级：{stats['level']}"
    )

def good_04(item: str, bucket: Optional[list] = None) -> list[str]:
    """正确处理「可变默认参数」的写法。

    默认值用 None（不可变），函数内部再按需创建新的列表，
    这样每次调用都有独立的 bucket，不会互相污染。

    Args:
        item: 要加入的科目名。
        bucket: 目标列表。为 None 时自动新建一个。

    Returns:
        传入（或新建）的列表，其中已包含 item。
    """
    # if bucket is None 而不是 if not bucket：
    # 后者会把「传入了一个空列表」也当成没传，导致调用方传入的列表被丢弃
    if bucket is None:
        bucket = []
    bucket.append(item)
    return bucket

## ⚠️ 四、常见错误清单

| 错误现象 | 原因 | 正确写法 |
| --- | --- | --- |
| `IndentationError: unexpected indent` | Tab 和空格混用 | 全文统一 4 空格；VS Code 设 `insert spaces = spaces` |
| `IndentationError: unindent does not match` | 同上 | 同上 |
| 变量名覆盖内置函数，后续 `list()` 报错 | 用了 `list = []` 这类命名 | `user_list = []`；或 `list_ = []` |
| `SyntaxError`（用了 `class` 作变量名） | 用了关键字 | 换名，如 `class_`、`class_name` |
| 默认参数里的列表数据「莫名其妙越攒越多」 | 可变对象作默认值（默认值只在函数定义时求值一次） | 默认值用 `None`，函数内 `if bucket is None: bucket = []` |
| `if not bucket` 判断失效（传了空列表却被丢弃） | `not` 对空列表也为 True | 用 `if bucket is None` 区分「没传」和「传了空列表」 |
| 函数调用莫名慢、启动卡顿 | 在函数内部 `import` 重型模块 | 提到文件顶部，或加注释说明为何要局部导入 |
| 改了阈值要翻遍 20 个文件 | 硬编码魔法数字 | 提取为 `UPPER_CASE` 常量，放模块顶部 |
| 团队合并代码后格式全变、diff 一片红 | 有人用 Tab 有人用空格，行宽也不统一 | 用 `.editorconfig` + Ruff 统一，提交前自动格式化 |
| 注释和代码对不上，误导了同事 | 代码改了注释没同步 | 改代码时一并改注释；过时的注释比没注释更糟 |
| docstring 里 Args 写了不存在的参数 | 手写文档没同步签名 | Args 必须与函数签名逐一对齐 |
| 一次改 300 行全在调格式，review 无法进行 | 格式没统一 | 单独提一个「纯格式化」commit；之后用工具自动保持 |
| 类套了 4 层，功能只有求和 | 为了「显得高级」过度设计 | KISS 原则：先写函数，等遇到第三个需求再抽象 |
| 命名里出现「管理器 / Handler / Manager」 | 一个类干太多事 | 拆成多个类，或退回函数 + 字典 |
| 长字符串导致整行超过 88 字符 | 没换行 | 用括号隐式拼接多行字符串，或 `# noqa: E501` |

## 📝 六、本课小结

- PEP 8 的目的是「让读代码的人更快」，核心信条是**可读性至上**。它是指南不是法律，**项目内一致比绝对遵守更重要**。
- 命名是投产比最高的一项：变量/函数 `snake_case`，常量 `UPPER_CASE`，类 `PascalCase`；布尔用 `is_`/`has_` 前缀；**绝不覆盖内置函数名**（`list = []` 会毁掉整个文件）。
- 魔法数字要提取成常量放在模块顶部，理由是「一处修改，全局生效」，且读者能看懂 60 是什么含义。
- **4 空格缩进，绝不混用 Tab**——Tab 在不同编辑器下宽度不一致，是「我机器上能跑」类问题的头号来源。
- **注释写「为什么」，不写「做什么」**。复述代码的注释应该删掉。过时的注释比没有注释更糟。
- docstring 用三引号，包含一行概述 + `Args` / `Returns` / `Raises`，且 Args 必须与函数签名逐一对齐。
- 空行规则：顶层函数/类之间 **2 行**，类内方法之间 **1 行**。空行是「视觉分组」。
- 行宽建议 **88 字符**（PEP 8 原版 79，Black 默认 88）。超长时用括号包裹换行，不要横向滚动。
- import 分三组（标准库 → 第三方 → 本地），组间空一行；**不要 `import *`**；`__all__` 明确对外接口。
- **KISS 原则：默认用函数，类是需要证明的复杂度。** 抽象层要有第二个实现才值得存在；不为「万一以后」而设计；继承超过 2 层就该改用组合。
- **过度设计比代码丑更严重**：丑代码只是难看，过度设计会让代码无法修改。初学阶段，能跑通的简单代码 > 优雅但复杂的代码。

> **一句话总结**：好代码不是「写得漂亮」，而是「让三个月后的你自己不用猜」。

| ② | 使用了 Tab 缩进 | 某行含 `\t` |
| ③ | 行尾有多余空格 | 某行 `rstrip()` 后与原行不同 |
| ④ | 变量名覆盖内置函数 | 出现 `list = `、`dict = `、`type = ` 等赋值 |
| ⑤ | 函数/类前空行不足 | 顶层 `def`/`class` 前连续空行 < 2 |
| ⑥ | `import *` 通配导入 | 出现 `import *` 或 `from x import *` |
| ⑦（选做） | 缺少函数 docstring | 顶层 `def` 后紧跟的第一行不是 `"""` |

**具体要求**：

1. 只依赖标准库；
2. 输入一个 `.py` 文件路径，输出检查报告（每条违规显示行号 + 内容 + 违规说明）；
3. 用 `try/except` 处理「文件不存在」「没有读取权限」「编码错误」；
4. **最后给一个总评分**（如 `检查了 N 行，发现 M 个问题，评分 100 - min(M*5, 60)` 分）；
5. **自己去测试它**：造一个故意写得很烂的测试文件，让检查器至少报出 5 个问题，截图记录；
6. 你自己写的检查器代码本身**必须符合 PEP 8**（可以用 Ruff 验证）。

- **输出**：`style_checker.py` 完整代码 + 用它检查 `examples/00_style_demo.py` 和你自己造的烂文件的输出截图。
- **验收标准**：6 条规则全部实现并验证有效；检查器自身通过 Ruff 检查；报告中每条问题都有**可操作的修改建议**而不只是报错。

<summary>✅ 挑战题参考思路与关键代码</summary>

**关键点 1：把每条规则写成独立的小函数**，返回「行号 + 说明」的列表，符合单一职责原则。

**关键点 2：检查顶层定义前的空行数**，需要「上一个非空行是什么」的上下文，所以要用 `enumerate` 配合索引回看。

**关键点 3：识别 `def`/`class` 行**用 `line.lstrip().startswith(("def ", "class "))`，但要排除缩进的（即只检查顶层的）。

**关键点 4：内置函数名检测**用 `keyword` 模块拿关键字，再用一个内置名集合比对。

**完整代码**：

```python
"""PEP 8 风格检查器 —— 挑战题参考实现。

用法：
    python style_checker.py 目标文件.py
    python style_checker.py examples/00_style_demo.py

只依赖标准库，检查 7 条 PEP 8 规则并给出评分。
"""

import builtins
import keyword
import sys
from pathlib import Path

# 规则参数集中定义为常量，方便调整和阅读
MAX_LINE_LENGTH = 88        # 单行最大字符数
REQUIRED_BLANK_LINES = 2   # 顶层定义前要求的空行数
DEDUCTION_PER_ISSUE = 5    # 每个问题扣多少分
MAX_DEDUCTION = 60         # 最多扣 60 分（不低于 40 分）

# 用 set 做 O(1) 查询；去掉下划线开头的私有名，减少误报
BUILTIN_NAMES = {
    name for name in dir(builtins)
    if not name.startswith("_")
}


class StyleIssue:
    """一条风格问题：记录行号、内容和说明。

    用 dataclass 会更简洁，但为了只依赖基础语法，这里手写一个普通类。
    """

    def __init__(self, line_no: int, content: str, rule: str, message: str):
        self.line_no = line_no
        self.content = content
        self.rule = rule
        self.message = message

    def __str__(self) -> str:
        """按「行号 → 内容 → 说明」的顺序输出，方便定位。"""
        preview = self.content if len(self.content) <= 50 else self.content[:47] + "..."
        return f"  第 {self.line_no:>4} 行 [{self.rule}] {self.message}\n         → {preview}"


def check_line_length(lines: list[str]) -> list[StyleIssue]:
    """规则①：检查单行长度是否超过 88 字符。"""
    issues = []
    for i, line in enumerate(lines, 1):
        if len(line) > MAX_LINE_LENGTH:
            issues.append(StyleIssue(
                i, line, "E501",
                f"行长 {len(line)} 字符，超过上限 {MAX_LINE_LENGTH}",
            ))
    return issues


def check_tab_indent(lines: list[str]) -> list[StyleIssue]:
    """规则②：检查是否使用了 Tab 缩进（必须全程使用空格）。"""
    issues = []
    for i, line in enumerate(lines, 1):
        # 只看行首部分：如果 Tab 出现在字符串内部则不算
        if line[: len(line) - len(line.lstrip())].count("\t"):
            issues.append(StyleIssue(
                i, line, "W191",
                "使用了 Tab 缩进，请改用 4 个空格",
            ))
    return issues


def check_trailing_space(lines: list[str]) -> list[StyleIssue]:
    """规则③：检查行尾是否有多余空格。"""
    issues = []
    for i, line in enumerate(lines, 1):
        if line != line.rstrip() and line.strip():
            issues.append(StyleIssue(
                i, line, "W291",
                "行尾有多余空格",
            ))
    return issues


def check_builtin_shadow(lines: list[str]) -> list[StyleIssue]:
    """规则④：检查变量名是否覆盖了内置函数或关键字。"""
    issues = []
    for i, line in enumerate(lines, 1):
        stripped = line.lstrip()
        # 跳过函数定义（def list(): 是合法的，虽然不推荐）和类定义
        if stripped.startswith(("def ", "class ")):
            continue
        for name in keyword.kwlist:            # 先查关键字，如 class / if
            if stripped.startswith(f"{name} =") or stripped.startswith(f"{name}="):
                issues.append(StyleIssue(
                    i, line, "E999",
                    f"'{name}' 是 Python 关键字，不能作变量名",
                ))
        for name in BUILTIN_NAMES:             # 再查内置函数，如 list / dict
            if stripped.startswith(f"{name} =") or stripped.startswith(f"{name}="):
                issues.append(StyleIssue(
                    i, line, "A001",
                    f"'{name}' 是内置函数名，改名可避免覆盖（如 {name}_user）",
                ))
    return issues


def check_star_import(lines: list[str]) -> list[StyleIssue]:
    """规则⑥：检查是否使用了 import * 通配导入。"""
    issues = []
    for i, line in enumerate(lines, 1):
        if line.lstrip().startswith("from ") and line.rstrip().endswith("import *"):
            issues.append(StyleIssue(
                i, line, "F403",
                "不要用 import *，请明确导入需要的名字",
            ))
    return issues


def check_blank_lines_before_top_level(lines: list[str]) -> list[StyleIssue]:
    """规则⑤：检查顶层 def/class 前是否有 2 个空行。

    ⚠️ 这里有个容易忽略的细节：如果定义上方紧贴着一段注释块，
    PEP 8 规定「注释属于它下面的定义」，所以 2 个空行要加在**注释块之前**。
    因此必须先跳过注释行再统计空行，否则会把合法的写法误报成错误。
    """
    issues = []
    for i, line in enumerate(lines, 1):
        stripped = line.lstrip()
        # 只检查顶层的 def/class（缩进的属于方法，要求只有 1 空行）
        if not (line.startswith(stripped) and stripped.startswith(("def ", "class "))):
            continue
        if i == 1:                        # 文件第一行，不检查
            continue

        # 关键一步：先向上越过紧贴的注释块，再统计空行
        index = i - 2                      # i-2 对应 1-based 的第 i-1 行
        while index >= 0 and lines[index].lstrip().startswith("#"):
            index -= 1

        blank_count = 0
        while index >= 0 and not lines[index].strip():
            blank_count += 1
            index -= 1

        if blank_count < REQUIRED_BLANK_LINES:
            issues.append(StyleIssue(
                i, line, "E302",
                f"顶层定义前需要 {REQUIRED_BLANK_LINES} 个空行，当前只有 {blank_count} 个",
            ))
    return issues


def check_missing_docstring(lines: list[str]) -> list[StyleIssue]:
    """规则⑦（选做）：检查顶层函数是否缺少 docstring。"""
    issues = []
    for i, line in enumerate(lines, 1):
        stripped = line.lstrip()
        # 只看顶层的 def，且要求是单行签名（多行签名不做判断，避免误报）
        if not (line.startswith(stripped) and stripped.startswith("def ")):
            continue
        if line.rstrip().endswith(":") and "__init__" not in line:
            # 看下一行是不是三引号 docstring
            if i < len(lines):
                next_line = lines[i].lstrip()
                if not next_line.startswith('"""'):
                    func_name = stripped[4:].split("(")[0].strip()
                    issues.append(StyleIssue(
                        i, line, "D103",
                        f"函数 {func_name}() 缺少 docstring",
                    ))
    return issues


# 把所有检查规则放进一个列表，主流程只需遍历调用
ALL_CHECKS = (
    ("E501 行长超限", check_line_length),
    ("W191 Tab 缩进", check_tab_indent),
    ("W291 行尾空格", check_trailing_space),
    ("A001 内置名覆盖", check_builtin_shadow),
    ("F403 import *", check_star_import),
    ("E302 空行不足", check_blank_lines_before_top_level),
    ("D103 缺少 docstring", check_missing_docstring),
)


def read_source(path: Path) -> str:
    """读取源码文件，对常见的读取异常给出清晰提示。

    Args:
        path: 目标文件路径。

    Returns:
        文件的文本内容。

    Raises:
        FileNotFoundError: 文件不存在。
        PermissionError: 没有读取权限。
        UnicodeDecodeError: 文件不是 UTF-8 编码。
    """
    # errors="strict" 是默认值，显式写出来是为了表明「编码问题要报错，不要乱码」
    with path.open("r", encoding="utf-8", errors="strict") as fp:
        return fp.read()


def check_file(path: Path) -> list[StyleIssue]:
    """对单个文件执行全部规则检查。

    Args:
        path: 待检查的 Python 文件路径。

    Returns:
        所有发现的问题列表，按行号排序。

    Raises:
        FileNotFoundError: 文件不存在。
        IsADirectoryError: 传入的是目录而不是文件。
        PermissionError: 没有读取权限。
        UnicodeDecodeError: 文件编码不是 UTF-8。
    """
    source = read_source(path)          # 异常直接向上传播，由 main 统一处理
    lines = source.splitlines()

    issues: list[StyleIssue] = []
    for rule_name, check_func in ALL_CHECKS:
        issues.extend(check_func(lines))  # 每个规则函数只返回自己发现的问题

    return sorted(issues, key=lambda x: (x.line_no, x.rule))


def format_report(path: Path, issues: list[StyleIssue], total_lines: int) -> str:
    """把检查结果格式化成可读报告文本。"""
    report = [
        "=" * 66,
        f"PEP 8 风格检查报告：{path.name}",
        "=" * 66,
        f"文件：{path.absolute()}",
        f"总行数：{total_lines}",
        "",
    ]
    if not issues:
        report.append("🎉 恭喜，没有发现任何风格问题！")
    else:
        report.append(f"发现 {len(issues)} 个问题：")
        report.append("")
        report.extend(str(issue) for issue in issues)
        report.append("")
        # 统计各规则的问题数
        by_rule: dict[str, int] = {}
        for issue in issues:
            by_rule[issue.rule] = by_rule.get(issue.rule, 0) + 1
        report.append("按规则分类统计：")
        for rule, count in sorted(by_rule.items(), key=lambda kv: -kv[1]):
            report.append(f"  {rule}: {count} 个")

    # 评分：每个问题扣 5 分，最多扣 60 分
    score = 100 - min(len(issues) * DEDUCTION_PER_ISSUE, MAX_DEDUCTION)
    report.append("")
    report.append(f"评分：{score} 分")
    if score >= 90:
        report.append("评价：✅ 风格良好，继续保持！")
    elif score >= 70:
        report.append("评价：⚠️ 有一些可改进的地方，建议按上方提示修改。")
    else:
        report.append("❌ 存在较多风格问题，建议先重构再继续写功能。")
    return "\n".join(report)


def main() -> None:
    """命令行入口：接收文件路径，执行检查并打印报告。"""
    if len(sys.argv) != 2:
        print(f"用法：python {Path(sys.argv[0]).name} 目标文件.py")
        print("示例：python style_checker.py examples/00_style_demo.py")
        return

    path = Path(sys.argv[1])
    try:
        issues = check_file(path)
        total_lines = len(read_source(path).splitlines())
    except FileNotFoundError:
        print(f"❌ 文件不存在：{path}")
        print(f"   当前目录：{Path.cwd()}")
        return
    except IsADirectoryError:
        print(f"❌ 这是一个目录，不是文件：{path}")
        return
    except PermissionError:
        print(f"❌ 没有读取权限：{path}")
        return
    except UnicodeDecodeError as exc:
        print(f"❌ 文件编码不是 UTF-8：{path}")
        print(f"   请用 VS Code 或记事本（选 UTF-8）重新保存。")
        print(f"   详细信息：{exc}")
        return

    print(format_report(path, issues, total_lines))


if __name__ == "__main__":
    main()
```

"""成绩处理模块：重命名后的规范写法。"""

# 阈值常量提到模块顶部，配一行业务说明
MAX_SCORE = 100
PASSING_THRESHOLD = MAX_SCORE / 2    # 及格线 = 满分的一半 = 60 分


def process_scores(chinese, math, english):
    """统计三科中超过及格线的分数总和与列表。

    Args:
        chinese: 语文成绩列表。
        math: 数学成绩列表。
        english: 英语成绩列表。

    Returns:
        含 total / other_passed 的字典。
    """
    total = 0
    for score in chinese:
        if score > PASSING_THRESHOLD:
            total += score

    # 直接遍历元素而不是用 range(len(...)) 取下标，Pythonic 且不易越界
    other_passed = [
        score
        for scores in (math, english)
        for score in scores
        if score > PASSING_THRESHOLD
    ]
    return {"total": total, "other_passed": other_passed}


class ScoreData:
    """封装一个学生的单科成绩。

    类名用 PascalCase（ScoreData），不是原来的小写 data。
    """

    def __init__(self, value):
        """初始化成绩。

        Args:
            value: 成绩数值。
        """
        self.value = value

    def get(self):
        """返回成绩。"""
        return self.value
