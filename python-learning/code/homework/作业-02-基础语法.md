# 作业 02：基础语法

## 作业说明

这份作业练的是「不查文档也能把 Python 写对」的基本功。

`02_basics/` 下六个文件覆盖的东西不多，但每一个都是「不真正理解就会一直写错」的知识点：

- **变量模型**：变量不是盒子，是贴在对象上的便利贴。名字绑定、动态类型、同一性（`id`）与相等（`==`）的区别、可变与不可变
- **运算符语义**：`and`/`or` 返回的是**操作数本身**而不是布尔值，`//` 是向下取整而不是向零截断，`+=` 对可变对象是原地修改、对不可变对象是重新绑定
- **字符串**：不可变带来的连锁约束（没有 `append`、切片返回新对象、驻留与 `is` 的陷阱）、三种格式化方式的取舍、f-string 进阶语法
- **分支**：`match-case` 的结构化匹配、解构一步到位、穷尽性检查、软关键字特性，以及它和 `if/elif` 各自的适用边界
- **循环**：`for-else` 的 `else` 不是「否则」而是「没有被打断」、`break` 只跳一层、嵌套循环的标志位模式
- **推导式**：列表/字典/集合推导式与生成器表达式、条件表达式与末尾 `if` 的位置语义差别、推导式的可读性边界

做完这份作业，你应当能：

- 在解释器里用实验**证明**一条语法规则，而不是背诵它
- 写出一段代码，能说出每个变量的类型、每个名字绑定到哪个对象、每个 `is` 判断的真假与依据
- 面对「用 `if/elif` 还是 `match`」「用推导式还是循环」这类问题，有可辩护的选择标准

本作业的题目刻意设计成**需要动手实验取证**的形式。只看不写，这块知识基本不会沉淀。

### 第 1 题：变量绑定实验台 ⭐☆☆

**题目描述**

新建 `q01_binding_lab.py`，用实验证明下面 6 个命题。**每条命题的输出必须包含可验证的证据**（`id()`、`type()`、`is` 的结果），不能只打印「是」或「否」。

需要验证的命题：

1. 赋值是**名字绑定**，不是把值复制到盒子；两个名字可以同时指向同一个对象
2. 同一个名字可以先后绑定到不同类型的对象，绑定时刻就完成了类型转换的"感知"
3. 小整数与短字符串存在驻留现象，`is` 判断为 `True` 并不代表「它们就是同一个语义对象」
4. `is` 与 `==` 在什么情况下会给出不同答案；对 `float('nan')` 用 `==` 和 `is` 分别判断是什么结果

6. 可变默认参数是「定义时求值一次」——请用实验证明参数默认值对象在多次调用之间是同一个对象

**输入/输出示例**

```
[命题 1] 名字绑定而非值复制

  alias = lst
  lst.append(4)
  id(lst) = 140234...  id(alias) = 140234...  (相同)
  alias is lst -> True
  两个名字看到的内容都是 [1, 2, 3, 4]
[命题 3] 驻留现象
  a = 256; b = 256      -> is = True
  a = 257; b = 257      -> is = False（但 == 为 True）
  a = "abc"; b = "abc"  -> is = True
  a = "".join(["a","b","c"]); b = "abc" -> is = False
[命题 4] is vs == 与 NaN
  [1, 2] == [1, 2] -> True      [1, 2] is [1, 2] -> False
  nan = float('nan')
  nan == nan -> False
  nan is nan -> True
[命题 5] 多重赋值求值顺序
  a = b = [] -> id(a) == id(b) -> True
  x, y = 1, 2; x, y = y, x -> (x, y) = (2, 1)
[命题 6] 可变默认参数
  连续调用三次后的默认参数内容: [[1], [1, 2], [1, 2, 3]]
  三次调用中默认参数的 id 全部相同 -> True

**题目描述**

新建 `q02_operator_lab.py`，用实测方式产出一张「运算符语义对照表」。**不允许凭记忆填表**，每个结论都要由代码跑出来。

7. 运算符优先级与结合性：至少 5 个「看起来应该从左往右、实际不是」的表达式，逐个打印实际结果并解释原因

**输入/输出示例**

```
[1] / 与 //
  7 / 3 = 2.3333333333333335   (类型 float)
  7 // 3 = 2                    (类型 int)
  -7 / 3 = -2.3333333333333335
  -7 // 3 = -3                  <- 向下取整，不是向零截断
  -7 % 3 = 2                    <- 结果符号跟随【除数】
  7 % -3 = -2                   <- 结果符号跟随【除数】
[3] += 的原地 vs 新建
  s = "ab"; id_before = id(s); s += "cd"; id_after = id(s)
  str:  id 相同 = False   内容 = abcd      <- 不可变，必须新建
  lst = [1]; id_before = id(lst); lst += [2]; id_after = id(lst)
  list: id 相同 = True    内容 = [1, 2]    <- 原地追加
[4] 链式比较
  1 < 5 < 10 -> True
  1 < x < 10 中 x=5 -> True
  存在让两者不等价的输入 -> 是（自己举例并验证）
[5] and/or 返回操作数
  'DEFAULT' or 'user' -> 'user'
  '' or 'DEFAULT'     -> 'DEFAULT'
  返回值类型 = str，不是 bool
[7] 优先级反直觉
  2 ** 3 ** 2 = 512      <- 右结合，(2**3)**2 = 64 不成立
  -2 ** 2 = -4          <- ** 比一元负号优先级高
  1 < 2 == 2 < 3 < 4 -> True
  True and 1 or 2 -> 1
  not 1 == 2 -> False    <- not 优先级低于 ==

**验收标准**

- [ ] 表中每一格的结论都由实际运行产生，代码里没有出现「写死期望值再比较」的伪验证

### 第 3 题：日志格式化流水线 ⭐⭐☆

**题目描述**

### 第 4 题：命令分发器（match-case 综合）⭐⭐☆

**题目描述**

新建 `q04_command_dispatcher.py`，用一个「迷你运维指令系统」把 `match-case` 的能力用满。

指令格式：`动作:参数1:参数2`（如 `restart:web-01:now`）。系统要支持以下动作：

| 动作 | 参数 | 含义 |
|---|---|---|
| `restart` | 服务名 + `now` / `sched` | 重启服务，可立即或排期 |
| `scale` | 服务名 + 副本数 | 扩缩容，副本数必须为正整数 |
| `deploy` | 服务名 + 版本号 | 发布，版本号需匹配特定格式 |
| `stop` | `all` / 服务名 | 停止全部或单个服务 |
| `query` | 服务名 | 查询状态 |

要求：

1. 用 `match-case` 实现分发，至少用到：字面量模式、结构化序列模式、映射模式、类模式、通配 `_`、捕获变量
2. 至少 3 个分支使用**守卫**（`if` 条件）
3. 至少 2 个分支使用 **or 模式**（`A | B` 合并匹配）

5. 输出一个**合法性报告**：对一组给定的（含合法与非法）指令，打印每条的处理结果或错误原因

**关键约束**：不要把 `match-case` 写成 `if/elif` 的语法糖翻译。要在注释或 README 中说明：哪一处用 `match` 比 `if/elif` 更简洁（省去了几次 `isinstance` 判断），哪一处 `match` 反而不如 `if/elif`（没有通配分支时缺少穷尽性保护）。

**验收标准**

- [ ] 至少 3 处使用了守卫，且每处守卫都改变了处理结果（不是摆设）

### 第 5 题：嵌套数据搜索器 ⭐⭐☆

**题目描述**

新建 `q05_nested_search.py`，实现一组在「多层嵌套数据」中搜索 / 校验 / 变换的工具函数。数据形如：

```python
data = {
    "users": [
        {"id": 1, "name": "张三", "tags": ["admin", "active"],
         "profile": {"age": 30, "city": "北京", "contact": {"email": "z@ex.com"}}},
        {"id": 2, "name": "李四", "tags": ["user"],
         "profile": {"age": 25, "city": "上海", "contact": {"email": "l@ex.com"}}},
    ],
    "meta": {"total": 2, "generated": "2026-01-15"}
}
```

需要实现：

| 函数 | 职责 |
|---|---|
| `find_by_key(data, value)` | 深度优先搜索，找到包含指定 `id` 的那个用户字典，返回它 |
| `collect_values(data, key)` | 递归收集所有指定键的所有值，返回扁平列表 |
| `filter_users(data, predicate)` | 按条件筛选用户，`predicate` 是接收用户字典返回布尔的函数 |
| `map_users(data, func)` | 对每个用户应用 `func` 并返回新结构（**原数据不能被修改**） |
| `validate(data)` | 校验结构完整性，返回缺失字段的清单 |
| `flatten(data)` | 把嵌套结构拍平为 `{点分路径: 值}` 形式，如 `users.0.profile.city` |

**关键约束**：

1. `collect_values` 与 `flatten` 必须是**递归**实现，且要处理「值本身是列表」与「值是字典」两种不同情况，不能只处理一层
2. `map_users` 必须保证**不修改原数据**，验证方式是把 `data` 的深拷贝与原数据逐字段比对
3. `filter_users` 的 `predicate` 必须是调用方传入的函数，你不能写死过滤条件

**输入/输出示例**

```
$ python q05_nested_search.py
[1] find_by_key(id=2) -> {'id': 2, 'name': '李四', ...}
[2] collect_values('city') -> ['北京', '上海']
    collect_values('email') -> ['z@ex.com', 'l@ex.com']
    collect_values('name') -> ['张三', '李四']
[3] filter_users(age>26)
    -> ['张三']
[4] map_users(取名字首字母)
    -> ['z', 'l']
    原数据未被修改 -> True   （逐字段深比对证据）
[5] validate(删除某个 contact 之后)
    缺失字段清单 -> ['users.1.profile.contact.email']
[6] flatten 输出的键（前 6 个）
    users.0.id, users.0.name, users.0.tags.0, users.0.tags.1, users.0.profile.age, users.0.profile.city
```

### 需要回看的文档章节

- **变量与类型**：把「可变/不可变」这个属性和「引用/值」这个模型彻底分开。想清楚：一个不可变对象为什么可以安全地在多线程间共享，一个可变对象为什么不能
- **运算符**：整理一张「Python 与 C 的运算符差异表」，重点标出 `//`、`%`、`and/or`、链式比较这四个。这一张表用一次，终身受用
- **字符串**：理解为什么 f-string 是当前首选（性能 + 可读性 + 不需要转义），以及它相比 `%` 和 `.format()` 的具体改进点在哪
- **分支**：记住 `match` 不是「更酷的 if」，它的价值在于**解构与匹配同步完成**。如果你的场景不需要解构，`if/elif` 更清晰
- **循环**：理解 `for` 面向「可迭代对象」而非下标，这是它能遍历文件、字典、生成器的原因。理解 `while` + `break` 就是 do-while
- **推导式**：记住它的边界——一层过滤/一层映射时最清晰，超过两层就该换回循环或辅助函数。这不是风格偏好，是可读性硬约束

### 延伸思考（不做要求，但值得想）
