# 作业 03：容器

## 作业说明

这份作业练的是「选对盒子」的能力。

`02_basics` 解决了「单个值怎么算」，`03_containers` 解决「一堆值怎么装、怎么找、怎么改」。这一模块的核心不是背 API，而是**工程判断力**：

- 需求来了，用 `list` 还是 `set`？依据是什么？复杂度差多少？
- 什么时候 `dict` 比 `list` 更合适，什么时候反过来？
- 为什么「去重」这件事用 `set` 比用 `list` 快一个数量级？
- 嵌套结构怎么设计才不会在第二次修改时崩溃？

配套文件覆盖：list 的增删改查与浅深拷贝、tuple 的不可变性与解包、set 的四种运算与哈希原理、dict 的遍历方式与有序性、`collections` 五大工具类（`namedtuple` / `deque` / `Counter` / `ChainMap` / `OrderedDict`）、以及四种容器的选型决策与 `timeit` 性能实测。

做完这份作业，你应当能：

- 拿到一个需求，10 秒内说出该用什么容器，并给出复杂度依据
- 说清 `sort()` 与 `sorted()`、`remove()` 与 `pop()`、浅拷贝与深拷贝的**本质区别**（不是 API 层面的区别）
- 解释「为什么 `set` 去重快」到哈希表桶与冲突处理的程度
- 用 `deque`、`Counter`、`ChainMap`、`namedtuple` 写出真实场景的代码，而不是「知道有这个东西」

**本作业有 3 道性能实测题**（第 2、3、8 题）。实测数据必须来自你自己的机器，不要抄文档里的数字。文档里的数据是在别人机器上、别人输入规模下测的，抄过来毫无意义。

### 第 1 题：列表的十种修改方式与它们的返回值 ⭐☆☆

**题目描述**

新建 `q01_list_lab.py`，系统性地验证 list 的修改类 API。重点不在「会用」，而在「每个方法**返回什么**」和「原对象有没有被改」。

需要实测并打印的 API：

| 分组 | 方法 |
|---|---|
| 增 | `append` / `extend` / `insert` / `+` / `*` |
| 删 | `remove` / `pop` / `del` / `clear` |
| 改 | 单元素赋值 / 切片赋值（长度不一致） |
| 排 | `sort()` / `sorted()` / `reverse()` / `reversed()` |

对每个 API，打印四项信息：

1. **返回值**（注意：很多返回 `None`，这是高频坑）
2. **原列表是否被修改**（用操作前后的 `id()` 与内容比对证明）
3. **操作后的内容**
4. **一个「如果我以为它返回了新对象」就会写错的误用示例**

**必须单独验证的高频陷阱**：

- `remove()` 按值删除（不存在则抛 `ValueError`）vs `pop()` 按位置删除（越界抛 `IndexError`，无参数时弹末尾）
- `list + list` 创建新对象 vs `list += other` 原地追加（用 `id()` 证明）
- `sort()` 原地排序返回 `None` vs `sorted()` 返回新列表
- `reversed()` 返回的是**迭代器**不是列表
- 用一个嵌套三层列表，分别用 `[:]`、`copy.copy()`、`copy.deepcopy()` 做浅/深拷贝，打印三层各自的修改影响

**输入/输出示例**

```
$ python q01_list_lab.py
=== 增 ===
API          返回值        原列表被改  原列表id不变
append       None         True       True
extend       None         True       True
insert       None         True       True
+            [3, 4, 5]    False      False
+=           None         True       True
=== 删 ===
remove       None         True       True      (值不存在时抛 ValueError)
pop          3            True       True      (越界抛 IndexError)
del          None         True       True
clear        None         True       True
=== 排 ===
sort()       None         True       True
sorted()     [1, 2, 3]    False      True
reverse()    None         True       True
reversed()   <list_reverse_iterator object>  False  True
=== 切片赋值（长度可不一致）===
原: [1, 2, 3, 4, 5]
lst[1:3] = ['a']      -> [1, 'a', 4, 5]        长度 5 -> 3
lst[1:1] = ['b', 'c'] -> [1, 'b', 'c', 'a', 4, 5]  长度 3 -> 5
=== 拷贝对比（三层嵌套）===
原数据 layers[0][0][0] = 1
[:] 浅拷贝后改 layers[0][0][0] = 99
  原数据受影响 = True    （因为内层是同一个对象）
deepcopy 后改 layers[0][0][0] = 99
  原数据受影响 = False
```

**验收标准**

- [ ] 每个 API 都打印了「返回值 / 原列表是否被改 / 原列表 id 是否变」三项，且 `id()` 比对真实存在
- [ ] `remove` 与 `pop` 的两种异常都被实际触发并捕获（`ValueError` 与 `IndexError` 各一次）
- [ ] `+` 与 `+=` 的 `id()` 差异有实测证据
- [ ] 切片赋值中「长度可不一致」的正反两个方向都演示了（原列表变长、变短）
- [ ] 浅拷贝 / 深拷贝用三层嵌套数据演示，且分别打印了「改哪一层影响谁」
- [ ] 每一组都附带了「如果误以为返回新对象会写错的代码」及该代码的错误表现

**涉及知识点**

`append / extend / insert`、`remove / pop / del / clear`、`+ 与 += 的原地语义`、`切片赋值`、`sort / sorted / reverse / reversed`、`稳定排序与 key`、`浅拷贝 vs 深拷贝`、`copy 模块`、`切片返回新对象`、`list 别名（引用同一对象）`

### 第 2 题：集合运算与权限模型（性能实测） ⭐⭐☆

**题目描述**

新建 `q02_set_lab.py`，用集合运算解决一个真实的「权限系统」问题，并在过程中完成性能实测。

**Part A — 权限模型**

给定三类角色的权限集合：

```python
ROLES = {
    "guest":      {"read_public"},
    "user":       {"read_public", "read_private", "comment"},
    "editor":     {"read_public", "read_private", "comment", "edit"},
    "admin":      {"read_public", "read_private", "comment", "edit", "delete", "manage_user"},
}
```

实现以下查询，每条都用集合运算（运算符或等价方法二选一，但需说明选择理由）：

1. `editor` 独有的权限（其他角色都没有的）
2. `editor` 与 `admin` 的交集、差集、对称差集
3. `admin` 是 `editor` 的超集吗
4. 三个人 `guest`、`user`、`admin` 的**并集**（他们合起来能做什么）
5. `admin` 减去 `editor` 后还剩什么（这组「剩余权限」应该恰好等于"最高权限减去次高权限"）
6. 权限从 `editor` **升级**到 `admin` 时，哪些权限被新增（提示：需要考虑权限的**传递**关系，即 admin 拥有 editor 的全部权限吗？）

**Part B — 性能实测**

7. 用 `timeit` 实测：把 100 万个整数放进 `list` 去重 vs 放进 `set` 去重，打印耗时与倍数关系
8. 实测：在一个 100 万元素的 `list` 里查找一个存在的元素 vs 在同样元素的 `set` 里查找
9. 实测：`set` 的运算符形式 `a & b` vs 方法形式 `a.intersection(b)`，在 10 万元素规模下的耗时差异，并解释为什么会有差异（是每次新建集合还是别的）

**Part C — 原理探究**

10. 输出一段「哈希查找原理」的实测过程：对若干个整数，展示 `hash(值)` 的结果、它们在 `set` 中的分布、以及发生哈希冲突时的表现
11. 实测 `frozenset` 作为 `dict` 的 key 是否可行，而 `set` 是否不可行，并解释原因

**输入/输出示例**

```

[2] 交集:   {'read_public', 'read_private', 'comment', 'edit'}
```

**题目描述**

下面这段代码是一个「配置解析器」，负责从多层嵌套的配置里取值。作者在开发环境测试通过，但上线后陆续出现两类事故：一类是取不到值时返回了「奇怪的东西」，另一类是改配置时意外改到了别的地方。

```python
DEFAULTS = {"timeout": 30, "retry": {"count": 3, "delay": 1}, "debug": False}
CURRENT = DEFAULTS.copy()


def get(path, config=None):
    if config is None:
        config = CURRENT
    parts = path.split(".")
    node = config
    for i, p in enumerate(parts):
        if p in node:
            node = node[p]
        else:
            return DEFAULTS.get(p)
    return node


def set_value(path, value, config=None):
    if config is None:
        config = CURRENT
    parts = path.split(".")
    node = config
    for p in parts[:-1]:
        node = node[p]
    node[parts[-1]] = value


def merge(base, override):
    result = base.copy()
    for k, v in override.items():
        if k in result and isinstance(result[k], dict) and isinstance(v, dict):
            result[k] = merge(result[k], v)
        else:
            result[k] = v
    return result


def validate(config):
    errors = []
    for key in ["timeout", "retry", "debug"]:
        if key not in config:
            errors.append("缺少必需配置: " + key)
    if "timeout" in config and not isinstance(config["timeout"], int):
        errors.append("timeout 必须是整数")
    if config["debug"] == True:
        print("调试模式已开启")
    return errors


def flatten_config(config, prefix=""):
    result = {}
    for k, v in config.items():
        key = prefix + "." + k if prefix else k
        if isinstance(v, dict):
            flatten_config(v, key, result)
        else:
            result[key] = v
    return result


def diff(old, new):
    keys = list(old.keys()) + list(new.keys())
    changes = {}
    for k in keys:
        if old.get(k) != new.get(k):
            changes[k] = (old.get(k), new.get(k))
    return changes


print(get("retry.count"))
print(get("retry.count", {"retry": {"count": 99}}))
set_value("retry.delay", 5)
print(DEFAULTS)
print(flatten_config(DEFAULTS))
print(diff(DEFAULTS, CURRENT))
print(validate(DEFAULTS))
```
