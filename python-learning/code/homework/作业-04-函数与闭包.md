# 作业 04：函数与闭包

## 作业说明

这份作业练的是「把逻辑拆成函数」以及「理解函数背后的机制」。

前面三个模块解决的是「值」和「容器」，从这里开始解决「行为」。`04_functions/` 六个文件覆盖的内容，是 Python 与 C/Java 差异最大、也最容易凭直觉写错的地方：

- **参数设计**：位置参数、默认参数、`*args`、`**kwargs`、仅位置参数 `/`、仅关键字参数 `*`，以及它们强制的书写顺序规则
- **作用域与闭包**：LEGB 四层查找、`global` / `nonlocal`、闭包的本质是「函数 + 自由变量的环境」、循环里的晚绑定陷阱
- **装饰器**：本质就是 `func = wrapper(func)`；带参数的装饰器需要三层嵌套；`functools.wraps` 为什么必须用；多装饰器的应用顺序
- **递归**：三要素、调用栈、记忆化、Python 的递归深度限制与 `RecursionError`
- **lambda 与类型注解**：`lambda` 只能写一个表达式、排序 `key` 的用法、`TypedDict` / `Protocol` / `ParamSpec` / `TypeVar`
- **`*args` / `**kwargs` 深入**：形参侧的打包 vs 实参侧的解包、参数转发、透明装饰器、`inspect.signature`

**这一模块的学习方法建议与其他模块不同**：不要背 API，要**画图**。作用域问题画作用域链图，闭包问题画「谁引用了谁」的引用图，装饰器问题画「函数对象被替换」的赋值图。画出来就懂了，讲不清楚就是没懂。

做完这份作业，你应当能：

- 独立设计一个函数签名，说清楚每个参数为什么在那里、为什么是这个形式
- 解释任意一段代码的作用域行为，包括 `global` / `nonlocal` 到底改了什么
- 手写三种装饰器（无参、带参、类装饰器），并解释每一层嵌套的作用
- 识别一段代码中所有的高频陷阱，并说明成因

### 第 1 题：函数签名设计工坊 ⭐☆☆

### 第 3 题：装饰器工具箱 ⭐⭐☆

**题目描述**

新建 `q03_decorators.py`，实现一套生产级的装饰器工具箱。每个装饰器都要有对应的「使用场景」演示。

### 必须实现的装饰器

| 装饰器 | 职责 | 必须展示的行为 |
|---|---|---|
| `log_calls` | 记录函数被调用的参数与返回值 | 装饰前后 `__name__` 的变化（`functools.wraps` 是否生效） |
| `timer` | 统计函数耗时（用 `time.perf_counter`） | 连续两次调用的耗时对比，第二次因为缓存而更短 |
| `retry` | 失败自动重试 N 次，带指数退避 | 前 2 次失败第 3 次成功的完整过程；以及全部失败的输出 |
| `require_args` | 参数校验装饰器（门卫模式） | 校验失败时的自定义错误类型；校验通过的路径 |
| `cache_result` | 基于 `lru_cache` 的记忆化 | `cache_info()` 的 `hits` / `misses` 随调用变化 |
| `rate_limit` | 限流装饰器：N 秒内最多调用 M 次 | 超限时的行为（抛异常 or 返回默认值，需说明选择理由） |
| `deprecated` | 标记废弃，调用时告警 | 未废弃函数的对比；`warnings` 输出的实际内容 |

### 必须覆盖的技术点

1. **`functools.wraps` 的必要性**：写一个**不使用** `wraps` 的版本与使用 `wraps` 的版本，对比 `__name__`、`__doc__`、`__qualname__`、`__wrapped__` 四个属性的差异
2. **三层嵌套**：带参数的装饰器（`retry(max_times=3, delay=0.1)`）必须实现三层嵌套，并在注释里画清楚每一层各是什么
3. **参数校验装饰器的通用性**：实现一个「可配置的校验装饰器」，支持 `require_args(int, str)` 与 `require_args(name=str)` 两种调用形式
4. **多装饰器顺序**：给一个函数叠加 3 个装饰器，验证应用顺序，并打印出装饰顺序的推理过程（不要只给结论，要给出「等价于 `f = d1(d2(d3(f)))`」的推导）
5. **装饰器 + 递归**：把 `retry` 与 `cache_result` 叠加到一个递归函数上，观察效果
6. **装饰器 + `ParamSpec`**：写一个带 `ParamSpec` 注解的装饰器，用 `reveal_type` 或 `__annotations__` 证明它保留了被装饰函数的签名
7. **类装饰器**：实现一个类装饰器（如 `add_repr_method`），给类动态添加一个方法，并说明类装饰器与函数装饰器的本质区别

**输入/输出示例**

```

调用: add(3, 4) -> 7
log_calls 装饰的函数名: add        (wraps 生效)
=== 不使用 wraps 的版本 ===
装饰前 __name__ = add, 装饰后 __name__ = wrapper
__doc__ 被覆盖: True
__wrapped__ 是否存在: False
=== retry(3, 0.05) ===
第 1 次尝试: 失败 (连接超时)
第 2 次尝试: 失败 (连接超时)
第 3 次尝试: 成功 -> 'data'
总耗时（含退避）: 0.104 s
=== cache_result ===
cache_info: CacheInfo(hits=0, misses=1, maxsize=128, currsize=1)
再次调用后: CacheInfo(hits=1, misses=1, maxsize=128, currsize=1)
=== 多装饰器顺序 ===
源码顺序（自上而下）:
  @d1
  @d2
  @d3

        else:
            result[k] = v
    return result


def find_value(data, key):
    if key in data:
        return data[key]
    for k, v in data.items():
        if isinstance(v, dict):
            found = find_value(v, key)
            if found is not None:
                return found
    return None


def count_leaves(data):
    if isinstance(data, dict):
        count = 0
        for v in data.values():
            count += count_leaves(v)
        return count
    else:
        return 1


def safe_json_loads(text):
    return json.loads(text)
```
