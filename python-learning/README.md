# Python 系统学习体系（从零到工程实践）

> 这是一套**自成体系、不依赖任何既有代码**的 Python 学习资料。全部内容按「环境 → 语言基础 → 工程能力 → 并发 → 生态」的顺序组织，每一节都有可运行代码、易错点、自测题。

---

## 一、这套体系怎么用

1. **严格按编号顺序学**，不要跳。01→04 是地基，05 之后都是建立在地基上的。
2. **每篇文档的顺序**：学习目标 → 概念讲解 → 可运行示例 → 易错点 → 本节小结 → 自测题。
3. **自测题必须做**，答案先自己写再看（答案折叠在 `<details>` 里）。做不出 70% 不要往下走。
4. **代码必须自己敲一遍**，不要复制粘贴。看懂 ≠ 会写。
5. **练习题**（`exercises/`）和**项目**（`projects/`）是检验学习成果的地方，光看文档学不会。

## 四、四阶段学习路线

### 阶段一：语言地基（01–04，约 4 周）
每天 1.5–2 小时，目标是能**不看资料写出 100 行以内的完整小程序**。

- 第 1 周：01 环境 + 02 语法
- 第 2 周：02 语法刷完 + 03 容器
- 第 3 周：04 函数 + 练习题 1、2
- 第 4 周：03 + 04 复习，自测题全部重做一遍

**阶段验收**：完成 `exercises/阶段1-基础语法练习.md` 和 `阶段2-数据结构练习.md`，正确率 ≥ 80%。

### 阶段二：工程能力（05–08，约 4 周）
目标是能写**多文件、有异常处理、会读写文件**的中小型程序。

- 第 5 周：05 模块包 + 06 面向对象
- 第 6 周：07 异常调试 + 08 文件 IO
- 第 7–8 周：完成 `projects/P1`、`P2`，阶段三、四练习题

**阶段验收**：`P1` 和 `P2` 两个项目能完整跑通，代码用 ruff 检查无 error。

### 阶段三：进阶能力（09–11，约 3 周）
目标是写出**高效、可读、有类型标注**的代码。

- 第 9 周：09 函数式与装饰器
- 第 10 周：10 并发编程
- 第 11 周：11 标准库精讲 + 12 的 ruff/mypy/pytest 部分

**阶段验收**：把 `P2` 重构一遍：加类型注解、加 pytest、写 docstring、过 ruff。

### 阶段四：工程化与实战（12 + 项目，约 3 周）
目标是具备**团队协作和线上交付**能力。

- 第 12 周：12 生态与工程实践（工程规范、测试、Git）
- 第 13 周：`P3` API 数据聚合与可视化
- 第 14 周：`P4` 异步爬虫 + 全面复盘

**阶段验收**：`P3`/`P4` 独立完成，有 README、有测试、有 .gitignore。

## 五、每日学习节奏（建议）

| 时段 | 内容 | 时长 |
|---|---|---|
| 前 30 分钟 | 读当节文档，敲一遍示例 | 30 min |
| 中间 40 分钟 | 做练习题，不看答案 | 40 min |
| 后 20 分钟 | 整理笔记：写下今天学到的 5 个「原来是这样」 | 20 min |
| 每周 1 次 | 回看本周所有自测题，重做错题 | 30 min |

**不要一次学超过 2 小时新内容**，Python 前两周的语法密度足以消化一整天。

## 六、常见的学习误区（避开就是省时间）

1. **不要从爬虫入门**。爬虫会让你误以为学会了 Python，其实你只学会了 requests 的用法。
2. **不要一上来搞 OOP**。先把过程式代码写熟练，类和装饰器是第 2 阶段的事。
3. **不要只看不敲**。手写 20 行代码的记忆效果远超读 200 行。
4. **不要追新**。Python 3.12 的新特性不影响你学习基础，别在语法细节上纠缠。
5. **不要跳过练习题**。文档是让你「看懂」，练习题才是让你「会做」。
6. **不要怕报错**。看 traceback 是 Python 开发者的核心生存技能，07 模块专门讲这个。
7. **不要用 Python 2 的老教程**。print 函数、类定义、异常语法都是 Python 3 的写法。

## 八、怎么检验自己学成了

学完四个阶段后，你应该能独立做到：

- [ ] 不查资料写出带类型注解、用装饰器、有异常处理的函数
- [ ] 用 pytest 为自己的代码写测试，覆盖率 ≥ 70%
- [ ] 用 asyncio 并发抓取 50 个网页并正确处理超时和重试
- [ ] 解释 GIL 是什么，以及什么时候该用多进程而不是线程
- [ ] 用 ruff + mypy + pre-commit 把关提交质量
- [ ] 独立设计并实现一个 500 行以上的项目，有 README、有测试、有异常处理

能打勾的项越多，说明越接近「能干活」的水平。
