## 一、类与实例

```python
class Dog:
    """一条狗。"""

    species = "犬"          # 类属性（所有实例共享）

    def __init__(self, name, age):
        self.name = name    # 实例属性（赋值即创建在实例 __dict__ 中）
        self.age = age

    def bark(self):
        """实例方法。"""
        return f"{self.name} 说：汪汪！"

    def __repr__(self):
        return f"<Dog {self.name}>"


d1 = Dog("旺财", 3)
d2 = Dog("小黑", 5)
print(d1.bark())          # 预期输出: 旺财 说：汪汪！
print(d1.species)         # 预期输出: 犬
print(d1.__dict__)        # 预期输出: {'name': '旺财', 'age': 3}
```

### 1.1 `self` 不是关键字

`self` 只是**约定俗成的第一个参数名**，由解释器在 `obj.method(...)` 调用时自动传入。

```python
d1.bark()             # 等价于 Dog.bark(d1)
```

写成别的名字也能运行，但会破坏生态（所有第三方库、文档、IDE 补全都按 `self` 约定）。

### 1.2 类属性 vs 实例属性（面试高频）

| | 类属性 | 实例属性 |
| --- | --- | --- |
| 定义位置 | 类体内直接赋值 | 任意 `self.x = ...` |
| 存储位置 | 类的 `__dict__` | 实例的 `__dict__` |
| 共享性 | 所有实例共享一份 | 每个实例独立 |
| 访问 | `Dog.species` 或 `d1.species` | 只能 `d1.name` |

**关键坑：实例属性遮蔽类属性。**

```python
d1.species = "猫"       # 创建了实例属性，遮蔽了类属性
print(d1.species)      # 预期输出: 猫
print(d2.species)      # 预期输出: 犬（不受影响）
print(Dog.species)     # 预期输出: 犬（类属性没变）
del d1.species         # 删除实例属性
print(d1.species)      # 预期输出: 犬（回落到类属性）
```

**可变类属性的陷阱：**

```python
class BadCounter:
    items = []          # 危险！所有实例共享同一个列表

class GoodCounter:
    def __init__(self):
        self.items = []  # 正确
```

结论：**可变默认值一律放 `__init__` 里创建，不要放在类属性位置。**

## 二、三种方法

```python
class MathUtil:
    PI = 3.1415926

    @staticmethod
    def add(a, b):
        """静态方法：不依赖类也不依赖实例，用作工具函数。"""
        return a + b

    @classmethod
    def from_pi(cls, value):
        """类方法：第一个参数是类，常用于构造器工厂。"""
        obj = cls()
        obj.area = value ** 2 * cls.PI
        return obj

    def instance_method(self):
        """实例方法：操作实例状态。"""
        return f"实例方法, PI={self.PI}"


print(MathUtil.add(1, 2))        # 预期输出: 3
print(MathUtil.from_pi(2).area)  # 预期输出: 12.5663704
print(MathUtil.PI)               # 预期输出: 3.1415926（类属性可直接访问）
```

调用方式上的关键区别：

```python
MathUtil.add(1, 2)             # OK，静态方法不传 self/cls
MathUtil().add(1, 2)           # 也 OK，但语义奇怪，不推荐
MathUtil.from_pi(2)            # OK
MathUtil().from_pi(2)          # 也 OK，cls 会被自动绑定为类型
```

**面试题：子类继承时，类方法的 `cls` 指向谁？** 指向**实际调用的那个子类**，这正是"类方法做构造器工厂"能支持继承的原因：

```python
class Circle(MathUtil):
    pass

c = Circle.from_pi(3)
print(type(c))     # 预期输出: <class '__main__.Circle'>，不是 MathUtil
```

## 三、`@property`：把方法伪装成属性

```python
class Rectangle:
    def __init__(self, width, height):
        self._width = width
        self._height = height

    @property
    def width(self):
        """读取时执行的逻辑。"""
        return self._width

    @width.setter
    def width(self, value):
        if value <= 0:
            raise ValueError("宽度必须为正数")
        self._width = value

    @property
    def area(self):
        """只读属性：没有 setter，写入会报 AttributeError。"""
        return self._width * self._height

    @width.deleter
    def width(self):
        self._width = 0


r = Rectangle(3, 4)
print(r.width)          # 预期输出: 3
r.width = 5
print(r.area)           # 预期输出: 20
try:
    r.area = 100
except AttributeError as e:
    print("不能赋值:", e)   # 预期输出: 不能赋值: property 'area' of 'Rectangle' object has no setter
try:
    r.width = -1
except ValueError as e:
    print(e)             # 预期输出: 宽度必须为正数
del r.width
print(r.width)          # 预期输出: 0
```

**为什么用 property 而不是直接暴露属性？**

- 可以在读取时做惰性计算（`area` 每次随 width 变化）；
- 可以在写入时校验；
- 对调用方来说语法跟普通属性一样，接口保持稳定。

## 四、继承与 MRO

```python
class Animal:
    def __init__(self, name):
        self.name = name

    def speak(self):
        return "..."

    def describe(self):
        return f"{self.name}: {self.speak()}"


class Dog(Animal):
    def speak(self):
        return "汪汪"


class Cat(Animal):
    def speak(self):
        return "喵喵"
```

### 4.1 多态（duck typing 在继承体系中的体现）

```python
for pet in (Dog("旺财"), Cat("咪咪")):
    print(pet.describe())
# 预期输出:
# 旺财: 汪汪
# 咪咪: 喵喵
```

`describe` 只写在 `Animal` 里一次，却自动适配子类行为 —— 这就是多态。

### 4.2 MRO：方法解析顺序

多继承时，Python 用 **C3 线性化算法** 计算 MRO，可以用 `__mro__` 查看。

```python
class A:
    def who(self):
        return "A"

class B(A):
    def who(self):
        return "B -> " + super().who()

class C(A):
    def who(self):
        return "C -> " + super().who()

class D(B, C):
    pass

print(D.__mro__)
# 预期输出:
# (<class 'D'>, <class 'B'>, <class 'C'>, <class 'A'>, <class 'object'>)

print(D().who())
# 预期输出: B -> C -> A
```

规则：**深度优先、保持父类相对顺序、每个类只出现一次**。

### 4.3 `super()` 的真相

面试常考点：**`super()` 不是"调用父类"，而是"调用 MRO 中下一个类"。**

```python
class D(B, C):
    def who(self):
        return "D -> " + super().who()

print(D().who())   # 预期输出: D -> B -> C -> A
```

多继承里，`super().who()` 走的是 `B` 之后的那一个（即 `C`），不是"B 的父类 A"。这就是为什么"每个 `__init__` 都调 `super().__init__()`"能正确地把参数链式传递下去，且不会漏掉任何类。

### 4.4 正确的 `__init__` 链式调用

```python
class Base:
    def __init__(self, a):
        self.a = a
        print("Base.__init__")

class Mid(Base):
    def __init__(self, a, b):
        super().__init__(a)      # 注意：不要写 Base.__init__(self, a)
        self.b = b
        print("Mid.__init__")

class Leaf(Mid):
    def __init__(self, a, b, c):
        super().__init__(a, b)
        self.c = c
        print("Leaf.__init__")

Leaf(1, 2, 3)
# 预期输出（自下而上）:
# Base.__init__
# Mid.__init__
# Leaf.__init__

print(Leaf(1, 2, 3).__dict__)
# 预期输出: {'a': 1, 'b': 2, 'c': 3}  —— 每个属性只被设置一次
```

**为什么不要 `Base.__init__(self, a)`？** 它会跳过 MRO 中可能存在的其他类（混入的 Mixin、协作继承类），导致初始化不完整。

## 五、组合优于继承

```python
# 继承版：has-a 关系被硬塞进 is-a
class Engine:
    def start(self):
        return "引擎启动"

class Car(Engine):          # Car 并不是一种 Engine
    pass

# 组合版（推荐）
class Car:
    def __init__(self, engine):
        self.engine = engine     # has-a

    def start(self):
        return self.engine.start() + "，汽车就绪"

print(Car(Engine()).start())    # 预期输出: 引擎启动，汽车就绪
```

组合的优势：

- 运行期可替换部件（把 `Engine` 换成 `ElectricEngine`），继承做不到；
- 避免继承带来的强耦合与 MRO 复杂度；
- 类层次扁平，易测试。

**实践建议**：能用组合就用组合；只有在真的 is-a（子类可以直接替代父类而不破坏 LSP）时才继承。

## 六、魔术方法（特殊方法 / dunder）

魔术方法让自定义类支持 Python 的内建语法。注意：**应该用 `__` 前后双下划线**，而不是单下划线或驼峰（如旧式 `__str__` 之外不要自己发明 `__str__` 命名）。

### 6.1 对象表示

```python
class Point:
    def __init__(self, x, y):
        self.x = x
        self.y = y

    def __repr__(self):
        # 面向开发者：应该像可以 eval 回来的表达式
        return f"Point({self.x}, {self.y})"

    def __str__(self):
        # 面向用户：可读性优先
        return f"({self.x}, {self.y})"

p = Point(1, 2)
print(p)          # 预期输出: (1, 2)   —— 走 __str__
print(repr(p))    # 预期输出: Point(1, 2) —— 走 __repr__
print(f"{p}")     # 预期输出: (1, 2)   —— format/__format__ 回落到 __str__
print(f"{p!r}")   # 预期输出: Point(1, 2)
```

规则：**只定义 `__repr__` 就够用**，`__str__` 默认回落到 `__repr__`。

### 6.2 相等性：`__eq__` 与 `__hash__`

Python 中 `==` 默认是**身份比较**（同一个对象）。

```python
class Item:
    def __init__(self, name, price):
        self.name = name
        self.price = price

    def __eq__(self, other):
        if not isinstance(other, Item):
            return NotImplemented     # 重要：让 Python 尝试对方的 __eq__
        return (self.name, self.price) == (other.name, other.price)

    def __hash__(self):
        # 定义 __eq__ 必须同时定义 __hash__，否则对象不可哈希
        return hash((self.name, self.price))


a, b = Item("笔", 3), Item("笔", 3)
print(a == b)              # 预期输出: True
print(a is b)              # 预期输出: False
print(len({a, b}))         # 预期输出: 1（哈希一致，去重生效）
print(a == "不是 Item")      # 预期输出: False
```

**规则：定义了 `__eq__` 就必须定义 `__hash__`。若对象不可变可以 `__hash__ = None` 显式声明不可哈希。**

### 6.3 容器协议

```python
class Playlist:
    def __init__(self, songs):
        self._songs = list(songs)

    def __len__(self):
        """支持 len(playlist)。"""
        return len(self._songs)

    def __getitem__(self, index):
        """支持 playlist[0]、playlist[1:3]，也是迭代协议的基础。"""
        return self._songs[index]

    def __setitem__(self, index, value):
        self._songs[index] = value

    def __contains__(self, item):
        """支持 `in` 操作，比默认的逐个 __getitem__ 更快。"""
        return item in self._songs

    def __iter__(self):
        """支持 for 循环。写了它就不需要再写 __next__。"""
        return iter(self._songs)

    def __add__(self, other):
        """支持 playlist + playlist。"""
        if not isinstance(other, Playlist):
            return NotImplemented
        return Playlist(self._songs + other._songs)

    def __repr__(self):
        return f"Playlist({self._songs!r})"


pl = Playlist(["A", "B", "C"])
print(len(pl))            # 预期输出: 3
print(pl[0])              # 预期输出: A
print(pl[-1])             # 预期输出: C
print(pl[1:])             # 预期输出: ['B', 'C']
print("B" in pl)          # 预期输出: True
print([s for s in pl])    # 预期输出: ['A', 'B', 'C']
print(pl + Playlist(["D"]))  # 预期输出: Playlist(['A', 'B', 'C', 'D'])
pl[0] = "Z"
print(pl)                 # 预期输出: Playlist(['Z', 'B', 'C'])
```

注意：**没有 `__iter__` 也能迭代**，因为 Python 会退化到"不断取 `__getitem__(0), __getitem__(1), …` 直到 IndexError"。但那样很慢，显式写 `__iter__` 更好。

### 6.4 可调用对象：`__call__`

```python
class Counter:
    def __init__(self):
        self.n = 0

    def __call__(self, step=1):
        self.n += step
        return self.n

c = Counter()
print(c(), c(), c())     # 预期输出: 1 2 3
print(callable(c))       # 预期输出: True
```

典型用途：装饰器类、策略对象、状态机。

### 6.5 上下文管理器：`__enter__` / `__exit__`

```python
class Timer:
    def __enter__(self):
        self.start = time.perf_counter()   # 需要 import time
        return self

    def __exit__(self, exc_type, exc_val, exc_tb):
        self.elapsed = time.perf_counter() - self.start
        return False          # 返回 False 表示不吞掉异常


with Timer() as t:
    sum(range(1_000_000))
print(f"耗时 {t.elapsed:.4f}s")   # 预期输出类似: 耗时 0.0032s
```

**返回 `True` 会吞掉异常（不建议滥用）；返回 `False`/不写则异常正常向外传播。**

`contextlib` 提供了更简洁的写法：

```python
from contextlib import contextmanager

@contextmanager
def timer():
    t0 = time.perf_counter()
    yield
    print(f"耗时 {time.perf_counter() - t0:.4f}s")

with timer():
    sum(range(1_000_000))
```

### 6.6 运算符重载速查

| 魔术方法 | 触发语法 | 用途 |
| --- | --- | --- |
| `__add__` | `a + b` | 加法 |
| `__sub__` / `__mul__` / `__truediv__` | `- * /` | 算术 |
| `__neg__` | `-a` | 取负 |
| `__lt__` / `__gt__` / `__le__` / `__ge__` | `< > <= >=` | 比较（可用 `functools.total_ordering` 减少样板） |
| `__bool__` | `bool(a)` | 真假判断 |
| `__format__` | `f"{a}"` | 格式化 |
| `__enter__` / `__exit__` | `with` | 资源管理 |
| `__getattr__` | `a.foo`（常规查找不到时） | 动态属性、代理 |
| `__getattribute__` | 任意属性访问 | 慎用，性能极差 |

用 `functools.total_ordering` 少写代码：

```python
from functools import total_ordering

@total_ordering
class Version:
    def __init__(self, parts):
        self.parts = tuple(parts)

    def __eq__(self, other):
        return isinstance(other, Version) and self.parts == other.parts

    def __lt__(self, other):
        return self.parts < other.parts

    def __hash__(self):
        return hash(self.parts)


print(Version((1, 2)) < Version((1, 3)))   # 预期输出: True
print(Version((1, 2)) >= Version((1, 2)))  # 预期输出: True（由 __eq__ + __lt__ 推导）
```

### 6.7 Python 3.10+ 的 `__slots__`

```python
class Point:
    __slots__ = ("x", "y")     # 固定属性集合

    def __init__(self, x, y):
        self.x = x
        self.y = y

p = Point(1, 2)
print(p)                        # 预期输出: <__main__.Point object at 0x...>
try:
    p.z = 3
except AttributeError as e:
    print("报错:", e)           # 预期输出: 报错: 'Point' object has no attribute 'z'
```

收益：省内存（无 `__dict__`）、属性访问略快。代价：不能给实例动态加属性、不能被弱引用（除非加 `__weakref__`）。适用于创建海量小对象（百万级实例）的场景。

## 七、`dataclass`：自动生成样板代码

`dataclass` 自动生成 `__init__`、`__repr__`、`__eq__`，可选 `frozen`、`order`、`slots`。

```python
from dataclasses import dataclass, field, asdict

@dataclass
class User:
    name: str                                  # 必填
    age: int = 18                              # 有默认值
    tags: list = field(default_factory=list)   # 可变默认值必须用 factory
    nickname: str = field(default="", repr=False)   # 不出现在 repr 中
    _internal: int = field(default=0, compare=False)  # 不参与比较

    def birthday(self):
        self.age += 1

    @property
    def label(self):
        return f"{self.name}({self.age})"


u = User("张三")
print(u)                      # 预期输出: User(name='张三', age=18, tags=[])
print(u == User("张三"))        # 预期输出: True（自动生成 __eq__）
u.tags.append("admin")
print(u.label)                # 预期输出: 张三(18)
print(asdict(u))              # 预期输出: {'name': '张三', 'age': 18, 'tags': ['admin'], 'nickname': '', '_internal': 0}
```

### 7.1 常用参数

```python
@dataclass(frozen=True)     # 实例不可变，可作为 dict 键 / 集合元素
class Point:
    x: int
    y: int

p = Point(1, 2)
print(p.x + p.y)            # 预期输出: 3
try:
    p.x = 10
except Exception as e:
    print(type(e).__name__) # 预期输出: FrozenInstanceError


@dataclass(order=True)      # 自动生成 < <= > >=，按字段顺序比较
class Version:
    major: int
    minor: int

print(Version(1, 2) < Version(1, 10))   # 预期输出: True（字典序比较，不是字符串比较）


@dataclass(slots=True)      # Python 3.10+，等价于 __slots__
class Node:
    value: int

print(Node(1).value)        # 预期输出: 1
```

### 7.2 不可变数据类的最佳实践

数据类适合表示**数据**，不要往里塞复杂逻辑。

```python
@dataclass(frozen=True)
class Point:
    x: float
    y: float

    def __post_init__(self):
        # 初始化后校验（frozen 时不能直接赋值属性）
        if self.x < 0 or self.y < 0:
            raise ValueError("坐标不能为负")
```

## 八、Enum：枚举

```python
from enum import Enum, IntEnum, StrEnum, auto, unique


class Color(Enum):
    RED = "red"
    GREEN = "green"
    BLUE = "blue"


class Level(IntEnum):
    LOW = auto()      # 1
    HIGH = auto()     # 2


print(Color.RED.value)              # 预期输出: red
print(Color("green"))               # 预期输出: <Color.GREEN: 'green'>  按值查找
print(list(Color))                  # 预期输出: [<Color.RED: 'red'>, <Color.GREEN: 'green'>, <Color.BLUE: 'blue'>]
print(Color.RED == Color.RED)       # 预期输出: True（枚举成员是单例）
print(Level.LOW < Level.HIGH)       # 预期输出: True（IntEnum 可以直接比较大小）
print(Level.LOW == 1)               # 预期输出: True

# 遍历时跳过别名
class Weekday(Enum):
    MON = 1
    TUES = 2
    MONDAY = 1      # MON 的别名，不出现在遍历中

print(len(Weekday))                 # 预期输出: 2
```

**什么时候用枚举？** 当一个值有"固定的可选集合"时 —— 状态、颜色、级别、方向。好处：拼写错误会立刻报错（传字符串 `"greeen"` 不会静默通过），且 IDE 有补全。

## 九、鸭子类型与 `Protocol`

### 9.1 鸭子类型（Duck Typing）

> "如果它走起来像鸭子、叫起来像鸭子，那它就是鸭子。"

Python 不要求对象继承任何东西，只要有需要的方法就能用：

```python
class MyList:
    def __iter__(self):
        return iter([1, 2, 3])

    def __len__(self):
        return 3

for x in MyList():        # 完全可行，没继承 list
    print(x, end=" ")
# 预期输出: 1 2 3
```

### 9.2 `Protocol`：结构化子类型

`Protocol`（Python 3.8+）把"结构约束"显式化，做静态类型检查时很有用。

```python
from typing import Protocol, runtime_checkable

@runtime_checkable
class Speaker(Protocol):
    def speak(self) -> str:
        ...

class Dog:
    def speak(self):
        return "汪汪"

class Robot:
    def speak(self):
        return "哔哔"

class Fish:
    pass

def announce(x: Speaker) -> str:
    return x.speak()

print(announce(Dog()))    # 预期输出: 汪汪
print(announce(Robot()))  # 预期输出: 哔哔
print(isinstance(Dog(), Speaker))     # 预期输出: True
print(isinstance(Fish(), Speaker))    # 预期输出: False（没有 speak）
```

**协议 vs 抽象基类：**

| | Protocol | ABC |
| --- | --- | --- |
| 检查方式 | 结构化（只看方法） | 命名继承 |
| 是否需要显式继承 | 不需要 | 需要 |
| 适合 | 第三方对象、鸭子类型的显式表达 | 统一管理一组类、强制实现 |

实践建议：**优先 Protocol（组合/结构约定），少量使用 ABC。**

## 十、抽象基类 ABC

```python
from abc import ABC, abstractmethod


class Shape(ABC):
    @abstractmethod
    def area(self) -> float:
        """子类必须实现。"""

    @abstractmethod
    def perimeter(self) -> float:
        ...

    def describe(self):
        # 模板方法：子类只实现变化的部分
        return f"面积={self.area():.2f}, 周长={self.perimeter():.2f}"


class Circle(Shape):
    def __init__(self, r):
        self.r = r

    def area(self):
        return 3.14159 * self.r ** 2

    def perimeter(self):
        return 2 * 3.14159 * self.r


print(Circle(2).describe())    # 预期输出: 面积=12.57, 周长=12.57

try:
    Shape()
except TypeError as e:
    print("不能实例化:", e)     # 预期输出: 不能实例化: Can't instantiate abstract class Shape with abstract methods area, perimeter
```

### 10.1 抽象类不能实例化，但类方法可以

class Repo(ABC):

        inst = cls()             # OK：调用的是具体子类

## 十一、设计模式在 Python 中的写法

### 11.1 单例（Singleton）

Python 有更简单的写法，实践中单例常被模块本身或全局变量替代。

```python
class Config:
    _instance = None

    def __new__(cls, *args, **kwargs):
        if cls._instance is None:
            cls._instance = super().__new__(cls)
        return cls._instance

    def __init__(self, env="dev"):
        # 注意：__init__ 每次都会被调用，所以要加保护
        if not hasattr(self, "_ready"):
            self.env = env
            self._ready = True


a, b = Config(), Config("prod")
print(a is b)             # 预期输出: True
print(a.env)              # 预期输出: dev（b 没有覆盖，因为有保护）
```

**更 Pythonic 的写法**：直接用模块

```python
# config.py
DEBUG = False
TIMEOUT = 30
```

```python
import config
config.DEBUG = True     # 全局唯一，直接改
```

### 11.2 工厂（Factory）

```python
class Notification:
    def send(self, msg):
        raise NotImplementedError


class EmailNotification(Notification):
    def send(self, msg):
        return f"邮件发送: {msg}"


class SMSNotification(Notification):
    def send(self, msg):
        return f"短信发送: {msg}"


# 简单工厂函数
def create_notification(kind: str) -> Notification:
    registry = {
        "email": EmailNotification,
        "sms": SMSNotification,
    }
    if kind not in registry:
        raise ValueError(f"未知的通知类型: {kind}，可选: {list(registry)}")
    return registry[kind]()


print(create_notification("email").send("hi"))   # 预期输出: 邮件发送: hi
try:
    create_notification("wechat").send("hi")
except ValueError as e:
    print(e)   # 预期输出: 未知的通知类型: wechat，可选: ['email', 'sms']
```

加新类型时只需往 `registry` 里加一项，调用方代码完全不变 —— 这就是工厂模式的价值（开闭原则）。

### 11.3 观察者（Observer）

```python
class Subject:
    def __init__(self):
        self._observers = []

    def subscribe(self, fn):
        self._observers.append(fn)
        return lambda: self._observers.remove(fn)     # 返回取消订阅的函数

    def notify(self, message):
        for fn in list(self._observers):              # 拷贝一份，允许回调中退订
            fn(message)


class EmailLogger:
    def __init__(self):
        self.log = []

    def __call__(self, message):
        self.log.append(f"[LOG] {message}")


class Alert:
    def __init__(self):
        self.alerts = []

    def __call__(self, message):
        self.alerts.append(f"[ALERT] {message}")


news = Subject()
logger = EmailLogger()
alert = Alert()
news.subscribe(logger)
news.subscribe(alert)

news.notify("服务器宕机")
print(logger.log)     # 预期输出: ['[LOG] 服务器宕机']
print(alert.alerts)   # 预期输出: ['[ALERT] 服务器宕机']
```

## 十二、常见面试题速答

1. **`self` 是什么？** 由调用时自动传入的第一个参数；`obj.m(x)` 等价于 `Cls.m(obj, x)`。
2. **`__init__` vs `__new__`？** `__new__` 创建对象（返回实例），`__init__` 初始化已创建的实例。`__new__` 用于不可变类扩展与单例。
3. **类属性与实例属性的区别？** 前者定义在类中、所有实例共享；后者在 `self.x = ...` 中创建、每个实例独立，且会遮蔽同名类属性。
4. **静态方法与类方法区别？** 静态方法无隐式首参，用作工具函数；类方法首参是 `cls`，可访问类属性、可作为构造器工厂且支持子类。
5. **`super()` 调的是父类吗？** 不是，是 MRO 中当前类之后的下一个类。
6. **定义 `__eq__` 后必须做什么？** 定义 `__hash__`，否则对象变为不可哈希。
7. **组合 vs 继承？** is-a 用继承，has-a 用组合；能用组合就用组合。
8. **`@property` 有什么用？** 把方法当属性用，支持惰性计算、写入校验、只读保护。
9. **多重继承下属性怎么找？** 按 `__mro__`（C3 线性化）依次查找。
10. **`dataclass` 的可变默认值为什么要 `field(default_factory=list)`？** dataclass 禁止把 list/dict 直接作为默认值（值可变、会被所有实例共享），用 `default_factory` 在每次实例化时新建。
11. **什么时候用 ABC，什么时候用 Protocol？** 需要强制所有子类实现一组方法 → ABC；只需"结构上像"而不强制继承 → Protocol。
12. **单例怎么实现？** `__new__` + 类变量缓存，或直接用模块/全局对象。

## 本节小结

- 类是工厂，实例是对象；`self` 是约定，不是关键字。
- 类属性共享、实例属性独立；**可变默认值永远放 `__init__`**。
- `@staticmethod` 无状态工具，`@classmethod` 带 `cls`（子类友好），`@property` 把方法包装成属性。
- 多继承看 `__mro__`；`super()` 是"下一个类"，所有 `__init__` 都应写 `super().__init__(...)`。
- **组合优于继承**：has-a 用组合，运行时可替换。
- 魔术方法让类支持内建语法；定义了 `__eq__` 必须定义 `__hash__`；`__enter__/__exit__` 是 `with` 的底层。
- 现代 Python 优先用 `dataclass` 表达数据、`Enum` 表达固定取值集合、`Protocol` 表达结构约定、`ABC` 表达强制的继承层次。
- 设计模式在 Python 里往往可以更简洁：单例用模块、工厂用字典注册、观察者用回调列表。

## 自测题

<details>
<summary>1. 类属性与实例属性有什么区别？下面代码为什么危险？</summary>

**答案：**
类属性定义在类体内，存储在类的 `__dict__`，被所有实例共享；实例属性通过 `self.x = v` 创建，存储在实例 `__dict__`，每个实例独立，且会遮蔽同名类属性。

```python
class BadCounter:
    items = []      # 危险：所有实例共享同一个列表
```
因为这个列表对象在类定义时就创建了，之后所有 `Counter()` 实例的 `self.items` 都指向它，任何一个实例 append 都会影响其他实例。正确做法是在 `__init__` 中 `self.items = []`。
</details>

<details>
<summary>2. `@staticmethod`、`@classmethod`、实例方法分别在什么场景使用？类方法能否被继承后返回子类实例？</summary>

**答案：**
- 实例方法：需要访问实例状态时使用，首参 `self`。
- 静态方法：与类、实例都无关的纯工具函数（如 `MathUtil.add(1, 2)`）。
- 类方法：需要访问类属性、或需要构造器工厂时使用，首参 `cls`。

能。`cls` 绑定的是实际调用的类型：
```python
class Circle(MathUtil): pass
type(Circle.from_pi(3))   # <class 'Circle'>
```
这正是类方法适合做工厂的原因 —— 子类继承后无需修改工厂代码即可返回正确的子类。
</details>

<details>
<summary>3. 下面代码的输出是什么？</summary>

```python
class A:
    def who(self): return "A"

class B(A):
    def who(self): return "B" + super().who()

class C(A):
    def who(self): return "C" + super().who()

class D(B, C):
    def who(self): return "D" + super().who()

print(D.__mro__)
print(D().who())
```

**答案：**
```
(<class 'D'>, <class 'B'>, <class 'C'>, <class 'A'>, <class 'object'>)
DBCA
```
MRO 按 C3 线性化计算；`super().who()` 沿 MRO 依次调用，因此 `D → B → C → A`。注意 `super()` 并不是"调用父类"。
</details>

<details>
<summary>4. 为什么 `__init__` 中要用 `super().__init__(...)` 而不是 `父类.__init__(self, ...)`？</summary>

**答案：**
`super().__init__()` 会沿 MRO 调用下一个类，因此在多继承/混入（Mixin）场景中能保证每个类都被初始化且参数正确传递；而 `父类.__init__(self, ...)` 跳过 MRO，直接调用指定类，会遗漏其他需要初始化的类，造成状态不完整。
</details>

<details>
<summary>5. 定义了 `__eq__` 而不定义 `__hash__` 会发生什么？为什么要同时定义？</summary>

**答案：**
Python 会自动把 `__hash__` 设为 `None`，使对象**不可哈希**，放进 `set` 或作为 `dict` 键会抛 `TypeError: unhashable type`。

因为哈希一致性要求：逻辑相等的对象必须哈希值相同（否则 `a == b` 但在 set 里却是两个元素）。所以定义 `__eq__` 时必须同时提供符合该语义的 `__hash__`。若对象不可变，可用不可变字段的哈希组合；确实不可哈希则显式写 `__hash__ = None`。
</details>

<details>
<summary>6. 实现一个类，使它可以被 `len()`、`for` 遍历、支持 `in`、且能相加。需要实现哪些魔术方法？</summary>

**答案：**
```python
class Box:
    def __init__(self, items): self.items = list(items)
    def __len__(self): return len(self.items)
    def __iter__(self): return iter(self.items)          # for 循环
    def __getitem__(self, i): return self.items[i]        # 索引/切片
    def __contains__(self, x): return x in self.items     # in 操作
    def __add__(self, other): return Box(self.items + other.items)
    def __repr__(self): return f"Box({self.items})"
```
- `len()` → `__len__`
- `for` → 优先 `__iter__`（返回迭代器）；没有时才退化到 `__getitem__` 逐个取值
- `in` → `__contains__`
- `+` → `__add__`（接收方类型不匹配时应返回 `NotImplemented`）
</details>

<details>
<summary>7. `@dataclass` 中为什么 `tags: list = field(default_factory=list)` 而不能直接写 `tags: list = []`？</summary>

**答案：**
因为 dataclass 会把默认值放进类属性，所有实例共享同一个可变对象，一个实例修改会影响全部 —— 与普通类里 `items = []` 是同一个坑。此外 dataclass 会直接禁止 list/dict/set 作为默认值，编译期就报错。

`default_factory` 保存的是一个"工厂函数"，每次实例化时调用一次，得到全新的独立对象，因此实例之间互不影响。
</details>

<details>
<summary>8. Protocol 和 ABC 的区别是什么？什么时候各用哪个？</summary>

**答案：**
- ABC：需要显式 `class X(BaseABC)` 继承，会在实例化时强制检查抽象方法是否实现；适合**一组由你管理的类**，需要统一约束。
- Protocol：结构化子类型，只要"长得像"就满足，不要求继承；`@runtime_checkable` 还可用 `isinstance` 检查。适合**第三方对象**或只是想表达"我需要这些方法"的场景。

实践建议：优先 Protocol（更松、更符合 Python 精神），只在需要统一生命周期管理或模板方法时用 ABC。
</details>

<details>
<summary>9. 用工厂模式实现：新增一种 `PushNotification` 时不需要修改调用方代码。</summary>

**答案：**
```python
def create_notification(kind: str) -> Notification:
    registry = {
        "email": EmailNotification,
        "sms": SMSNotification,
        "push": PushNotification,      # 只需新增这一行
    }
    if kind not in registry:
        raise ValueError(f"未知类型: {kind}")
    return registry[kind]()
```
调用方始终写 `create_notification(cfg["channel"])`，新增类型只改注册表一处，符合开闭原则。更完善的写法是在 `Notification` 上加 `register()` 类方法做自注册。
</details>
