## 1. 一等函数（First-class Function）

在 Python 中，**函数是对象**。这意味着函数可以：

- 赋值给变量
- 作为参数传给别的函数
- 作为别的函数的返回值
- 放进容器（列表、字典）
- 作为类的属性或实例属性

这是「函数式编程」的基石，也是装饰器的原理。

```python
# 09-01_first_class.py
def double(x):
    return x * 2


# 1) 赋值给变量
f = double
print(f(3))                  # 6 —— 注意是调用 double(3)，不是 f

# 2) 放进容器
funcs = [double, abs, str]
print([fn(-5) for fn in funcs])   # [-10, 5, '-5']

# 3) 作为参数传递
def apply(fn, value):
    return fn(value)


print(apply(double, 10))     # 20

# 4) 作为返回值（高阶函数）
def make_adder(n):
    def adder(x):
        return x + n
    return adder


add5 = make_adder(5)
print(add5(3))               # 8

# 5) map / filter / lambda 都是「接收函数」的builtins
print(list(map(double, [1, 2, 3])))         # [2, 4, 6]
print(list(filter(lambda x: x % 2 == 0, range(6))))  # [0, 2, 4]
print(sorted([3, 1, 2], key=lambda x: -x))  # [3, 2, 1]

# 6) 函数也是对象，可以查看元信息
print(double.__name__)       # double
print(double.__doc__)        # None（本例没有写文档字符串）
print(double.__module__)     # __main__
```

**预期输出**

```
6
[-10, 5, '-5']
20
8
[2, 4, 6]
[0, 2, 4]
[3, 2, 1]
double
None
__main__
```

> 面试常考点：`f = double` 只是让 `f` 指向同一个函数对象。若要「克隆并改名」需要 `functools.wraps` 或 `functools.partial`，直接赋值不会复制。

## 2. 闭包：LEGB 与函数记住的环境

### 2.1 LEGB 规则回顾

名字查找顺序：**L**ocal（局部）→ **E**nclosing（外层函数局部）→ **G**lobal（模块全局）→ **B**uilt-in（内置）。

```python
# 09-02_legb.py
x = "global"           # G

def outer():
    x = "enclosing"   # E

    def middle():
        x = "local"   # L

        def inner():
            return x  # 找 L：命中 middle 的 x
        return inner()

    return middle()


print(outer())          # local


# 逐层向外找，直到 G
def find_name():
    print(name)        # 这里没有局部 name，向外找不到，落到 G
    return name


name = "I am global"
print(find_name())     # I am global
```

### 2.2 闭包 = 内层函数 + 它捕获的外层变量

闭包的前提是：**内层函数被返回出去，并在外层函数执行完之后才被调用**。这时内层函数仍然"记得"外层作用域里的变量。

```python
# 09-03_closure.py
def counter(start=0):
    def step(increase=1):
        nonlocal start          # 修改外层变量必须用 nonlocal（Python 3）
        start += increase
        return start
    return step


c = counter(10)
print(c())      # 11
print(c(5))     # 16
print(c())      # 17 —— 状态被保留，闭包是有状态的


# 闭包能"偷看"外层的私有变量：实现私有属性
class Account:
    def __init__(self, balance):
        self.__get_balance = lambda: balance   # balance 藏进了闭包

    def get(self):
        return self.__get_balance()

    def add(self, amount):
        self.__get_balance = lambda: self.__get_balance() + amount


a = Account(100)
a.add(50)
print(a.get())   # 150
# print(a.balance)   # AttributeError —— 无法从外部访问 balance
```

### 2.3 用闭包实现记忆化（面试常考手写题）

```python
# 09-04_memoize.py
def memoize(fn):
    """闭包版记忆化：对相同参数只计算一次。"""
    cache = {}

    def wrapper(*args, **kwargs):
        key = (args, tuple(sorted(kwargs.items())))
        if key not in cache:
            cache[key] = fn(*args, **kwargs)
        return cache[key]

    wrapper.cache = cache        # 暴露缓存，便于测试与清理
    wrapper.__name__ = fn.__name__
    return wrapper


@memoize
def slow_sum(a, b):
    print(f"  计算 {a} + {b}")
    return a + b


print(slow_sum(1, 2))   # 计算 1 + 2 -> 3
print(slow_sum(1, 2))   # 直接命中缓存 -> 3（无"计算"输出）
print(slow_sum(1, 3))   # 计算 1 + 3 -> 4
print(slow_sum.cache)
```

**预期输出**

```
  计算 1 + 2
3
3
  计算 1 + 3
4
{((1, 2), ()): 3, ((1, 3), ()): 4}
```

> 闭包的代价：闭包持有外层变量引用，如果外层变量很大，会阻止其被垃圾回收。生产环境请优先用 `functools.lru_cache`，它用 C 实现、更快且能处理不可哈希参数的限制（同样不支持，但有 maxsize 控制）。

## 3. 装饰器模式

### 3.1 装饰器本质

装饰器就是一个**接收函数、返回新函数**的函数。`@decorator` 是语法糖：

```python
# 09-05_decorator_sugar.py
def log_calls(fn):
    def wrapper(*args, **kwargs):
        print(f"[调用] {fn.__name__}{args}")
        result = fn(*args, **kwargs)
        print(f"[返回] {fn.__name__} -> {result}")
        return result
    return wrapper


# 写法 A
@log_calls
def add(a, b):
    return a + b


# 写法 B（完全等价）
def add2(a, b):
    return a + b
add2 = log_calls(add2)
```

### 3.2 必须使用 `functools.wraps`

不加 `wraps` 会丢失原函数的名字、文档、签名，调试和框架（如 Flask 路由）都会出问题。

```python
# 09-06_wraps.py
import functools
import inspect


def timed(fn):
    @functools.wraps(fn)              # ← 关键一行
    def wrapper(*args, **kwargs):
        return fn(*args, **kwargs)
    return wrapper


@timed
def greet(name, punctuation="!"):
    """打招呼的文档字符串。"""
    return f"你好，{name}{punctuation}"


print(greet.__name__)              # greet  （而不是 wrapper）
print(greet.__doc__)               # 打招呼的文档字符串。
print(greet.__module__)            # __main__
print(inspect.signature(greet))    # (name, punctuation='!')
print(greet("张三"))                 # 你好，张三！
```

**预期输出**

```
greet
打招呼的文档字符串。
__main__
(name, punctuation='!')
你好，张三！
```

### 3.3 带参数的装饰器

要写"带配置的装饰器"，就得**三层嵌套**：外层接收配置 → 中层接收函数 → 内层才是真正的包装器。

```python
# 09-07_param_decorator.py
import functools


def retry(times=3, exceptions=(Exception,)):
    """失败自动重试的装饰器。"""

    def decorator(fn):
        @functools.wraps(fn)
        def wrapper(*args, **kwargs):
            last = None
            for i in range(times):
                try:
                    return fn(*args, **kwargs)
                except exceptions as e:
                    last = e
                    print(f"  第 {i + 1} 次失败：{e}")
            raise last

        return wrapper

    return decorator


@retry(times=3, exceptions=(ValueError, KeyError))
def parse(text):
    if text == "":
        raise ValueError("空输入")
    if "=" not in text:
        raise KeyError(text)
    k, v = text.split("=", 1)
    return {k: int(v)}


print(parse("age=18"))   # 第 1 次失败... {'age': 18}
print(parse(""))
# 打印 3 次失败后抛出 ValueError
```

**预期输出**

```
  第 1 次失败：''
{'age': 18}
  第 1 次失败：空输入
  第 2 次失败：空输入
  第 3 次失败：空输入
Traceback (most recent call last):
  ...
ValueError: 空输入
```

### 3.4 装饰器类（有状态装饰器）

当装饰器需要保存配置状态、或实现"类注册表"时，用类更自然。

```python
# 09-08_class_decorator.py
import functools


class Timer:
    """统计被装饰函数的总调用次数与耗时（毫秒）。"""

    def __init__(self):
        self.count = 0
        self.total_ms = 0.0

    def __call__(self, fn):
        @functools.wraps(fn)
        def wrapper(*args, **kwargs):
            import time
            start = time.perf_counter()
            try:
                return fn(*args, **kwargs)
            finally:
                elapsed = (time.perf_counter() - start) * 1000
                self.count += 1
                self.total_ms += elapsed

        self.fn = fn          # 保留原函数引用，方便测试
        return wrapper

    def report(self):
        avg = self.total_ms / self.count if self.count else 0
        return f"{self.fn.__name__}: 调用 {self.count} 次，平均 {avg:.4f} ms"


timer = Timer()


@timer
def work(n):
    return sum(range(n))


work(100)
work(1000)
print(timer.report())     # work: 调用 2 次，平均 0.00xx ms


# ---- 更实用的例子：注册表装饰器 ----
class Register:
    """把类注册进一个字典（常用于插件/路由系统）。"""

    def __init__(self):
        self.handlers = {}

    def __call__(self, cls):
        self.handlers[cls.__name__] = cls()
        return cls


registry = Register()


@registry
class CatHandler:
    def handle(self):
        return "喵"


@registry
class DogHandler:
    def handle(self):
        return "汪"


for name, obj in registry.handlers.items():
    print(name, "->", obj.handle())
```

**预期输出**

```
work: 调用 2 次，平均 0.0023 ms
CatHandler -> 喵
DogHandler -> 汪
```

### 3.5 多个装饰器的执行顺序

这是必考题。口诀：

> **自底向上应用（定义时），自顶向下调用（运行时）。**

```python
# 09-09_decorator_order.py
import functools


def deco(label):
    def outer(fn):
        @functools.wraps(fn)
        def wrapper(*args, **kwargs):
            print(f"  [{label}-前]")
            result = fn(*args, **kwargs)
            print(f"  [{label}-后]")
            return result
        return wrapper
    return outer


@deco("A")            # 第 3 层（最外）
@deco("B")            # 第 2 层
@deco("C")            # 第 1 层（最内，贴近原函数）
def target():
    print("  真正执行 target")


print("调用开始：")
target()
```

**预期输出**

```
调用开始：
  [A-前]
  [B-前]
  [C-前]
  真正执行 target
  [C-后]
  [B-后]
  [A-后]
```

等价写法帮你理解：

```python
target = deco("A")(deco("B")(deco("C")(target)))
```

即 `C` 最先包住原函数，`A` 最后包住一切，所以调用时 `A` 最先进。

### 3.6 保留参数签名的进阶装饰器（面试加分）

```python
# 09-10_signature_preserving.py
import functools
import inspect


def trace(fn):
    """保留真实签名，introspection 与框架友好。"""

    @functools.wraps(fn)
    def wrapper(*args, **kwargs):
        # 通过 __signature__ 暴露被包装函数的真实签名
        wrapper.__signature__ = inspect.signature(fn)
        print("调用", inspect.signature(wrapper))
        return fn(*args, **kwargs)

    return wrapper


@trace
def add(a: int, b: int = 10) -> int:
    """加法。"""
    return a + b


print(add(1, 2))
print(add.__annotations__)   # {'a': int, 'b': int, 'return': int}
```

**预期输出**

```
调用 (a: int, b: int = 10) -> int
3
{'a': <class 'int'>, 'b': <class 'int'>, 'return': <class 'int'>}
```

## 4. functools 常用工具

### 4.1 `lru_cache` / `cache`

```python
# 09-11_lru_cache.py
import functools


@functools.lru_cache(maxsize=128)
def fib(n):
    """朴素递归斐波那契 —— 有缓存后从 O(2^n) 降到 O(n)。"""
    return n if n < 2 else fib(n - 1) + fib(n - 2)


print(fib(100))
# 13739980291790237585750800382171432768

fib.cache_clear()          # 清空缓存
print(fib.cache_info())    # CacheInfo(hits=0, misses=0, maxsize=128, currsize=0)
print(fib(30)); print(fib.cache_info())
# 832040
# CacheInfo(hits=1, misses=31, maxsize=128, currsize=31)


# 不限制大小的缓存（Python 3.9+）
@functools.cache
def expensive(key):
    return key * 2


print(expensive(21))       # 42


# unhashable 参数会报错
@functools.lru_cache
def bad(d):
    return sum(d.values())

try:
    bad({"a": 1})
except TypeError as e:
    print("TypeError:", e)
# TypeError: unhashable type: 'dict'
```

**要点**

- `maxsize=None` 表示无限缓存（等价于 `@functools.cache`）。
- 参数必须**可哈希**；传 list/dict 需先转 tuple 或自定义缓存键。
- 缓存是**实例级**的（在类方法上会缓存 `self`），注意 `self.__hash__` 默认按身份，一般没问题。
- 会造成**内存增长**与**强引用驻留**，长驻进程要留意 `maxsize`。

### 4.2 `partial`：偏函数

```python
# 09-12_partial.py
import functools


def greet(greeting, name, punctuation="."):
    return f"{greeting}, {name}{punctuation}"


# 固定第一个参数 greeting
hello = functools.partial(greet, greeting="Hello")
print(hello("Bob"))                 # Hello, Bob.

# 用关键字顺序固定中间参数（按签名顺序绑定）
hello_zh = functools.partial(greet, "你好")
print(hello_zh("张三", "！"))         # 你好, 张三！

# 关键字参数可以覆盖 partial 中的默认值
print(functools.partial(greet, "Hi")("Ann", punctuation="?"))   # Hi, Ann?


# 实战：给 print 加前缀（stdout 写文件）
import sys
log = functools.partial(print, file=sys.stdout)
log("普通输出")


# 实战：给命令行参数绑默认值
import argparse
parser = argparse.ArgumentParser()
parser.add_argument("--port", type=int, default=8080)
parse_port = functools.partial(parser.parse_args, ["--port", "9000"]).port
print(parse_port)                  # 9000
```

**要点**：`partial` 只是把参数预先绑好，返回的仍是一个可调用对象，没有改变原函数。

### 4.3 `reduce` 与 `singledispatch`

```python
# 09-13_reduce_singledispatch.py
import functools
from functools import reduce

# reduce：两两折叠
print(reduce(lambda a, b: a + b, [1, 2, 3, 4], 0))    # 10
print(reduce(lambda a, b: a * b, [1, 2, 3, 4]))         # 24

# 统计词频：比手写字典循环更简洁
words = "a b a c b a".split()
freq = reduce(lambda d, w: {**d, w: d.get(w, 0) + 1}, words, {})
print(freq)    # {'a': 3, 'b': 2, 'c': 1}


# singledispatch：基于「参数第一个类型」做多分派（消除 if-elif 链）
@functools.singledispatch
def describe(obj):
    return f"通用对象：{type(obj).__name__}"


@describe.register
def _(obj: int):
    return f"整数：{obj}，二进制 {obj:>08b}"


@describe.register
def _(obj: str):
    return f"字符串：{obj.upper()}"


@describe.register
def _(obj: list):
    return f"列表，长度 {len(obj)}"


print(describe(42))       # 整数：42，二进制 00101010
print(describe("hi"))      # 字符串：HI
print(describe([1, 2]))   # 列表，长度 2
print(describe(3.14))     # 通用对象：float
```

## 5. 上下文管理器 contextlib

### 5.1 `with` 语句的本质

`with` 调用对象的 `__enter__` / `__exit__`。即使不写 `contextlib`，也可以用类实现。

```python
# 09-14_with_class.py
class Timer:
    def __enter__(self):
        import time
        self.start = time.perf_counter()
        return self                      # as 后面拿到的就是它

    def __exit__(self, exc_type, exc_val, exc_tb):
        import time
        self.elapsed = time.perf_counter() - self.start
        return False                     # 返回 True 会「吞掉」异常

    def __repr__(self):
        return f"<Timer {self.elapsed * 1000:.3f} ms>"


with Timer() as t:
    sum(range(10000))
print(t)    # <Timer 0.2xx ms>

# 异常也会触发 __exit__（这正是 with 的价值：自动释放资源）
try:
    with Timer() as t2:
        raise ValueError("boom")
except ValueError as e:
    print("捕获到异常：", e, "| 计时器已安全关闭：", bool(t2.elapsed))
```

### 5.2 `@contextlib.contextmanager`：用生成器写 `with`

```python
# 09-15_contextmanager.py
import contextlib
import sys


@contextlib.contextmanager
def open_file(path, mode="r"):
    """生成器版上下文管理器：yield 前是进入，之后是退出。"""
    f = open(path, mode, encoding="utf-8")
    try:
        yield f                        # with 块在此执行
    finally:
        f.close()                      # 即使块内抛异常也会执行


@contextlib.contextmanager
def timer(label):
    import time
    start = time.perf_counter()
    try:
        yield
    finally:
        print(f"{label}: {(time.perf_counter() - start) * 1000:.3f} ms")


# 用法
with timer("累加") as t:
    sum(range(100000))


# 实战：临时重定向 stdout
buf = None
import io
buf = io.StringIO()
with contextlib.redirect_stdout(buf):
    print("这段文字被重定向了，不会出现在终端")
print("终端收到：", buf.getvalue().strip())
# 终端收到： 这段文字被重定向了，不会出现在终端

# 实战：忽略异常
with contextlib.suppress(FileNotFoundError):
    open("不存在的文件.txt")

# 实战：让一段逻辑只执行一次
run_once = contextlib.suppress(RuntimeError)
called = []
with run_once, contextlib.suppress(RuntimeError):
    called.append(1)
print("called =", called)   # called = [1]
```

### 5.3 `ExitStack`：管理多个动态资源

```python
# 09-16_exit_stack.py
import contextlib


@contextlib.contextmanager
def resource(name):
    print(f"打开 {name}")
    try:
        yield name
    finally:
        print(f"关闭 {name}")


names = ["db", "cache", "queue"]
with contextlib.ExitStack() as stack:
    for n in names:
        stack.enter_context(resource(n))
    print("--- 全部资源就绪 ---")
print("--- 已按相反顺序清理 ---")
```

**预期输出**

```
打开 db
打开 cache
打开 queue
--- 全部资源就绪 ---
关闭 queue
关闭 cache
关闭 db
--- 已按相反顺序清理 ---
```

> 常用 `contextlib` 工具：`contextmanager`、`redirect_stdout/stderr`、`suppress`、`ExitStack`、`closing`、`nullcontext`。

## 6. 生成器（Generator）

### 6.1 `yield` 与惰性求值

函数体里出现 `yield`，它就变成生成器函数：调用它不执行函数体，而是返回生成器对象。

```python
# 09-17_generator.py
def counter(n):
    """生成器：逐个产出，不一次性占用内存。"""
    for i in range(1, n + 1):
        yield i


g = counter(3)
print(type(g))          # <class 'generator'>
print(next(g))          # 1
print(next(g))          # 2
print(next(g))          # 3
# print(next(g))        # StopIteration


# 对比：列表 vs 生成器的内存占用
import sys

list_version = [i * 2 for i in range(100000)]
gen_version = (i * 2 for i in range(100000))
print(sys.getsizeof(list_version) / 1024, "KB (list)")
print(sys.getsizeof(gen_version), "bytes (generator)")
# 800.x KB (list)
# 48 bytes (generator)

print(sum(counter(1000000)))   # 生成器适合聚合计算，内存恒定
# 500000500000
```

### 6.2 `yield from`：委托给子生成器

```python
# 09-18_yield_from.py
def sub_gen(n):
    for i in range(n):

    yield 2

            yield from flatten(it)
        else:
```

## 7. 迭代器协议与可迭代对象

### 7.1 协议本身

- **可迭代对象（iterable）**：实现 `__iter__()`，返回迭代器。
- **迭代器（iterator）**：实现 `__iter__()`（返回自己）和 `__next__()`。
- `__next__` 抛 `StopIteration` 表示结束。

`for` 循环做的正是：

```python
# for x in obj  等价于：
# it = iter(obj)
# while True:
#     try: x = next(it)
#     except StopIteration: break
```

```python
# 09-22_iterator_protocol.py
class Countdown:
    """自定义迭代器：必须实现 __iter__ 与 __next__。"""

    def __init__(self, start):
        self.current = start

    def __iter__(self):
        return self                # 迭代器自己返回自己

    def __next__(self):
        if self.current <= 0:
            raise StopIteration     # 结束信号
        self.current -= 1
        return self.current + 1


c = Countdown(3)
print(list(c))       # [3, 2, 1]

# 可迭代对象：只需 __iter__，每次调用产生一个新的迭代器
class Range2:
    def __init__(self, n):
        self.n = n

    def __iter__(self):
        return iter(range(self.n))    # 复用内置迭代器


r = Range2(3)
print(list(r), list(r))    # [0, 1, 2] [0, 1, 2]  <- 每次都是新的


# 旧式协议（了解即可）：__getitem__ 配合索引
class Legacy:
    def __getitem__(self, i):
        if i >= 3:
            raise IndexError
        return i * 10


print(list(Legacy()))      # [0, 10, 20]


# 双向迭代器：__length_hint__ 帮 list() 预分配内存
class Sized:
    def __init__(self, n):
        self.i, self.n = 0, n

    def __iter__(self):
        return self

    def __next__(self):
        if self.i >= self.n:
            raise StopIteration
        self.i += 1
        return self.i

    def __length_hint__(self):
        return self.n - self.i


print(list(Sized(3)))       # [1, 2, 3]
```

## 9. 综合实战：流水线式数据处理

把上面所有工具串起来，理解它们如何协作。

```python
# 09-25_pipeline.py
import itertools as it
from collections import Counter
from functools import reduce, partial


def read_lines():
    """模拟数据源。"""
    return iter([
        "alice,30,python",
        "bob,25,java",
        "carol,30,python",
        "dave,35,go",
        "erin,25,python",
    ])


def parse(line):
    name, age, lang = line.split(",")
    return {"name": name, "age": int(age), "lang": lang}


def young_enough(p):
    return p["age"] < 33


records = map(parse, read_lines())
filtered = filter(young_enough, records)
by_lang = it.groupby(sorted(filtered, key=lambda r: r["lang"]))

for lang, group in by_lang:
    group = list(group)
    total_age = reduce(lambda a, b: a + b["age"], group, 0)
    names = ", ".join(p["name"] for p in group)
    print(f"{lang:8s} 共 {len(group)} 人，平均年龄 {total_age / len(group):.1f}：{names}")

print()
# Counter + most_common
print(Counter(p["lang"] for p in map(parse, read_lines())).most_common())
# [('python', 3), ('java', 1), ('go', 1)]

print()
# reduce + partial 做通用聚合
def group_count(acc, key):
    acc[key] = acc.get(key, 0) + 1
    return acc


add_lang = partial(group_count, key="lang")
print(reduce(add_lang, map(parse, read_lines()), {}))
# {'lang': 'python', ...}
```

**预期输出**

```

java     共 1 人，平均年龄 25.0：bob
python   共 3 人，平均年龄 28.3：alice, carol, erin

[('python', 3), ('java', 1), ('go', 1)]
```

## 10. 常见反模式与陷阱

| 反模式 | 问题 | 正确做法 |
|---|---|---|
| 在循环里手动累加但用生成器重复生成 | 每次迭代重新计算 | 先 `list(...)` 缓存 |
| 闭包捕获大对象 | 阻止垃圾回收 | 用默认参数 `def f(x, _big=big)` 或改用类属性 |
| 装饰器里直接 `print` | 不便测试 | 用 `logging` 模块 |
| 生成器里忘记 `yield` 导致无限循环 | 死循环 | 用 `yield from` 或加终止条件 |
| 迭代器被 `next()` 消费两次 | 得到空列表 | 需要重复遍历就转成 list |
| `lru_cache` 缓存参数含 dict/list | `TypeError: unhashable` | 转 tuple 作 key 或用自定义 memoize |
| 循环内创建生成器 | 性能极差 | 提取为变量复用 |

---

## 本节小结

- **一等函数**是函数式编程的地基：函数能赋值、传参、返回、存入容器。
- **闭包**遵循 **LEGB**，用 `nonlocal` 修改外层变量；闭包自带状态，是"记忆化"的天然实现。
- **装饰器**三形态：函数型（`wraps` 必写）、带参型（三层嵌套）、类型（有状态）。多个装饰器 **自底向上应用、自顶向下调用**。
- **functools**：`lru_cache` 缓存纯函数（参数须可哈希），`partial` 预绑参数，`singledispatch` 做类型多态。
- **上下文管理器**：`with` 保证资源释放；`@contextlib.contextmanager` 用生成器写，`ExitStack` 管理动态数量的资源。
- **生成器**：`yield` 让函数惰性求值，`yield from` 委托子生成器，`send` 实现双向通信；理解"迭代器协议"（`__iter__`/`__next__`）是掌握生成器的前提。
- **itertools** 提供组合、聚合、过滤、终止四类管道算子，与 `map`/`filter`/`reduce` 组合能替代大量手写循环。

2. 写出带参数装饰器 `@limit_rate(max_per_sec=2)` 的完整实现，并说明为什么需要三层嵌套。

<details>
<summary>参考答案</summary>

```python
import time
import functools

def limit_rate(max_per_sec=2):
    def decorator(fn):                      # 第二层：接收函数
        @functools.wraps(fn)
        def wrapper(*args, **kwargs):       # 第三层：真正被调用
            wait = 1.0 / max_per_sec
            time.sleep(wait)                # 简单模拟限流
            return fn(*args, **kwargs)
        return wrapper
    return decorator                        # 第一层：接收配置
```

三层的原因：

- 第一层必须在"使用处"执行（`@limit_rate(max_per_sec=2)` 会立即调用它），拿到配置 `max_per_sec`；
- 第二层拿到配置后才作用于被装饰函数；
- 第三层才是每次实际调用时执行的逻辑。少一层就无法同时携带"配置"和"原函数"。

</details>

3. 用装饰器实现一个缓存装饰器，要求：能记录调用次数、能在运行时清空缓存、支持带默认值的关键字参数。

<details>
<summary>参考答案</summary>

```python
import functools

def counted_cache(fn):
    cache = {}
    stats = {"hits": 0, "misses": 0}

    @functools.wraps(fn)
    def wrapper(*args, **kwargs):
        key = (args, tuple(sorted(kwargs.items())))
        if key in cache:
            stats["hits"] += 1
            return cache[key]
        stats["misses"] += 1
        cache[key] = fn(*args, **kwargs)
        return cache[key]

    wrapper.stats = stats
    wrapper.clear = cache.clear
    return wrapper
```

运行测试：

```python
@counted_cache
def add(a, b=10):
    return a + b

print(add(1, b=2))   # 计算
print(add(1, b=2))   # 命中
print(add(1))        # 计算（key 不同）
print(add.stats)     # {'hits': 1, 'misses': 2}
add.clear()
```

关键点：`kwargs` 必须转为可哈希的 tuple，且需 `sorted` 保证顺序无关；`functools.lru_cache` 内部也是类似做法。

</details>

4. `lru_cache` 装饰的函数接收 `dict` 参数时为什么报错？如何解决？

<details>
<summary>参考答案</summary>

因为 `lru_cache` 用参数构造缓存 key，需要 key 可哈希。`dict`、`list`、`set` 都是可变且不可哈希的，会抛 `TypeError: unhashable type: 'dict'`。

解决方案：

1. **转成不可变形式**：`f(tuple(sorted(d.items())))`
2. **自定义包装层**：

```python
import functools

def hashable_cache(fn):
    @functools.wraps(fn)
    def wrapper(d, *a, **k):
        key = (tuple(sorted(d.items())), a, tuple(sorted(k.items())))
        return fn(key, *a, **k)
    return wrapper
```

</details>

5. 用一段代码演示"自底向上应用、自顶向下调用"，并写出 `@a @b @c def f()` 的等价写法。

<details>
<summary>参考答案</summary>

```python
import functools

def deco(label):
    def outer(fn):
        @functools.wraps(fn)
        def wrapper(*a, **k):
            print(f"{label}-前")
            r = fn(*a, **k)
            print(f"{label}-后")
            return r
        return wrapper
    return outer

@deco("A")
@deco("B")
@deco("C")
def f():
    print("f 执行")
```

输出：

```
A-前
B-前
C-前
f 执行
C-后
B-后
A-后
```

等价写法：

```python
f = deco("A")(deco("B")(deco("C")(f)))
```

即最靠近函数的装饰器（C）最先包住原函数，最外层的 A 最后包住一切；运行时调用从最外层进入，所以 A 最先进。

</details>

6. 实现一个自己的迭代器类，能像 `range` 一样迭代 `[start, stop)`，并解释 `__iter__` 与 `__next__` 的区别。

<details>
<summary>参考答案</summary>

```python
class MyRange:
    def __init__(self, start, stop):
        self.start, self.stop = start, stop
        self.i = start

    def __iter__(self):
        return self            # 迭代器返回自己（迭代器协议要求）

    def __next__(self):
        if self.i >= self.stop:
            raise StopIteration  # 结束信号，for 循环靠它退出
        self.i += 1
        return self.i - 1

print(list(MyRange(0, 5)))   # [0, 1, 2, 3, 4]
```

区别：

- `__iter__` 定义"如何被迭代"——必须返回一个迭代器。可迭代对象（如 `list`）的 `__iter__` 每次返回**新**的迭代器，所以可以反复遍历。
- `__next__` 定义"如何取下一个元素"——只有迭代器才有，且它返回自身（`iter(it) is it` 为 True）。
- `for x in obj` 等价于 `iter(obj)` + 反复 `next()` 直到 `StopIteration`。

</details>

7. `with open(...) as f` 的底层机制是什么？`@contextlib.contextmanager` 装饰的函数如何实现 `__enter__`/`__exit__`？

<details>
<summary>参考答案</summary>

底层机制：`with` 语句会调用对象的 `__enter__()`（返回值赋给 `as` 的变量），执行代码块，然后**无论是否抛异常**都调用 `__exit__(exc_type, exc_val, exc_tb)`。`__exit__` 返回真值会吞掉异常。

`@contextlib.contextmanager` 内部把"生成器函数"包装成对象：

- `__enter__` 调用生成器并执行到第一个 `yield`，把 `yield` 的值返回给 `as`；
- `__exit__` 调用生成器的 `send/throw`，让生成器从 `yield` 之后继续执行（通常是 `finally` 清理），并在无异常时抛 `StopIteration` 表示正常结束。

```python
import contextlib

@contextlib.contextmanager
def res(name):
    print("open", name)
    try:
        yield name
    finally:
        print("close", name)

with res("db") as x:
    print("using", x)
```

关键：资源获取写在 `yield` 前，释放写在 `yield` 后的 `try/finally` 中。

</details>

8. 用 `yield from` 写一个函数展平任意嵌套的列表/元组，并说明它比递归 `for + yield` 的优势。

<details>
<summary>参考答案</summary>

```python
def flatten(items):
    for it in items:
        if isinstance(it, (list, tuple)):
            yield from flatten(it)
        else:
            yield it

print(list(flatten([1, [2, [3, [4]], 5], 6])))
# [1, 2, 3, 4, 5, 6]
```

`yield from X` 等价于：

```python
for x in X:
    yield x
```

优势：

1. 写法更简洁、可读性好；
2. 委托时能拿到子生成器的 `return` 值：`r = yield from sub()`；
3. C 层实现，比 Python 层的 `for + yield` 循环快；
4. 递归时不必担心多层嵌套导致函数调用栈——不过它仍是递归实现，极深嵌套仍可能触及递归深度。

</details>
