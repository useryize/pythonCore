### 练习 1：自定义异常体系
设计一个计算器模块：
- 定义异常基类 `CalculatorError(Exception)`
- 定义 `DivisionByZeroError`、`InvalidInputError` 继承它
- 实现 `calculate(a, b, op)`，支持 `+ - * /`
- 非法操作符抛 `InvalidInputError`，除零抛 `DivisionByZeroError`

<details><summary>参考答案</summary>

```python
class CalculatorError(Exception): ...
class DivisionByZeroError(CalculatorError): ...
class InvalidInputError(CalculatorError): ...

_OPS = {
    "+": lambda a, b: a + b,
    "-": lambda a, b: a - b,
    "*": lambda a, b: a * b,
}

def calculate(a: float, b: float, op: str) -> float:
    if op == "/":
        if b == 0:
            raise DivisionByZeroError("除数不能为 0")
        return a / b
    if op not in _OPS:
        raise InvalidInputError(f"不支持的操作符: {op}")
    return _OPS[op](a, b)
```
</details>

### 练习 2：重试与降级
写一个 `safe_call(func, *args, retries=3, default=None, **kwargs)`：
函数抛异常时重试，全部失败返回 `default`，并记录日志。

<details><summary>参考答案</summary>

```python
import logging
import time

logging.basicConfig(level=logging.INFO)
log = logging.getLogger(__name__)

def safe_call(func, *args, retries=3, delay=0.5, default=None, **kwargs):
    for i in range(1, retries + 1):
        try:
            return func(*args, **kwargs)
        except Exception as e:
            log.warning("第 %d/%d 次失败: %s", i, retries, e)
            if i < retries:
                time.sleep(delay)
    log.error("全部重试失败，返回默认值")
    return default
```
</details>

### 练习 3：读懂 traceback
下面代码的 traceback 是什么？指出真正的错误行：

```python
def a(x):
    return b(x) + 1

def b(x):
    return c(x) * 2

def c(x):
    return x / 0

print(a(5))
```

<details><summary>参考答案</summary>

调用链自下而上显示：c ← b ← a ← print。
真正的错误行是 `return x / 0`（ZeroDivisionError），
`print(a(5))` 那行只是调用起点。
**读 traceback 从最后一帧往上找，第一个属于你自己代码的帧才是出错点。**
</details>

## Part B · 文件与数据处理（★★★★）

### 练习 4：CSV 数据清洗
给定 `orders.csv`（列：order_id, customer, amount, date），要求：
1. 读取为 list[dict]
2. 过滤掉 amount 为空或非法的记录
3. 统计每个 customer 的总消费，降序输出
4. 结果写入 `summary.csv`
5. 处理完关闭文件、打印处理条数

<details><summary>参考答案</summary>

```python
import csv
from collections import defaultdict
from pathlib import Path

def process(src: Path, dst: Path) -> None:
    totals: dict[str, float] = defaultdict(float)
    bad = 0
    with src.open(encoding="utf-8") as f:
        for row in csv.DictReader(f):
            try:
                totals[row["customer"]] += float(row["amount"])
            except (ValueError, KeyError):
                bad += 1
    with dst.open("w", encoding="utf-8", newline="") as f:
        writer = csv.writer(f)
        writer.writerow(["customer", "total"])
        writer.writerows(sorted(totals.items(), key=lambda kv: -kv[1]))
    print(f"有效 {sum(totals.values()):.2f} 元，丢弃 {bad} 条")

process(Path("orders.csv"), Path("summary.csv"))
```
</details>

root = Path(".")

py_files = sorted(root.rglob("*.py"), key=lambda p: p.stat().st_size, reverse=True)

            for f in root.rglob("*")

## Part D · 并发实战（★★★★★）

### 练习 9：并发请求
用 `asyncio` + `httpx` 并发请求 20 个 URL，要求：
- 超时 5 秒
- 最多 3 个并发
- 失败的自动重试 2 次
- 全部完成后按耗时排序输出

<details><summary>参考答案</summary>

```python
import asyncio, time
import httpx

sem = asyncio.Semaphore(3)

async def fetch(client, url):
    async with sem:
        for attempt in range(3):
            try:
                r = await client.get(url, timeout=5.0)
                r.raise_for_status()
                return (url, r.status_code, time.perf_counter())
            except Exception:
                if attempt == 2:
                    return (url, "FAIL", time.perf_counter())
                await asyncio.sleep(1)

async def main(urls):
    async with httpx.AsyncClient() as client:
        return await asyncio.gather(*[fetch(client, u) for u in urls])

results = asyncio.run(main(urls))
for url, status, _ in results:
    print(url, status)
```
</details>

### 练习 10：解释并选型
用文字回答（不用写代码）：
1. 什么是 GIL？它为什么让多线程对 CPU 密集任务无效？
2. 计算密集任务和 IO 密集任务分别该用什么方案？为什么？
3. 什么时候用 `multiprocessing` 而不是 `threading`？注意什么坑？

<details><summary>参考答案</summary>

1. GIL 是 CPython 解释器级别的全局锁，同一时刻只允许一个线程执行字节码，因此多线程无法利用多核做 CPU 并行。
2. CPU 密集 → 多进程（`ProcessPoolExecutor`）；IO 密集 → 协程（asyncio）或线程池。
3. 当需要绕过 GIL 拿到多核并行时用多进程。坑：参数和返回值必须可 pickle；Windows 下必须 `if __name__ == "__main__":` 保护，否则会无限递归启动子进程。
</details>
